# Replay acceleration and stage packages

Normative extension of `../PIPELINE.md`. Read this file only when that contract routes the current task here.

## Replay acceleration commands

- `X trace_phase_index build --source RAW --sha256 SHA --directory status/trace-index/UNIQUE`: one-pass source hashing and validated phase chunks. Retain RAW. Index contains only phase-state/GPU/sound; other channels remain in RAW. `X trace_phase_index compare --index INDEX.json --sha256 RAW_SHA --native NATIVE.phases --begin ORDINAL --end EXCLUSIVE --report REPORT.json` verifies selected chunk hashes and compares only the requested window. Final publication still requires full source/provenance verification. Cache reuse is content-bound, not mtime-only.
- `X trace_diagnostic_packet --report REPORT.json --output PACKET.json [--address 0xADDRESS --image IMAGE]`: compact first difference, hashed report and bounded MIPS/pseudocode excerpts. Explicit function selection remains necessary when the report has only a data offset. Keep detailed inputs/checkpoint evidence linked from the original report. `trace_stage_run` emits diagnostic-packet.json automatically for a first difference, including the range, axis and artifact/dependency paths.
- Native project collectors should default to in-process capture and expose explicit debugger opt-in. Store actual argv, diagnostic environment and collector hash at launch. Existing project-specific flags are documented in project AGENTS.md; shared tools must not assume an FF ABI.

## Stage automation upgrade (incremental)

- `X trace_stage_plan --name NAME`: validate finalized trace, discover the first project-audited gameplay entry (`stage_pipeline.entry_tick`, PC from profile), declare excluded prefix and stage segments, prepare complete input-call/menu streams and a hashed phase index. Artifacts stay in `status/stage-pipeline/prepared`. Immutable identity includes raw/profile/planner hashes and entry rule. Reuse validates artifacts; a changed source is rejected. This command prepares inputs, not a verified native anchor or a MATCH verdict.
- `X trace_stage_verify --manifest MANIFEST --report REPORT`: verify an explicit schema-1 contract (`phase_begin`, exclusive `phase_end`, inclusive `start_tick/end_tick`, `native_tail_ticks`, `input_calls_end`). Requires original/native actors, world, input and phase paths; input-call stream and capture receipt binding native channel hashes, exit status and final input cursor. Optional `phase_index` with `raw_sha256` uses indexed phase comparison. Reject missing/extra records, shifted ticks, changed channels and undeclared native tails. Compare configured GPU semantics and retain raw mismatch counts; no pixel/PCM claim. Schema 1 covers historical single-stage captures; schema 2 below covers phase-aligned stage segments.
- Stage packages, automatic project conversion, narrow diagnostics and multi-stage contracts are implemented. Dead capture workers support bounded recovery; ambiguous launches remain fail-closed. Keep historical workflows available for unsupported traces. Do not infer project adapter support from shared tool availability.
- `X trace_stage_run --name NAME [--anchor CANDIDATE.json] [--wait 0..30]`: incremental stage orchestrator; build/preparation/preflight/capture/comparison/publication stages are journaled in `status/stage-pipeline/runs.sqlite`. Worker survives controller exit and writes capture-time dependency/channel hashes. Repeated requests observe the same live worker; an interrupted launch with uncertain ownership fails closed instead of spawning again. Resume a completed capture by repeating the same command. Stable completed inputs reuse the comparison without native execution. Request identity includes build, project configuration, prepared manifest, runner/verifier/collector, internal capture-library and candidate hashes. Capture requests also bind the internal runtime files, so changing a retained library such as `trace_runner` cannot reuse an older MATCH. Progress publication failure remains a failure and is retried on resume.
- Stage candidate fields: `raw_sha256`, `phase_begin`, `checkpoint`/`checkpoint_sha256`, adjacent `context`/`context_sha256`, `abi`, `adapter_version`, `input_calls_sha256`, `jobs_sha256`. Preflight checks phase PC/ordinal, context input/menu cursors, complete input stream size/controller IDs and input history hashes before launching the port. Candidate status is not acceptance; only fresh channel comparison can accept continuation. Omitting --anchor resolves a compatible registered candidate; otherwise the runner invokes stage_pipeline.adapter using the captured stage package index. The adapter CLI is --plan MANIFEST --index PACKAGE_INDEX --output DIRECTORY; it must create candidate.json. The runner verifies adapter/index hashes before and after execution. Adapter source changes invalidate converted registry candidates. Explicit candidates remain supported for diagnostics.
- `pipeline_journal` schema 1 stores immutable requests, stage receipts/timings, transition events and persistent attempt/time budgets. `stage_pipeline.anchor_attempt_limit` and `anchor_seconds_limit` bound candidate preparation; repeated calls cannot reset a run's budget. Project conversion runs in a subprocess with the remaining persisted time budget as its timeout. Missing adapter/package, rejected conversion or exhausted deadline returns `ANCHOR_UNSUPPORTED`; no interactive emulator search is attempted. Native/game failures remain separate from MATCH. A running receipt with a proven dead worker can recover automatically only when no native process is present; ambiguous ownership remains fail-closed.


- `X trace_stage_registry register --plan MANIFEST --anchor CANDIDATE`: retain a candidate keyed by raw/profile hashes, phase ordinal, PC, stage/tick, native ABI, adapter version and input/menu hashes. `resolve --plan MANIFEST` requires project `stage_pipeline.native_abi` and `compatible_adapters`; ambiguous candidates fail closed. Registration means eligibility, not PASS. A new EXE always reruns continuation; only unchanged complete runner identities may reuse their comparisons. `accept --plan MANIFEST --anchor CANDIDATE --run RUN_DIRECTORY` binds passing complete comparison, actual capture dependencies and channels to the EXE. Runner invokes accept automatically. Never rewrite old evidence when a build changes.
- Distributed DuckStation stage capture: `[XportStage] enabled=true` and explicit `entry_tick=N` in the project runtime trace profile. At `game_begin`/entry tick, an independent `ff-stage-NAME.bin` stream captures RAM, scratchpad and serialized CPU/GPU/SPU (including VRAM) at the same guest boundary. XST1 schema 1 uses device serializer version 85. Section capture is synchronous on the emulation thread; file writes are asynchronous. This is not a zero-pause claim or a native-compatible state. Raw phase/input ordinals and guest clocks bind the package to trace metadata. Opt-in per project after boundary/adapter validation; do not enable against an older distributed EXE. user_trace start validates and installs the project profile before launching. A different profile on a live emulator fails closed; restart it explicitly. Provenance includes the actual installed profile.
- `X trace_stage_package --session SESSION --output PROJECT_STATUS_DIRECTORY` validates committed sidecar, envelopes, required section sizes, monotonic ordinals and phase/input-cursor alignment, then exports hashed sections/index. user_trace finalization calls it automatically; historical records without sidecars report unavailable. Conversion must map guest device state to native fields and reconstruct wrapper/continuation state, then pass uninterrupted comparison. Captured status is not accepted-anchor status. GPU serialization latency is outside existing VBlank capture timing; measure it separately before making overhead claims.

- Stage diagnostics: verifier orders channel differences by absolute phase ordinal; missing/invalid channel positions do not certify a matching prefix. Stage runner writes diagnostic-packet.json and starts a narrow replay automatically for a localized mismatch. Periodic native checkpoints carry capture-time hashes and continuation/input context. Choose only checkpoints strictly before the earliest divergent phase; otherwise use the initial anchor candidate. Never use a later checkpoint to manufacture agreement. Incomplete channels require repair before seeking.
- `X trace_stage_narrow --run RUN_DIRECTORY [--target ABSOLUTE_PHASE --wait 0..30]`: select a checkpoint and resume through two phases after the target, bounded by the original interval. Explicit --target also tests checkpoint continuation on a passed run. Default target is the first difference. A separate worker survives caller exit. Repeat the command to observe it. Output is diagnostic_match/diagnostic_mismatch/capture_failed/not_localizable; this phase-state/GPU/sound test never replaces complete channel acceptance. Runner journals an ongoing diagnostic and resumes it before a new build.
- Narrow native collectors preserve the complete recorded input stream for boundary priming but accept an explicit input_calls_end cursor derived from original boundary clocks. The native adapter must check exact consumption at completion; it must not silently accept unread input. Without that option require complete stream exhaustion. Changing diagnostic instrumentation still requires new-build continuation proof against the original.
- Diagnostic packets link hashed comparison/capture evidence and bounded MIPS/IDA excerpts. With a phase index and configured analysis image, resolve the containing function at the recorded PC through SQL. Label it execution-boundary context, not the cause of a data difference. Ambiguous function ranges remain candidates; a state byte offset never identifies a causal function by itself.

- Interrupted diagnostic finalization: persist planned before launching. Resume planned/running diagnostics before building; an already committed mismatch must still finish missing diagnostic work. Terminal diagnostics are not relaunched. Unknown process ownership remains fail-closed; proven dead workers use the bounded path in [RECOVERY.md](RECOVERY.md).
- Strict stage contract schema 2: declare ordered segments with stage, start_phase/end_phase (exclusive), start_tick/end_tick (inclusive). Each segment has exactly one gameplay boundary per tick; gaps between segments can contain other phases. Validate segments against actual original phase PCs/stages/ticks. Actors/world retain every declared boundary across tick resets; native extra transition tails are rejected. Independent-stage replay loads one converted package per segment, validates a segment-specific input cursor and recorded PAD schedule, then merges phase/actor/world/input outputs in contract order. The execution interval after each segment's last boundary is explicitly excluded, so its decoded input and sound calls are not claimed; actors, world, GPU and phase state at that boundary remain compared. Channel-local differences map through segments to absolute phase ordinals. Schema 1 remains compatible with historical single-stage captures. Stage runner uses phase-aligned native capture and schema 2. Project adapters must accept every coherent captured stage supported by their continuation ABI; do not use stage-number allowlists as a substitute for field validation.

- Phase-aligned native capture (`phase_aligned=true`, adapter environment AUDIT_PHASE_ALIGNED=1 with project prefix) writes actors/world before each game phase, including the first boundary after stage loading; legacy post-frame tails remain available only to old collectors. This is instrumentation, not a game-logic change. Original actors/world/input channels are extracted by monotonic phase position, never by resetting tick alone; excluded prefix gameplay must not leak into verification.
- If the recording ends on a gameplay boundary, schema 2 declares terminal_gameplay_boundary_only and original_terminal_input_records (0 or 1, determined by raw phase association). Independent-stage contracts apply the same incomplete-interval rule at every segment end. Compare all actors/world/GPU/phase boundaries but only completed decoded-input and sound intervals. Reject extra native input, cursor drift or undeclared exclusions. The recorded per-segment PAD schedule still reproduces the exact controller state in each terminal boundary snapshot.

- `duckstation_state85` decodes captured CPU/GTE, GPU/VRAM and SPU RAM/voices/registers into explicit fields. This parser is tied to serializer version 85 and the audited source revision, including POD sweep/envelope layout; version equality alone is not sufficient for another fork. Validate section hashes, lengths, markers, booleans and register bounds. Keep unsupported/host-only state explicit; parser success does not imply that the native device model can represent it.
- Native stage conversion is a project adapter. It must validate PC/phase, pending operations, packet/section provenance and native ABI; map units and signedness explicitly; list imported, reconstructed and unrepresented fields in conversion evidence. Produce a candidate, then require unchanged uninterrupted original/native continuation. A checkpoint constructed from original device state does not need an old native template. Unsupported fields require ANCHOR_UNSUPPORTED or an implemented adapter, not guessed values. Never infer pixel/PCM equality from command/call comparison.


### Portability boundary for stage packages

- Shared DuckStation contains no game-specific stage-loader implementation. Each project supplies audited profile PCs/data addresses. Current capture predicate is game_begin PC plus explicit entry_tick, with phase transitions deduplicated; tick zero alone never establishes that resource loading has completed.
- During project setup prove a boundary after resources/actors/device state are ready and before the first simulated gameplay step. Audit CPU continuation and pending operations. Set the project profile and stage_pipeline.entry_tick consistently. If the game cannot express that boundary with the current predicate, extend a generic profile-driven predicate and tests in the shared toolset; never insert game-name/address branches in shared emulator code.
- CPU/RAM/scratchpad/GPU/SPU serialization and sidecar format are shared. Guest addresses, native checkpoint layout, wrapper reconstruction, continuation semantics and supported device modes belong to the project-local stage_pipeline.adapter. Never copy another game's adapter or native checkpoint unchanged.
- Configure stage_pipeline.native_abi, compatible_adapters, adapter, anchor_attempt_limit and anchor_seconds_limit. Historical traces without packages need an independently proven registered candidate or a new recording; absence is ANCHOR_UNSUPPORTED, not permission to guess initialization.
- Accept each project adapter with original/native uninterrupted continuation and relevant stage transitions; retain imported/reconstructed/unrepresented-state provenance. Updating the shared emulator must preserve disabled-profile behavior, runtime dependencies and serializer/source identity for other projects.
