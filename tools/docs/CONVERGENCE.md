# Convergence, diagnostics, repair and telemetry

Normative extension of `../PIPELINE.md`. Read this file only when that contract routes the current task here.

### Converge worker, diagnostics and accounting

- `converge NAME`: use `X trace_workflow converge NAME --wait 30`. It verifies the completed trace, starts/reuses telemetry and enters one persistent hidden worker through validation, build, conversion, capture, comparison, repair, publication and cleanup. The model resumes only at `ATTENTION_REQUIRED`, `COMPLETE` or `FAILED`; unchanged internal progress is not a model turn
- Observe using `X trace_workflow status NAME --operation converge --after-revision REVISION --wait 30`; this never launches another worker or cancels it on timeout. Lower-level runner status, telemetry snapshot and `--inline` are troubleshooting paths only. Durable state is under `status/stage-pipeline/workers/NAME`
- At `ATTENTION_REQUIRED`, read only `attention.json` and its linked bounded evidence. The packet binds the failure signature, verified prefix, causal image/address when known, source/ledger identities, complete bounded TODO branch, ambiguity gaps and acceptance criteria. A missing causal address requests an observation; never guess a function
- For code attention, start from the linked `repair-manifest.template.json`. Translate the issued branch dependency-first without crossing image, ambiguity or configured limits, update exact ledger rows, then run `X trace_workflow submit-repair NAME --manifest status/repair-manifest.json --wait 30`. The wrapper rejects foreign edits, partial branches and scope expansion; it owns refresh, provisional replay and the full fresh-build final gate
- The supervisor and solver never synthesize or approve general gameplay C, choose ABI/structures or declare ledger `DONE`. Full fresh-build replay remains the behavioral gate
- At `MATCH`, read the compact completion summary and report only its declared scope. Do not rerun tests, identity scans, telemetry snapshots or cleanup unless the summary requests attention. `MATCH` does not prove pixels, PCM or excluded intervals outside its comparison contract
- Capture failure collects a dedicated native WIP journal when `native_trace.wip_log_argument` is configured. Keep exact PC, stage/tick, actor state, callback context supplied by the project and nearest complete checkpoint. Incomplete checkpoint files are listed, not accepted. World differences report byte offset/pool/slot/address using the active profile; optional `trace_layout.world_fields` contains `[offset,size,name]` for world item fields. This metadata does not change comparison semantics
- Before returning capture_failed, compare available complete actors/world/decoded-input/phase/GPU/sound records. `prefix-comparison.json` is diagnostic-only and always has passed=false. Report channel truncation/unavailability and conservative verified_prefix_end; final incomplete sound/input intervals are excluded. Keep earliest first_difference separately from terminal_failure. A later abort never overrides an earlier state divergence
- `trace_stage_narrow` accepts a complete comparison or failure-prefix report. Automatically select a checkpoint before the proven prefix limit within the target segment; otherwise use that segment's original anchor. Bound replay by the same segment and calculate absolute phase/input cursors from recorded metadata. Compare all diagnostic channels; require completion and exact consumed input cursor for a diagnostic_match. A repaired build uses the same path via fix-probe, then mandatory full fresh-build verification
- `X trace_audit_packet 0xSITE --image IMAGE --output status/.../audit.json`: containing function, nearby MIPS/delay slots, bounded branch-target context, duplicate candidates, local calls, constants and C/IDA references. Review all connected dispatch cases and defaults; do not copy constant mappings from one case. Extend explicit ranges when the bounded packet is insufficient. A recorded boundary PC is not the causal instruction and must not automatically select a function to fix
- Audit packets obtain C implementation/declarations from the content-bound source index. They never scan every project `.c` file or assume `FUN_ADDRESS` naming. An unavailable, stale or ambiguous mapping is an explicit diagnostic gap; refresh the index or add a reviewed ledger identity rather than opening unrelated source candidates
- Audit output is bounded to approximately 12 KB, with links/hashes and truncation flags. `--state N`, `--pseudo-line N` and `--radius N` select focused excerpts. State text matches are navigation hints. `X trace_audit_packet --address 0xDATA --image IMAGE --output status/.../refs.json` gives bounded nearby static references; candidates are not proven writers and indirect access may yield none. Request additional ranges only for an unresolved audit question
- After published MATCH and completion-summary publication, worker retention stores a resumable compact receipt and removes the matched raw trace, periodic trace save states, decoded payload, prepared cache and owned conversion. It also removes resolved failed/mismatched runs for the same trace/raw identity. Preserve recording metadata, MATCH/completion/retention receipts, databases, user save slots, other traces and live/ambiguous workers. Stop only emulators with explicit workflow leases after PID/creation/executable/project/data-directory/endpoint revalidation; active recordings remain protected. `X duckstation_stop --lease PROJECT_LOCAL_LEASE.json` is the supported owned-stop command. Blocked retention yields FINALIZATION_REQUIRED and does not erase accepted evidence
- `X query 0xADDRESS --image IMAGE` limits each result list to 8 rows with counts/truncation; `--limit N` caps at 32; `--full` explicitly requests complete lists. Read only evidence needed for the current defect. Do not load previous convergence histories or full transcripts. New user-visible tasks require explicit user authorization

#### Bounded diagnostic context (second optimization batch)

- Diagnostic packets retain each channel's first difference, problem/availability and absolute phase plus stage/tick when resolvable. Prefix diagnostics do not remap already absolute ordinals. World scalar addresses come from the profile, not a game constant. These are views of existing reports; they do not change comparison or verified-prefix semantics
- At most four differing data addresses receive static-reference candidates; at most two unique candidate sites receive linked, hashed, bounded MIPS/IDA audits. These may be readers or unrelated accesses, not demonstrated writers. A missing SQL mapping is diagnostic unavailability, not a reason to infer a function. Full original comparison remains linked
- `X trace_agent evidence --name NAME --path PROJECT_JSON --pointer /FIELD [--since SHA256]` returns a bounded JSON selection with source SHA. Unchanged content returns only its identity; no repeated body. JSON pointer escapes follow ~0/~1. No cross-project reads through this command. Views cap arrays/strings, indicate omissions and stay within approximately 12 KB; use a narrower pointer for omitted fields rather than accepting missing evidence
- Worker handoff/control output is bounded; durable state and full diagnostic/report paths remain available. This does not compact conversation history or remove actual evidence. Batch independent queries and use shell-safe native arguments, not one model turn per schema/key lookup
- `X trace_context --package-index INDEX --phase ABSOLUTE_PHASE --address 0xADDRESS [--address 0xADDRESS ...] --words 1..16 --output status/WORDS.json` reads up to eight explicit addresses from exactly one captured stage-entry RAM package. Validate section size/hash, index identity and PSX main-RAM aliases; scratchpad/MMIO are rejected. Resolve pointer-like values through the configured image SQL as candidates only. Stage-entry state is not arbitrary later-phase state; no static executable table is substituted for runtime RAM

#### One-command validation and evidence levels

- Configure project `stage_pipeline.validation_suites` as `{directory, pattern}` entries. `X trace_validation --name NAME` performs file-presence/syntax preflight and prints planned argv without executing tests. It does not prove fixture semantic compatibility
- Explicit `--run` executes the configured unittest suites with a 600-second per-suite bound, synthetic prefix/seek checks and a synthetic cold/warm hash lease benchmark. Persist per-suite argv, exit status, timings, log hashes and shared/test source identities under `status/toolset-validation/NAME/ATTEMPT`. It never launches recording/converge or edits fixtures. Failed attempts and logs remain; fix only the indicated failure and deliberately rerun
- `--status` reads the latest receipt, verifies its hash and reports whether its recorded source identity still matches; it never executes checks. Identity-current means the listed inputs match, not universal fixture/dependency validity. No automatic cross-run unit-result reuse
- Overall `automated_checks_passed` means only the listed unit/synthetic checks passed. Every real gate starts deferred: fresh-build all-channel MATCH, real reset/transition, ABI rejection, changed source/cache rejection, cleanup interruption/ownership, fresh chat without history, distinct project/profile and comparable end-to-end performance. Record separate evidence paths/hashes, identities and scope for each actual experiment in the project acceptance manifest; never promote a mocked unit result to real-run PASS
- Historical acceptance receipts are not rewritten when tools change. A new optimization batch gets a new manifest with implementation/static status separate from unit, synthetic, real-run and benchmark status. An unavailable case remains deferred or explicitly not exercised, not PASS
- The hash benchmark uses an owned temporary file and compares cold/warm calls under one read lease, write refusal on Windows and changed content after release. Disk cache is uncontrolled; this proves neither storage cold-cache performance nor total converge speedup. Performance targets remain advisory

#### Declarative repair supervision

- `repair_bench` extracts the established restricted MIPS audit runner and generates a common x86 C harness from schema-1 contracts. Production instruction bytes are pinned to SQL and configured original image loads; existing native bodies are pinned through the source index. New supported cases are declarative JSON, not fresh Python/C harnesses
- `repair_dispatch` emits a semantic selector index and only two deterministic insertion classes: callback_binding and state_transition. Require a resolved original call and arguments, reproduced baseline failure and passing candidate bench before applying. Fixture contracts never modify game C. Unknown semantics go to observations/solver, not guessed C
- `repair_supervisor` is integrated into trace_converge_worker, with persistent attempt/call budgets, owned backup/recovery, mandatory code_refresh, full replay, existing publication/pruning and separately scoped validation. A later failure is progress only with a later verified prefix; it is not acceptance. Foreign edits and ambiguous interrupted jobs fail closed
- The isolated solver is a read-only CLI invocation returning structured contract proposals or missing observations. It never owns source edits. Keep task, prompt, output schema, command, process identity, usage and logs. Include discovered solver transcripts in complete telemetry and disclose missing ones. Repeated unchanged failures do not launch new model turns
- `repair_causal` consumes bench instruction/memory events to locate writer candidates and bounded dependencies. It does not infer later live RAM from stage-entry snapshots. `repair_codegen` only assesses a restricted integer-function subset; it neither generates nor approves gameplay C
- `stage_pipeline.validation_inputs` adds fixture/config inputs to validation identity. A supervisor reuses only its same-identity, hash-verified validation receipt. Detailed contract assumptions, bounds, unsupported cases and required independent oracle/full-replay evidence are normative in REPAIR_CONTRACT.md. Fixture/runtime/performance acceptance remains deferred until an explicitly authorized record -> converge actually produces its scoped evidence

#### Cache and replay invariants

- Capture identity binds source/contract/build/config/converter/collector and runtime dependencies. Verification identity is separately saved with the comparison; publication identity is saved with continuation/publication. Registry/render-only corrections reuse a completed capture/verdict. Verifier-only changes rerun verification against retained captures. Shared capture/verification module changes conservatively invalidate capture; do not weaken capture provenance to force a hit
- Commit comparison before registry acceptance. Acceptance/publication failure resumes that step without repeating capture. Pruned unchanged runs return their compact receipt; changing verification after pruning requires a fresh capture because raw native evidence no longer exists. Never rewrite old evidence hashes
- With explicit project opt-in `stage_pipeline.diagnostic_cross_build_checkpoint=true` and an identical nonempty `native_abi`, a new build can probe the previous failure from a nearby checkpoint. Require matching trace, adapter/conversion inputs, segment and checkpoint/context hashes. Label every such result diagnostic-only: its prefix may encode old behavior. The full capture and all-channel verification still run before MATCH even when the probe matches or fails
- Old native checkpoints remain candidates only under the project's serialization ABI promise. Bump native_abi for layout/device/wrapper serialization changes. Missing compatible checkpoints skip the probe; no bootstrap search. Native capture retains complete prefix checkpoints on failure. Window replay retains absolute phase/input cursors
- One worker hash session may reuse binary SHA-256 only while Windows handles forbid write/delete of those exact files. Mutable metadata and EXE are rehashed. Release handles before owned cleanup; other platforms hash normally. No mtime-only acceptance. Equal raw GPU payloads bypass canonicalization; differing payloads retain existing masks and raw-difference accounting. Do not fuse away independent acceptance channels
- Leased binary suffixes also include captured `.ram/.scratchpad/.cpu/.gpu/.spu/.inputs` sections. SHA streaming reuses a fixed-size read buffer. JSON, source and executable hashes are not cached; no persistent mtime cache or cross-process trust is introduced. Hash-session implementation is part of capture runtime identity; changes invalidate older dependent captures normally
- User VBlank RAM uses 4 KiB pages plus the 1 KiB scratchpad page. Legacy modes 0/1 remain readable. Recorder modes 2/3 assign a nonzero content ID using SHA-256 lookup plus exact-byte collision verification. Mode 2 emits changed page references and bytes only for newly live content; mode 3 is an independent 513-reference keyframe every 600 VBlanks with no repeated RAM bytes. Recorder content storage is reference-counted to the current RAM image, so capture memory remains bounded; content that leaves RAM and later returns may be emitted again under a new ID. `vblank_storage` reports payload/definition/reference/keyframe counts and bytes. This optimizes the RAM stream only: periodic full DuckStation savestates still contain complete device state and are measured separately
- Capture children also use scoped read leases; dependencies are checked before and after capture. Narrow world reads use `trace_world_index`: source/profile/content-bound offsets in project status/stage-pipeline/channel-index. Validate the offset-file hash before seeking; new source identity requires another index. Original world files are scanned once when creating the index, not from byte zero for every narrow replay

#### Telemetry contract

- Append-only spans: `status/telemetry/operations/PID.jsonl`, unique operation/parent IDs, trace/run/PID, start/end, outcome and counters. Stages include prepare/build/convert/capture/verify/acceptance/cleanup/hash. Hash spans record bytes hashed/cache hits. Worker-exclusive remainder includes orchestration/waits, not native CPU time
- Additional spans cover native_capture, prefix_compare, failure_localize, audit_packet, fix_probe, world_index and finalize. Child environment carries parent operation IDs. Native capture records process CPU/I/O/output bytes separately; nested process deltas are nonadditive. Summaries expose stage milestones and native-child totals. MATCH-to-finalization and MATCH-to-final-response are distinct measurements. Session attribution uses transcript identity, preserving parent metadata separately
- Report `status/telemetry/converge/NAME.json` uses the originating task_complete boundary, or the next task_started as a conservative closing bound. A hidden watcher finalizes after completion; snapshot/start provide recovery. Response IDs are deduplicated, conflicting usage rejected. `requests` means recorded model responses, never HTTP attempts
- Local item durations and operation durations use interval unions/exclusive categories; overlapping processes/items have explicit overlap categories. The two views overlap each other: never sum them. Keep unknown/unobserved time. Legacy SQLite step.seconds/updated-created are not additive wall time; reports label that snapshot separately
- Summaries include before/after-MATCH response/token buckets, mean input per response, the eight largest uncovered local gaps and twelve highest-byte hash paths with calls/cache hits. Usage timestamps assign responses to buckets; crossing responses are not split. Unknown gaps remain unattributed, not server latency
- `validation` and `publication` spans distinguish automated verification from ordinary converge and progress publication. Per-category interval unions include nested work and overlap other categories; never add them to exclusive totals. Hash per-path durations can overlap across processes. Retain unknown time and null RTT/retries
- OpenAI server RTT/retry counts remain null unless measured by an actual transport source. Never present local gaps as network latency. Reasoning is already included in output tokens; cached input is already included in input. Preserve primary/child attribution. Prefer compact report fields to reading per-response arrays
- Agent context reduction is a working rule, not automatic removal of conversation history. Handoff/query limits reduce routine output; actual input/request, uncached tokens, compaction counts and time savings must be measured on subsequent comparable work
- After tool changes, refresh this document and project-specific metadata. Syntax/static review and successful compilation are not runtime acceptance. The consuming project's AGENTS.md identifies the authorized fresh-chat record -> converge cycle; do not claim measured speedup before its evidence is committed
- Deferred checks are executed by the configured one-command validation/supervisor path on that cycle: synthetic earlier-divergence/late-abort, incomplete-prefix/truncation/indexed-seek fixtures plus real tick reset/input priming, changed ABI/source/cache rejection, cleanup ownership and full all-channel MATCH where applicable. Record exact evidence in project-local manifests; a synthetic pass never replaces a real gate, and an unexercised gate is not PASS
- `stage_pipeline.optimization_targets` supplies advisory budgets and an optional measured project baseline. Defaults: 35 responses, 900 seconds, 200000 uncached-input-plus-output tokens, zero compactions, 30 seconds finalization, 180 seconds after MATCH. Import-only `trace_optimization_budget.evaluate` reports actuals, exceeded targets and baseline deltas through `converge_telemetry`; it is not a standalone CLI. Targets apply to comparable small-defect traces, never weaken acceptance, and are not promised savings. Controller transfer capture remains unchanged
