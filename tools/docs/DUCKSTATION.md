## 5. Establish emulator/native observation

Reproducible source contract: `duckstation/duckstation-manifest.json`; upstream revision `5fd366809053fe287291de7a39752c4d5d5b146b` (0.1-11752), build VS2022 v143 Release x64. Complete local patch: `duckstation/internal-trace-api.patch`; generated distribution receipt: `duckstation/distribution/xport-runtime.json`. Run `[XPORT_ROOT]/tools/prepare.bat`; source, dependencies, workspace and distribution are generated and excluded from Git. The historical executable suffix ReleaseLTCG is a compatibility filename, not the build configuration. Update the manifest, patch, hashes and clean-build evidence on upgrades; never infer feature availability from filename alone.

`X duckstation_deploy --role ROLE` creates only project data/settings/profile directories. EXE/DLL/resources stay in `[XPORT_ROOT]/tools/duckstation/distribution`. No BIOS/game data is bundled. Provide project-owned BIOS/disc and controller bindings. The shared build reads absolute `XPORT_DUCKSTATION_DATA_ROOT`; never place settings/portable.txt in the shared distribution.

`X duckstation_run --role ROLE --visible [--state FULL_STATE | --slot 1..10]` launches normal-speed interactive UI; root BAT delegates using a relative toolset path. Omit `--visible` for paused diagnostic execution. `--plan` has no launch/settings effects. `--game-exe` uses `paths.original_executable`. Interactive Save State slots belong to that project's data directory. Repeating a plain visible launch verifies the existing instance's ownership, requests its window foreground and succeeds without restarting or changing state. Explicit state/slot/game-exe or diagnostic relaunch refuses an occupied instance; an unverified owner always fails with a concise message. This command/BAT is for manual play and state creation. For a user recording, do not launch DuckStation separately; use the single-call `trace_workflow record` entry in [RECORDING.md](RECORDING.md)

Configure fast boot, no CPU overclock/rewind/runahead; automated runs disable display VSync and physical audio output. Do not alter emulated CPU frequency. Manual playback speed/audio remains independent. `duckstation.data_directories` isolates role data; settings GDB port must match the reserved role. Startup/attachment verifies process receipt and endpoint ownership.

`duckstation.trace_profile` points to project INI; `X trace_profile` validates 44 version-1 decimal fields (see `duckstation/profile-schema.json`): hook PCs, counters, RAM sizes/ranges, pad buffers, sound hooks, OT and GPU pools. Missing/invalid profile returns E25. Audit actual MIPS hook boundary/register ABI; bounds validation and changing addresses alone do not make another game compatible. Format slots are versioned; unsupported semantics require a shared extension/project adapter.

`trace_layout.actor_stride` and `actor_fields` (`[offset,size,name,struct_format]`) name optional diagnostic fields; absent mapping remains byte-level. `trace_layout.gpu.ignore_ft4_padding` is the legacy switch for audited textured-quad padding in FT4/GT4 packets; `ignore_raw_sprite_rgb` defaults false. Enable either only with project evidence, retain raw differences and test every non-padding byte for sensitivity. Never transfer a game's exclusion masks blindly.

Python `Remote(host,port)` handles DuckStation RSP directly. Shared RAM reads are allowed only when stopped at a proven boundary; live reads can mix ticks. Registers, breakpoints, execution and input writes remain RSP. `XPORT_GDB_RAM_BACKEND=rsp` forces fallback; fallback is not a claim of shared-memory speed. Shared RAM selects the ownership receipt by endpoint port; multiple roles must not redirect one another. Do not add a console-GDB binary or per-project GDB bundle; the automated pipeline does not use one.

Full-state API: `qSupported` advertises `qFFSaveState+`, `qFFLoadState+`; commands take hex-encoded ASCII name, 1–64 letters/digits/`_`/`-`, not a path. Files: data `savestates/ff-audit-NAME.sav`. Saving refuses overwrite and returns only after write. E10 state, E11 name, E12 exists, E13 operation. Call only on stopped CPU. Loading removes breakpoints: reinstall. Agent API: `Remote.checkpoint(name[,load=True])`; use API rather than GUI for automation. Manual users may use the GUI.

## 6. Paired checkpoints and accelerated execution

- Reach a comparable original/native boundary through real execution once. Save full original CPU/devices/GPU/SPU state and the port's own checkpoint; a RAM dump is not a Save State or a valid native checkpoint.
- Native checkpoint includes RAM, scratchpad, GTE state, GPU/VRAM, SPU, wrapper and caller/phase state affecting continuation. Version it and bind it to build/context/input history. Incompatible rebuild → regenerate.
- Separate serialization compatibility from semantic evidence. Gate loading with an explicit checkpoint ABI/schema, not a compiler timestamp. A rebuild under the same ABI may reuse the bytes only after a fresh boundary-overlap check; it never reuses the old comparison verdict automatically. Bump the ABI and regenerate after any serialized RAM/device/wrapper/context layout change.
- Validate load roundtrip PC/registers/RAM and continuation against uninterrupted execution. Equality immediately after load alone is insufficient. Restore before each variation; reuse prepared context instead of menu/cutscene/frontend restart.
- Inputs use absolute game ticks. Compare `[start,end]` boundaries: `end-start+1` snapshots, `end-start` input records. Phase ordinals handle tick resets. Verify actual decoded input, not only requested masks.
- Headless native: hidden window, no host Sleep/VSync waits, rasterization off by default. Keep emulated VBlank/time/callbacks, GPU construction/OT traversal/state, VRAM loads/stores/copies and logical sound/SPU calls. Pixel/VRAM validation explicitly enables rasterization; screenshots from raster-off runs prove nothing about pixels.
- Capture actors/camera, world/scene/effects/scripts/RNG, input, ordered GPU payloads and sound calls in one synchronized pass. Channels may be separate files, linked by run/ticks. Current sound hooks are game calls, not all SPU registers or PCM. Wall-time audio buffer counts do not prove PCM equivalence.
- Measure native, original and complete scenario wall time separately on identical work. Native raster-off speedup is not total pipeline speedup; shared RAM does not remove debugger-stop cost.
