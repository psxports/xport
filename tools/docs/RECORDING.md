# User recording and replay preparation

Normative extension of `../PIPELINE.md`. Read this file only when that contract routes the current task here.

## 7. User trace → replay → defect localization

### User command vocabulary

Treat the following standalone user phrases as exact workflow commands. Do not require a slash prefix and do not reinterpret them as shell commands.

- `record SLOT NEW_TRACE_NAME`: call only `X trace_workflow record SLOT NEW_TRACE_NAME --wait 30`. Python resolves the exact configured slot 1..10, launches the recorder worker through Windows Shell, checks state SHA, ownership and raw growth, then leaves the visible emulator open. The worker console is hidden, but interactive DuckStation receives an explicit `STARTF_USESHOWWINDOW/SW_SHOWNORMAL`; absence of a user-visible window is a failed interactive start even if the process, GDB endpoint and raw trace are live. Do not prelaunch DuckStation, manually inspect slots/processes or assemble Shell commands on the successful path. Missing/ambiguous state fails closed without fallback
- `stop`: call only `X trace_workflow stop --wait 30`. Python selects the single active recording, finalizes it, checks completion/provenance and closes only its verified emulator. An unresolved launch or multiple active sessions needs attention; an idle project does not cause unrelated processes to stop. Optional explicit name resumes observation of that same workflow receipt
- `converge TRACE_NAME`: create a goal for full MATCH in the named completed trace's declared channels, then call `X trace_workflow converge TRACE_NAME --wait 30`. The entry point starts accounting and the persistent supervisor; observe the same worker through workflow status. Report excluded prefixes; MATCH is not menu/setup or pixel/PCM equivalence outside declared scope. Preserve evidence-based repairs, fresh-build full verification, publication and pruning. Never weaken comparison, input or provenance to obtain MATCH. The worker takes a provisional terminal telemetry snapshot; the post-response watcher closes request totals. Pause only for missing evidence/state/authority or an explicit attention handoff

`record` and `stop` manage capture; they do not start convergence. `converge` requires a closed, validated trace and never opens a user-play window. Its first local command is now `X trace_workflow converge TRACE_NAME --wait 30`, which performs accounting and runner entry internally; the older two-command accounting/start sequence below is a diagnostic interface, not extra preparation. Goal creation remains an agent/product action, not something the Python launcher can perform. These are the only canonical natural-language aliases; `converge trace TRACE_NAME` is not an alias.

A project without audited trace hooks, layout and continuation ABI sets `capabilities.trace_workflow.enabled=false` with a stable reason. `record` and `converge` must then return `TRACE_WORKFLOW_DISABLED` without launching a worker or emulator; `stop` and `status` remain available for recovery. Remove the gate only with the reviewed contracts and end-to-end validation.

Workflow launch/result/log receipts live under `status/workflow`. A timeout returns launching/running and never relaunches. Use `X trace_workflow status NAME --operation record|stop|converge --wait 30` to observe. Ambiguous/dead launch receipts require ownership review, not deletion/retry. All lower-level checks remain in Python. Record timings are cumulative seconds from recorder entry (profile/settings, identity, emulator readiness, state load, provenance, resume); the workflow additionally records request-to-arm/resume. These do not measure time before the agent invoked Python. Hashing remains synchronous and content-based; no mtime-only cache or unproven speedup is introduced.

Project `Record.cmd SLOT NAME`, `Stop.cmd [NAME]`, and `Converge.cmd NAME` may be thin relative wrappers. Direct Converge.cmd uses `--telemetry none` deliberately: pipeline timings remain, but no unrelated/stale Codex transcript is attributed. Agents use the default codex mode for complete request accounting. Shell workers run Python hidden, but an interactive record launch explicitly passes `STARTF_USESHOWWINDOW/SW_SHOWNORMAL` to DuckStation so it cannot inherit the worker's hidden show state. This explicit child show-state is mandatory; omitting `--hidden` is not an equivalent guarantee. A consuming project's AGENTS.md records whether its first runtime-validation record -> converge cycle is authorized

```powershell
# Canonical interactive workflow
X trace_workflow record SLOT UNIQUE --wait 30
X trace_workflow status UNIQUE --operation record --wait 30
X trace_workflow stop --wait 30
X trace_workflow status UNIQUE --operation stop --wait 30
X trace_workflow converge UNIQUE --wait 30
X trace_workflow status UNIQUE --operation converge --wait 30

# Lower-level diagnostic interfaces only
X user_trace start --name UNIQUE --state FULL_STATE --seconds 600 --hidden
X trace_stage_run --name UNIQUE --status --wait 30
X converge_telemetry snapshot --name UNIQUE
X trace_stage_narrow --run RUN_DIRECTORY [--target ABSOLUTE_PHASE --wait 0..30]
```

- Names: <=40 ASCII letters/digits/`_`/`-`; duration 1–600 seconds. Interactive capture defaults to the project's `user` role and reserved port. `[PROJECT_USER_DATA]` is that role's configured `duckstation.data_directories.user`; `[SAVE_SLOT]` is the actual slot file, not a slot number. Resolve every placeholder before execution. Raw/state paths stay under project data; session/decoded/replay outputs under `status/user-traces/NAME`.
- `trace_workflow record` owns the logged-in user's `Shell.Application.ShellExecute` launch, exact slot resolution, profile/settings preparation, state copy/load, process receipt, capture arming and raw-growth confirmation. Agents must not duplicate those preparations. The lower-level `user_trace start` remains only for hidden automation and explicit diagnosis. Do not prelaunch DuckStation with the root BAT and attach later; startup/load can race into `E10`, and the recorder loses ownership of the complete launch sequence
- `--hidden` is exclusively for automated tests. It adds batch mode and explicitly passes `SW_HIDE`; interactive recording explicitly passes `SW_SHOWNORMAL`. Never add `--hidden` to user play. The foreground helper may restore an already launched hidden top-level window, but foreground APIs or a successful window lookup still do not prove that the user can see it. Interactive-shell provenance plus user observation is the visibility gate. If the user reports no window, do not wait, relaunch, attach another emulator or proceed as though recording were usable. Inspect the one workflow/session receipt and its verified PID. On an explicit discard request, terminate only the identity-verified worker/emulator and delete only that recording's trace directory, workflow receipts and name-bound runtime files; do not run normal stop/finalization and do not delete shared logs or unrelated telemetry
- The canonical workflow validates/installs the trace profile and normalizes the user-role GDB settings while the endpoint is idle. `X trace_profile` and `duckstation_deploy --role user` are setup/diagnostic commands, not routine pre-record steps. Missing/stale profile fails closed; observe the same workflow receipt and repair the stated prerequisite before an explicitly new attempt
- Every interactive `record` requires a fresh idle user runtime and atomically normalizes a fixed launch contract before DuckStation starts: `EmulationSpeed=1`, `FastForwardSpeed=1`, `TurboSpeed=1`, host-refresh sync/rewind/runahead/CPU overclock/VSync disabled, fast boot enabled and CPU ratio 1:1. This prevents inherited unlimited-speed or turbo settings while preserving project-local controller bindings, other display choices and audio volume. Hidden test capture uses the same contract with all three speed values `0`. Store the contract and resulting settings hash in session.json. On finalization, require the emulator-recorded effective-settings.ini to match the mode contract; mismatch is `capture_failed`, never comparison-ready. Do not attach a recording to an already running emulator because its live settings cannot be normalized safely.
- Require a full state file and verify its SHA-256 after the session is created (`session.state_sha256` equals the requested state). Wait for `session.status=recording`, a live recorded PID, the expected user-role port/data directory and a growing raw file. A created process or open window alone does not prove recording. If the user says the window/state is wrong, stop/finalize that attempt before replacement; never keep a session marked `recording` after its process ends.
- Recording names are immutable identities. If `status/user-traces/NAME` or matching runtime files already exist, choose a new name or obtain explicit authorization to delete that exact closed attempt. Verify its status/name/duration and resolved paths before deletion. Do not retain user-declared failed attempts after authorized removal.
- Canonical stop is `X trace_workflow stop --wait 30`; it performs lower-level stop/finalization, requires complete decode/zero missing VBlanks/unchanged provenance and closes the exact owned emulator. A timeout means observe its receipt, not invoke user_trace or terminate a PID. Lower-integrity or changed-ownership failures remain attention states
- Internal recorder captures coherent VBlank RAM/scratchpad deltas without per-frame GDB stops. Content-addressed modes 2/3 remove repeated live page contents and replace each 600-frame RAM keyframe with a 513-reference map; legacy modes 0/1 remain readable. Full emulator savestates still occur approximately every ten emulated seconds and are not page-deduplicated. Measure raw VBlank bytes, `.sav` bytes, gaps and latency separately rather than promising a total reduction. Controller serial polls and game input-decoder calls are distinct evidence
- Stop drains/finalizes/decodes and reports name, duration, VBlank/game counts and missing VBlanks. Repeated completed stop validates hashes without controlling the emulator. Long decoding is not permission to restart. `recover` operates on inactive/interrupted capture; retain partial raw data and declare prefix/missing tail. Never recover over a live recording.
- On the first recording after workflow/recorder changes, retain the workflow launch receipt and decoded session. Verify the recorded emulator hash, startup-to-arm/resume timings, raw growth, legacy/new VBlank mode counts, `vblank_storage`, indexed reconstruction, periodic savestate sizes and capture latency. Continue through a fresh-build all-channel converge MATCH before promoting runtime acceptance. Update each project acceptance manifest with exact evidence/hash/scope; an untriggered automatic repair or solver remains `not_exercised`
- Current replay starts from a project-audited stage boundary. The runner resolves a compatible stage candidate or invokes the configured project adapter against a captured stage package. Historical traces without a package require a separately proven explicit candidate; otherwise return `ANCHOR_UNSUPPORTED`.
- Replay uses strict hidden headless native execution, no host waits/raster/audio output. `native_trace.environment_prefix` selects diagnostic variables; `phase_arguments` substitutes `{jobs}`. Native ABI includes AUDIT_PAD_SCHEDULE, MENU_CHECKPOINT_LOAD, TRACE_PHASE_PATH, PHASE_CHECKPOINT_LOAD/DIRECTORY/INTERVAL, TRACE_INPUT_CALLS, MENU_PHASE_COUNT, AUDIT_END_TICK, AUDIO_OUTPUT, RASTERIZE, VERIFY_VRAM, CAPTURE_WIP. Implement semantics or provide an adapter; renaming an EXE is not ABI support.
- Project-specific legacy collectors may remain for historical evidence, but they are not part of the current shared command surface. New work uses `trace_stage_run` and `trace_stage_narrow`.
- Narrow replay uses the generated phase index and chooses the nearest prior checkpoint inside a verified prefix, never at/after the first difference. Ordered phase ≠ VBlank ≠ resettable game tick. Repeating the same command observes the persisted worker without relaunch.
- On first mismatch retain raw evidence; select earliest differing phase/tick/field/call. Narrow replay/detail window, then MIPS and CDB stepping of `bin/[PROJECT].exe` (cwd `bin`); compare branch decisions and side effects. Fix the demonstrated cause, rerun the affected range, then justified regressions. Do not repeat full suites without a code change, failure or unresolved concern.
- Tooling tasks do not implicitly authorize game decompilation. Record game mismatches for the scoped task. A long capture is not proof of an equally long native match.
- Convergence telemetry is stored under `status/telemetry/converge`. It totals primary and child Codex `token_usage_record` entries (input, cached input, uncached input, output and reasoning), response IDs, model-response count, wall time, local item durations and stage-journal runs/steps/statuses. The observed response interval is a local end-to-end proxy; Codex does not expose HTTP retries or exact network RTT. Billing cost remains unavailable unless the account supplies pricing/billing records. Telemetry failures are fail-open for convergence and must be reported as missing evidence, never filled with estimates.

### Replay acceptance and anchor preparation lessons

- Treat a finalized trace bundle as an offline oracle for its captured channels. Ordinary native replay/comparison needs no running DuckStation. Start the original only for missing observations, branch/register/GTE inspection, anchor preparation or a new capture; reuse the nearest recorded full emulator state. Raw trace alone is not a portable execution package: retain source state, periodic states, profile/schema, effective settings, game/runtime identities, input streams and decoder versions. Replay additionally needs native assets and a compatible native anchor.
- Define a channel acceptance manifest before convergence: each recorded channel is an input, compared output, diagnostic-only channel or unsupported output, with exact fields/intervals/counts. Phase-state PASS does not prove world RAM, all input-decoder calls, every VBlank, the final incomplete sound interval, pixels or PCM. Report scoped MATCH until every required output channel has a comparator and passes. Validate missing/extra input calls separately; injecting input is not evidence of decoding equality.
- When captured per-call input affects a boundary snapshot, publish every input packet belonging to that boundary before capturing state. Keep the ordered decoder-call cursor unchanged until the native calls consume and validate those same records; advancing it during publication can hide missing or reordered calls.
- Validate per-call input by its recorded order and the project boundary identity. A game tick may reset between phases or scenes; never reject a later recorded packet solely because its tick is lower than the previous phase's tick. Require exact native call order, controller, packet, final cursor and phase transition instead.
- Use the project-defined boundary identity and ordering contract; never assume a counter is globally unique. Game-specific scene changes and counter-reset rules belong in project AGENTS.md. When the native port cannot reproduce a menu/CD transition, split the trace at recorded resumable stage boundaries, convert each captured stage package independently, and merge the declared channels by monotonic phase ordinal. Validate every segment and reject gaps, duplicates and cursor drift. This proves the declared stage intervals; use a separate transition-scoped trace when the transition itself is required evidence.
- Hash and retain exact capture-time project configuration/profile/collector snapshots, plus effective runtime settings. A later configuration change is neither trace corruption nor automatically harmless. Compare snapshots and dependencies; filesystem mtime after recording start does not prove the change happened after recording ended or that it is irrelevant. Do not hard-code a known changed path as a provenance exemption. Store actual native argv/environment/tool hashes at launch; current source code is not proof of historical launch settings.
- Fast replay defaults to validated in-process binary collectors. Use CDB for first-divergence diagnosis and targeted collector equivalence checks; do not duplicate every sound event through both CDB and the in-process collector during ordinary full replay. Physical audio mute is not a null backend: a muted waveOut worker can still mix and submit buffers. A null sink must preserve guest-time SPU progression and guest-visible state; verify it before replacing the backend. It can cost more CPU than wall-time-limited muted playback because it processes the complete emulated duration. Report correctness and throughput separately.
- Hash/decode finalized inputs once per immutable identity, then use indexed binary chunks for narrow windows. Hash while streaming, reuse a validated index/cache under the established cache contract, and revalidate changed/untrusted inputs and final publication. Do not reread an entire multi-gigabyte trace for every field lookup, repeat identical final verifiers, or dump large git diffs/JSON/logs into agent context. Measure hash/decode/compare/native/debugger/build times separately before claiming total speedups.
- A DuckStation save can stop inside a guest function or interrupt. C code cannot resume from an arbitrary MIPS PC/stack. Choose a project-audited resumable boundary (outer menu/game dispatch, initialization complete, resources loaded, prior work quiescent); retain the original save and deterministic prefix to that boundary. State the recorded prefix separately if the native comparison starts later. Never silently drop its coverage.
- Preferred anchor workflow: prepare and verify a paired original/native boundary once; register it by immutable original-state hash and native build/schema/context, then reuse it for recordings from that state. Native checkpoints must include explicit continuation phase, input cursor and caller locals needed after resume, as well as RAM/scratchpad/GTE/GPU/SPU/wrappers. Ordinary original playback remains available when no native anchor exists; report the preparation cost explicitly.
- When a trace includes a long menu/setup prefix but the requested scope is gameplay, execute that prefix once, save a native phase checkpoint at the first gameplay boundary, and compare that boundary against the recorded original before accepting the anchor. State the excluded prefix ordinals explicitly. Replays then load the stage checkpoint directly; retain a separate menu-scoped run when menu behavior itself is under test.
- Importing original RAM/scratchpad into a same-build native template is a candidate bootstrap only, not a verified anchor. Document every imported and retained subsystem and preserve provenance of native-derived dumps. Require uninterrupted continuation/overlap evidence for the declared channels; no per-frame state injection, hash editing or post-divergence reanchoring to hide defects. Full arbitrary-state conversion requires versioned device conversion and guest continuation support; do not advertise it from RAM equality alone.
- Portable semantic checkpoints should use explicit guest fields, schema/component versions and content hashes, never raw host pointers or build timestamps as the only compatibility gate. Keep strict build binding until migration and continuation validation exist. Store paired anchors and generated indices under the project, not the shared toolset. Portable checkpoint conversion remains an extension requirement; the implemented build-bound anchor registry is documented in [REPLAY.md](REPLAY.md).
- Final verifier computes a fresh result from inputs and an acceptance contract; an old verdict is not its oracle. Test missing/truncated channels, extra boundaries, altered payloads, bad overlaps and changed identities. Do not infer static-audit correctness from the mere existence/hash of MIPS and pseudocode files; retain the actual instruction-level findings and links to implementation changes.
