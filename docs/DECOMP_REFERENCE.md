# Decomp technical contracts

Read only the section required by [DECOMP.md](DECOMP.md). Stage execution and build gates are owned there and in [BUILD_POLICY.md](BUILD_POLICY.md).


The shared `RotMatrix` implementation follows the packed PsyQ `rcossin_tbl` quadrant indexing and multiply/negate/shift order used by the original library routine. That table duplicates quadrant endpoints and is intentionally distinct from the scalar `rsin` quarter-wave lookup; translations must not substitute scalar `rsin`/`rcos` calls or reorder fixed-point negation and shifts without original evidence.

Perspective projection uses the PSX GTE UNR reciprocal approximation, including normalization, lookup quantization, two refinement steps and final saturation. Exact host integer division is not equivalent and can move projected coordinates even when matrices and vertices match.

## Target language and naming

Record the target language in the project's `AGENTS.md` before translation. Follow the language-specific [naming and structure rules](REFACTORING_CONTRACTS.md#naming-and-structure): C uses `lower_snake_case` functions and `UPPER_SNAKE_CASE` structure types; C++ uses `PascalCase` classes, structures, type aliases, free functions and methods, including `Effect10d::Effect10d()` and `Effect10d::ReadMasked()`. Variables, parameters and fields use `lower_snake_case` in both languages. C++ implementation files must use `.cpp`. Preserve required SDK/ABI names and linkage at mixed-language boundaries. Translate established object operations as owner methods; a `.cpp` rename alone does not fulfill object-oriented translation. These naming rules do not authorize changing the guest memory/observation contract or bypassing the refactoring entry gate.

Record the selected C++ standard in the project's `AGENTS.md` and honor it throughout decompilation. A C++98 project uses classic `virtual` declarations, unscoped enums, `0` null pointers and explicit destructor bodies; do not introduce `override`, `enum class`, `nullptr`, defaulted functions or other later-language features. Preserve required SDK/ABI types and document necessary compiler extensions instead of silently upgrading the target standard.

Use C++98 for game decompilation unless the user explicitly selects another standard. Do not silently raise the dialect for host convenience or modern formatting.

C++ function and method signatures must occupy one physical line in declarations and definitions, including the complete parameter list. Do not wrap a signature to satisfy a line-length preference. Constructor initializer lists and function bodies may use separate lines.

Default arguments are forbidden in decompiled C++ declarations and definitions. Pass every required argument explicitly at each callsite. When removing existing defaults, supply the same values explicitly and preserve overload selection and argument order. A pure virtual declaration ending in `= 0` is permitted: it is not a default argument.

Before representing an original function as an instance method, record its receiver classification from complete original caller setup, object construction and table provenance. On MIPS, an object-like pointer in `$a0` alone does not establish an implicit `this`: an ordinary function uses the same first-argument register. Validate adjusted virtual-call receiver and target pairs when present; for nonvirtual candidates, establish independent owner/receiver evidence. If the distinction remains unresolved, emit a free function in the relevant module with an explicit pointer argument. Do not claim that absence from a virtual table proves an original free or static function. Identify newly written native view/adapter helpers separately from recovered original methods.

## Reuse the existing xport SDK runtime

- This workflow produces a native game port. Existing xport PsyQ implementations are the shared, SDK-reviewed runtime; use their public APIs instead of translating SDK internals again for each game. A decomp request authorizes game translation and integration, not a parallel SDK or a replacement of the shared runtime
- Use the DRAM, VRAM, scratchpad and SPU RAM already provided by xport through their existing APIs. Reusing native PsyQ wrappers does not require replacing the game's memory model. Do not create a second memory/device model or retire the provided memory domains without a separate explicit user request
- Before implementing an SDK dependency, locate its existing declaration, implementation and documented contract in xport. Match the classified original callee to the correct API and check the actual caller's arguments, result use, buffer ownership and callbacks. Do not repeat a full SDK implementation audit when the problem is caller wiring
- Keep one implementation and one owner of SDK state. Do not create duplicate `*_guest.c` modules, a second PsyQ-looking API, per-game copies of SDK algorithms/tables, or mirrors of BIOS, IRQ, SIO, DMA, GPU or SPU driver state to reproduce an original executable's memory layout
- Guest RAM equality, original SDK scratchpad/stack writes, diagnostics and internal queues do not authorize rebuilding PS1 execution machinery or bypassing a working native API. Treat a mismatch in replaced SDK internals as a boundary-contract issue; preserve the evidence and report any comparison limitation. Never rewrite the runtime merely to make that comparison pass
- Adapt only the proven game-to-runtime boundary: argument types, bounded buffers, resource formats and callback registration. Prefer a direct existing API call. Keep unavoidable game-specific adapters and addresses in the consuming project; an adapter must delegate the SDK operation and must not reproduce its algorithm or maintain parallel SDK state
- A suspected missing feature or defect requires a concrete caller/reproducer, the existing implementation and the smallest demonstrated contract gap. Before adding a shared SDK module, replacing an existing implementation, changing SDK state ownership or expanding device emulation, present that evidence and the proposed scope for explicit user authorization. Approval for a local ABI adjustment, original-game bug fix or another subsystem does not authorize that work. Do not create a speculative replacement while awaiting authorization
- If the existing API suffices, fix the integration and retain the implementation. If a shared change is separately authorized, implement the smallest change in the existing owning subsystem, preserve unrelated consumers and validate the affected contract. Do not treat a new implementation as necessary simply because its interface resembles the original MIPS more closely
- Reviewed SDK functions remain separate runtime boundaries with their existing classification and evidence. Do not silently bring them back into the game translation queue, inflate game coverage with duplicated SDK bodies or claim original machine-state equivalence for native SDK calls

## Runtime file access

- Game runtime file sources are the extracted files under project `bin/DATA`, including numbered disc subdirectories for multi-disc games. Open them through `xport_fopen` using the runtime DATA path, read with `xport_fread` or the applicable shared file helper, and use the existing stream seek/close operations. Do not bypass the shared opener with direct OS APIs or ordinary `fopen`; the shared boundary also supports Web asset loading and collection
- During decompilation replace identified game file lookup, open, read, seek and CD-ready wrappers with thin adapters to these file APIs. Do not translate their internal PsyQ CD command, LBA seek, FIFO/DMA or busy-wait machinery merely to read a resource. This replacement is authorized during decompilation and does not require the refactoring entry gate
- Treat the CD medium as always present and ready for ordinary file access. Replace drive-only readiness, seek-completion and disc-insertion polling with the corresponding ready/completed game result. Do not blindly replace every `CdReady`, `CdSync`, `CdControl*`, `CdSearchFile`, `CdGetloc*` or `CdlLOC` use: establish its actual caller contract, preserve game-visible state transitions and completion notifications, and distinguish asset reads from audio/video stream control
- Drive readiness does not guarantee that a file exists or that a Web download has completed. Preserve missing-file, bounds, short-read and transport errors. Use the shared loading mechanism while data is unavailable; do not signal successful completion before the requested bytes are present
- Resolve original ISO names, version suffixes, disc selection and sector offsets at the project file boundary. Convert a reviewed file-relative sector range to bounded byte offsets using the extracted file's actual layout; raw STR/XA files may contain physical sectors rather than 2048-byte payloads. Preserve archive parsing, decompression, destination ownership, read lengths and gameplay side effects outside the replaced I/O boundary
- Never mount, search or read ISO/BIN/CUE disc images as data sources during native or Web gameplay, and do not fall back to an original executable or image when an extracted asset is missing. Images remain inputs for startup extraction, original analysis and original-game recording only. Runtime operation must succeed with `iso` unavailable
- Fullscreen and texture movies use the applicable `xport_fmv_*` service; audio uses existing shared streaming services. Internal shared stream compatibility may expose CD-style controls over extracted files, but this does not authorize image-backed gameplay or a second project-local CD controller
- Record original caller/image/address provenance and the replacement contract. An adapter replacing CD behavior is not a complete translation of the omitted original driver loop and does not prove drive-state equality. Preserve historical evidence, report the changed boundary and verify the required game-visible bytes, ordered callbacks and effects
- At integration verify representative file loads, offsets, lengths, EOF/short-read/error paths and relevant callback/state transitions, plus native operation without access to disc images and Web loading through packaged assets. Keep the existing no-build-during-translation policy

For every Web deliverable, apply the mandatory [MP4 movie policy](FMV.md#web-movie-policy): fullscreen and in-game movies use prepared MP4/WebCodecs through `xport_fmv_*`. Original STR names are logical lookup keys only. Embedded movie containers need a bounded source adapter; isolated non-movie MDEC blocks retain their decoding path.

## Authorized save and movie replacements

These are required decomp replacements, not optional enhancements or missing translations. Identify omitted functions by original image/address, classify their actual role from callers and record the replacement/removal and every redirected callsite in project context. Exclude only identified card/player/UI bodies from the active translation inventory; never classify mixed gameplay logic wholesale. Do not emit TODO/abort stubs or fake translated bindings for omitted bodies.

Replace card-sector I/O, card managers, formatting/directory/device checks and save-slot/confirmation screens with one project save through `sint32 xport_save(const void *data, sint32 size)` and `sint32 xport_load(void *data, sint32 capacity)`. Keep payload packing/unpacking, size/version/checksum validation and required gameplay state changes. Do not store host pointers or blindly replace a sector transfer with a whole save. Use the existing [save contract](LIBRARY_SYSTEM.md#native-game-saves) for return values/storage; a missing save keeps valid defaults, and storage failure must not be reported as success. Save/load actions execute directly without card management, slot selection, prompts or confirmation dialogs. Remove those UI routes and their now-unused code/resources from the build; preserve original analysis inputs. No card emulation or successful no-op wrappers.

Fullscreen movies call xport_fmv_play; in-game/background/texture movies call xport_fmv_open, xport_fmv_next and xport_fmv_close. Translate only game-specific selection, scene timing, bounded texture/frame upload and setup/teardown around the service. Omit original decoder, buffering, CD/XA and player-loop implementations. Use [FMV.md](FMV.md) for frame/status and backend contracts: unsupported containers/native frame backends need a concrete bounded adapter or reported integration gap, never a second player or silently retained original movie pipeline. Isolated MDEC texture decompression without a movie timeline is not a movie player.

## Fullscreen movie playback

- When decompilation identifies a fullscreen movie player, use the shared `xport_fmv_*` host service from `xport.h`. Do not decompile or reproduce its internal PsyQ CD/STR ring-buffer, VLC/MDEC, XA audio, frame presentation, event loop or skip-handling implementation in the consuming project. This is an authorized replacement boundary during decompilation; it does not require waiting for the refactoring stage
- Establish the boundary from original callers, movie paths, arguments, return-value use and surrounding state changes. Preserve the game-specific movie selection, playback conditions, resource release/reinitialization, display-mode transitions and logic-clock restoration in a thin project-local adapter. Do not discard gameplay effects merely because they occur in a movie-related function
- Call `sint32 xport_fmv_play(const char *path)` with the original virtual movie path. It owns the playback/event loop and new-press Cross/Start interruption; map its results explicitly to the caller's contract: 1 for EOF, 2 for interruption and -1 for failure. The synchronous player handles interruption and window-close events internally; there is no public stop function. Do not add a second playback loop or duplicate decoder/device state around this service
- Keep platform selection inside xport: native playback uses STR/MDEC/XA, while enabled and registered web movies use prepared MP4/WebCodecs assets. Do not insert browser-specific decoding into game code. Follow [WEB.md#prepared-video-assets](WEB.md#prepared-video-assets) and [STARTUP_REFERENCE.md#str-video-preparation](STARTUP_REFERENCE.md#str-video-preparation) for preparation and activation
- Preserve original image/address provenance and record the replaced player boundary, adapter and verified behavior in project evidence. Classify it as an explicit replacement, not as a translated original body or a PsyQ SDK function. Do not mark an omitted playback implementation as a complete MIPS translation or claim original machine-state equivalence; translation accounting and verification evidence must retain this limitation
- In-game movies follow the open/next/close replacement above. Continue translation for mixed gameplay logic outside the player boundary and non-movie MDEC texture decompression through shared decoding APIs; a DecDCT call alone does not classify the entire caller as a player
- Verify real video/audio, EOF, Cross/Start skip, error/shutdown cleanup and return to gameplay for the consuming integration. A successful build or prepared MP4 alone does not establish playback correctness

## Guest-memory access

Use the standard xport functions for scalar guest-memory access: `r_u8`, `r_u16`, `r_u32`, `r_s8`, `r_s16`, `r_s32`, `w_u8`, `w_u16` and `w_u32`. Preserve the original width, signedness and access order. Express a read-modify-write through an explicit standard read followed by the matching standard write; evaluate an address with side effects once in a named local.

Do not introduce project-local accessors or guest-memory lvalue macros such as `P2_U32`, even if they delegate to `psx_addr` or the standard functions. They bypass or obscure the shared memory bus and write diagnostics. Map memory with `psx_addr(address, required_bytes)` only when a native SDK/function ABI explicitly requires a host pointer; use ordinary C access for native local objects.

## Debug-only assertions

- Shared `XASSERT(condition)` from `src/xport.h` has an executable body only when `_DEBUG` is defined. It evaluates the condition once and reports expression/file/line before aborting on failure. In every other configuration it expands to `((void)0)` and never evaluates its argument; `NDEBUG` does not select this behavior
- The argument must be a check only: no assignment, compound assignment, increment/decrement, function call or other observable side effect. This includes calls hidden inside macros and apparently pure predicate calls. Perform required operations outside the assertion in every configuration, then check their already computed results
- Never hide initialization, allocation, resource loading, input polling, memory/device access or state changes inside `XASSERT`. Removing assertions must not remove required game operations or change their order
- Keep required runtime validation, error returns, cleanup and original failure branches as ordinary code. Debug-only assertions are not a replacement for required Release behavior. Use them only for established diagnostic invariants; do not invent assumptions from one observed run

## Semantic types and integer conversions

- Choose semantic local, parameter and result types before writing the body. Treat Hex-Rays types and register temporaries as hypotheses. Establish width and signedness from complete MIPS loads, comparisons, shifts, division, callers and consumers. `ADDU`/`ADDIU` alone do not establish an unsigned game value; they specify non-trapping addition
- Split unrelated values that reuse one original register into separate meaningful locals. Keep a shared carrier only when its actual dataflow requires it. Do not reproduce register reuse by repeatedly casting one temporary between signed, unsigned, address and mask roles
- Correct an inaccurate declaration or signature at its source instead of casting every use. Reconcile affected callers, definitions, callback types and SDK boundaries through the existing signature registry. Do not change a shared field or ABI for one convenient consumer; inspect its producers and consumers. Keep guest addresses distinct from host pointers
- Use the standard `r_s*` or `r_u*` accessor matching the original load and its required extension. A later consumer can require another view; preserve that explicit boundary rather than changing the load's semantics
- Before the final complete-body MIPS audit, remove same-type casts and whole-expression casts already performed identically by assignment, return or a fixed parameter. Account for integer promotions and every intermediate operation. Variadic arguments have no fixed parameter conversion. Do not generate cast noise with the intention of cleaning it during refactoring
- Retain conversions required for intermediate narrowing, sign/zero extension, arithmetic width, modulo wrapping, signed/unsigned comparisons, shifts, fixed-point truncation and ABI boundaries. Destination conversion does not replace an earlier narrowing or establish the arithmetic domain of preceding operations. Preserve defined host behavior; never replace unsigned wrapping with overflowing signed C arithmetic
- Establish ranges from original control/dataflow or validated format/API contracts, never from one trace, typical gameplay or an assumed positive value. Mixed-domain values may require explicit conversions even with correct declarations. Do not delete casts by regex, cast-count targets or a preference for signed arithmetic
- Record non-obvious numeric contracts once per function or shared data family in existing audit/context evidence: widths, signedness, required truncation/wrapping and any range assumptions with their basis. List only meaningful exceptions; do not create a per-cast ledger. Bind the final readable body to its audit. Reuse unchanged original analysis and family contracts; review changed operations and affected consumers, without treating historical proof as acceptance of changed code
- Translation order: recover semantic types and signatures, translate, remove redundant conversions, then audit the complete final body against MIPS and register it. This is numeric cleanup within the existing memory model, not authorization for native-state migration or other refactoring

At the existing integration gate, the static rules of `tools/refactor_c_integer.py` may assist with redundant conversions; see [Automatic integer-expression pass](REFACTORING_CONTRACTS.md#automatic-integer-expression-pass). Respect its configuration, source identity and observer restrictions. Do not add per-function compiler runs, CBMC checks or proof infrastructure to ordinary translation. Type-changing candidates require the affected semantic review; a tool report, parse or build is not a complete MIPS audit. If a post-audit edit changes the body, review/rebind the affected evidence before claiming a current complete translation.

## Numeric literal suffixes

Do not use `u`, `l`, `ll`, their uppercase or combined forms, floating-point suffixes or other numeric literal suffixes without an explicit semantic need. Do not add them mechanically because an argument, field or result has a fixed-width type. Prefer `1`, `64` and `0x80010000` over redundant `1u`, `64u` and `0x80010000u`.

A suffix is allowed only when omitting it changes the required literal range, expression type, wrapping arithmetic, shift width, precision, overload selection or SDK/ABI contract. For example, `1u << 31` requires unsigned arithmetic to avoid a signed left-shift overflow. Establish the need from the complete expression and the original MIPS, not just the destination type; record a non-obvious reason in a brief comment or the function audit. Respect the selected language standard when choosing suffixes. Before removing an existing suffix, audit integer promotions and intermediate operations; never trade faithful arithmetic for formatting.

## Mandatory function translation audit

When complete IDA pseudocode exists, read it from its first through last line and use it as the structural baseline. A bounded excerpt, function prologue, inferred purpose, neighboring implementation or model summary is not a complete baseline. Missing, partial or unreadable pseudocode is a normal input state: set `pseudocode_complete: false` and `pseudocode_used_as_baseline: false`, then translate and audit from the complete MIPS listing. Pseudocode availability alone never accepts or rejects a function.

Audit the resulting C against the complete immutable MIPS listing before registering a complete translation. Cover every basic block, branch target, delay slot, callsite, argument carrier, return value and memory side effect. Track register-carried state across calls, including nonstandard helper conventions that update argument registers, packet pointers, tags or accumulators. Audit direct local helpers in the same repair cluster when their return values or register side effects contribute to the failing function. A call alone does not require every callee listing in the owner packet: identify the specific unproved callee effect before expanding the cluster, while still auditing the owner's entire callsite and all paths.

Do not replace an original algorithm with a simpler policy, representative branch, guessed formula, fallback or placeholder. Do not defer weighted selection, pointer chaining, error paths or other reachable semantics to runtime verification. If any reachable behavior is unresolved, make no implementation claim and keep the function uncovered.

For a startup translation, the attention packet must contain complete MIPS with `complete: true` and explicit pseudocode completeness metadata. The response must bind every supplied evidence hash in `decision.function_audits`, set `complete_mips_audit: true`, set `pseudocode_used_as_baseline` to the supplied `pseudocode_complete` value, and provide an empty `unresolved_semantics` list. The supervisor rejects truncated MIPS, false pseudocode completeness claims and incomplete audit receipts. It does not reject absent or partial pseudocode.

For a bounded owner audit, `tools/mips_function_fixture.py` can execute original raw words with MIPS-I branch/load delays and explicitly supplied external-call fixtures. It rejects unsupported instructions, control transfers in delay slots, data outside aligned cached 2 MiB RAM and instruction-limit exhaustion. The explicit `allow_ram_aliases=True` fixture option additionally accepts the physical and KSEG1 aliases of that same RAM while retaining original addresses in the access trace; scratchpad, MMIO and ROM remain rejected. MULT/MULTU, DIV/DIVU and MFHI/MFLO model result words, including divide-by-zero and signed overflow; HI/LO timing remains outside fixture scope. BREAK terminates the fixture before subsequent instructions and reports both encoded fields when the second is nonzero; it does not emulate the exception handler. It is a limited audit fixture, not a complete PS1 CPU. A project comparison must bind the original function bytes and actual C/header/fixture hashes, compare all owner boundary carriers and ordered guest data accesses, and declare every external fixture limitation. Fixture MATCH corroborates the static owner audit; it cannot certify unimplemented callees or full-game runtime equivalence.

Signed `ADD`, `ADDI` and `SUB` reject signed 32-bit overflow before writing their destination, including register zero. `ADDI` sign-extends its 16-bit immediate; `ADDIU` remains wrapping arithmetic. Overflow stops the fixture with `ValueError`; it does not emulate CP0 exception state or a guest exception handler. Run `python -B -m unittest tools.tests.test_mips_function_fixture` from the toolset root after changing instruction semantics.

Full-pass allocation/integration is owned by [DECOMP.md](DECOMP.md).

## 8. Translation presence and scoped verification

### Reviewed data prefixes before a code entry

When an immutable inventory range includes a data table before its real entry, retain that inventory identity for accounting and use only the actual code entry in `FUNCTION_MARKER`. Configure `analysis.reviewed_function_entries` as a project-relative JSON manifest with schema `xport-function-entries-v1` and an `entries` array. Each entry supplies `image`, hexadecimal `inventory_address` and `entry_address`, `original_size`, `original_sha256`, exact `prefix_data` hex bytes, `code_sha256`, project-relative `image_path`, `image_sha256`, `review: {path, sha256}` and a reviewed `reason`.

The default `image_format: "psx_exe"` derives the load address from the original PS-X EXE header. For a headerless canonical `OVL_*` image, use `image_format: "raw_overlay"` and a reviewed hexadecimal `load_address`; byte zero maps to that address. Both formats require the same whole-image, inventory-range, exact data-prefix, code-suffix and review hashes. Raw format is restricted to overlay identities and does not authorize changing the original inventory or treating prefix bytes as executable code.

The registration command validates the selected original image format, complete original range, aligned prefix, suffix code and review hashes before accepting the actual entry marker. Duplicate identities or destinations, changed bytes, escaping evidence paths and data-address markers fail. The SQL binding retains the immutable inventory address; the derived index ledger records `native_entry` and resolves the named actual body. Do not exclude the whole mixed range, add a fake prefix marker or count both entries. A reviewed entry correction grants no semantic completeness: the complete native body audit and explicit `--complete` attestation remain required.

Use the compact SQL context and complete-body registration commands in `../AGENTS.md` for every translation or repair. The queue distinguishes uncovered and decompiled game bodies; reviewed SDK identities are separate candidates for existing runtime APIs. Compilation, execution in a recording, a prototype, a partial body or a stub cannot establish a full translation. Existing complete bodies are rebound from their original audit, never automatically promoted from historical WIP/DONE labels.

Keep verification separate from presence: save exact tested properties, scenario, configuration and limitations as scoped check/finding records linked to original artifacts. Original MIPS remains authoritative. Complete static MIPS audits remain mandatory; a SQL summary never grants a proof. Historical status fields remain readable only for legacy strict-proof contracts.

Before working on an SDK dependency use `X query 0xADDRESS --image IMAGE --view sdk`; review the classification, existing API and caller ABI. Do not decompile an identified PsyQ function when its implementation already exists in xport. Decompilation is permitted only when tests produce divergent results and specific evidence supports suspicion that this implementation causes the divergence; record the test inputs, results and evidence before proceeding. The exception does not authorize replacing the shared implementation or expanding device emulation; separate explicit authorization remains required. Pending or ambiguous classification does not authorize excluding a game function.

Compare the entire declared range, expected counts, selected structures, ordered calls and arguments. Inspect partial/channel scope and first difference; exit zero alone may not mean PASS. State or call matches do not prove pixels/PCM, unhooked intervals or all inputs. Never suppress or mask an observed difference.

Update a complete-body SQL binding after audited source changes. Refresh derived source indexes only at the workflow's integration gate. Preserve immutable proof history; do not render the retired progress dashboard.

For retained additional image exports, configure `analysis.additional_index_exports` as a list or `{path, sha256}` referencing a project `status` JSON list. Each binding supplies `image`, export-folder `path`, `config`, `config_sha256`, `review`, `review_sha256`, `original_sha256` and `files` mapping every consumed export file to its SHA-256. Prepare derived copies with `startup.canonicalize_ida` when retained IDA inventories lack `raw_instructions`; never normalize immutable snapshots in place. The index validates image/profile/GP identity, original GP initializer bytes, every function word/chunk/hash and listing/pseudocode bindings. Additional images cannot replace an existing image input. These checks establish input provenance, not semantic completeness, SDK classification or runtime equivalence.

## Reviewed indirect call edges

Projects may bind `analysis.resolved_indirect_calls` to a project-local JSON manifest with schema `xport-reviewed-indirect-calls-v1` and an `edges` array. Each edge contains `image`, integer `source`, `site`, `target`, `image_sha256`, `source_sha256` and `proof`. A `reviewed_vtable_slot` proof contains a project-local review `path` and `sha256`, integer `constructor`, `constructor_sha256`, integer `table`, `slot_offset`, signed `receiver_adjustment`, exact eight-byte little-endian `slot_bytes`, and `complete_target_set: false`. The review must establish the constructor's table assignment and the complete caller's receiver/slot/target loads from original MIPS, using full available pseudocode as its structural baseline. A pointer word alone is not a dispatch proof.

A `reviewed_callback_argument` proof uses the same review path/hash and `complete_target_set: false`, plus `caller`, `caller_sha256`, `call_site`, `argument_register`, two `argument_setup` entries with integer `site` and hexadecimal `word`, and `callback_binding` with `site` and `word`. The supported setup is LUI followed by ADDIU in the direct call delay slot; the caller must call the reviewed source. The callee binding must copy that argument into the JALR target register. Review the complete original bodies to establish control flow, absence of intervening clobbers and callback argument semantics. Validation checks these local encodings and identities; it does not prove reachability, accept ambiguous caller boundaries or close unknown targets.

`build_database` rejects changed image/function/review hashes, non-JALR sites, missing original functions and mismatched table slots. Accepted alternatives become `indirect_reviewed` edges with SQL `edge_provenance`; their sites remain `partially_resolved_static`. They are possible static dispatch edges, not observed calls or exhaustive target sets. Missing manifests preserve the direct graph. Keep unreviewed indirect alternatives unresolved; do not infer dead code from a missing graph path. Rebuild the SQL index after the connected implementation pass to display the reviewed edges.

Projects may bind `analysis.function_scope` to a project-local `xport-function-scope-v1` JSON document with `image` and `rows`. Each row contains the eight-digit hexadecimal `address`, `original_sha256`, `category` and `reason`. Categories are `needed`, `possibly_needed`, `replaced` and `dead_code_candidate`. Keep evidence and uncertainty in additional row fields. The SQL queue validates duplicate/stale scope identities and returns scope annotations independently of translation presence. Candidate exclusion affects the current translation queue only; a missed observation never proves unreachability, and a scope label never establishes a complete translation, reviewed SDK classification or semantic equivalence.

## Minimal CTree sidecars

`ida/ida_analyze_export.py` accepts an optional bounded `ctree_addresses` list. For each successfully decompiled address it writes `ctree/ADDRESS.json` with contract `xport-ida-ctree-v1`: statement/expression kind, numeric and named operation, type text/width/signedness, parent and child identities, local-variable identity/location, node EA when available, prototype, reviewed GP, function hash and original image identity. A missing node EA is stored as `null` with `unsupported_source_map_gap`; it is never replaced by a guessed instruction.

Projects bind derived sidecars through `analysis.ctree_exports`. `build_database` validates the schema, original image bytes and current image-qualified function hash before populating `ctree_functions`, `ctree_lvars` and `ctree_nodes`. The CTree database is structural evidence for dereference/index recovery and source mapping. It is not generated C, a complete mapping, or proof that Hex-Rays types and control flow are correct.

Run a real installed IDA/Hex-Rays export before claiming support. Python schema tests cover only the import contract. Keep the new IDB/export under status as derived evidence; do not overwrite the original canonical exports.

## Reviewed CTree-to-C candidates

`ctree_to_c.py` translates only `xport-ida-ctree-v1` sidecars covered by an exact `xport-ctree-transform-v1` manifest. Version 1 supports fixed-width integer expressions, wrapping arithmetic, assignments, 8/16/32-bit guest loads and stores, if/else, loops, and direct calls with a node-specific reviewed prototype. Guest addresses remain `uint32_t`; host pointer arguments require the distinct `host_pointer` manifest kind. Unsupported widths, address forms, intrinsics, indirect calls, or ABI assumptions produce a node-specific gap in `report.json`.

The output directory must be outside every `src` path. A manifest may bind a proposed application only by exact existing-source SHA-256 and `reviewed: true`; generation itself never changes hand-edited source. Review rejects register arrays, instruction-shaped macros, and switch dispatchers. Names and layouts may be refined after the generated baseline passes behavior tests.

Use `ctree_z3_verify.py` only for a short expression with an independently written MIPS semantic AST and explicit preconditions. Missing `z3-solver`, timeout, unknown, or a counterexample is not a pass. Keep development and holdout fixtures under `tools/tests/fixtures/ctree_to_c`; both sets must compile with MSVC warnings as errors. An unsupported CTree sample must produce an explicit gap and must never be rewritten or promoted to project source.

## 10. Tips: PSX/MIPS/IDA

These are platform facts and audit checks, not game addresses or blanket normalization permissions.

- When a PsyQ symbol collides with a host API or macro, give the canonical shared wrapper a `PSX` suffix and use that name in translated game code. Preserve the original PsyQ identity in classification and audit evidence; do not solve the collision with include order or `#undef` of the host API. Canonical example: PsyQ `LoadImage` becomes `LoadImagePSX`, while Win32 keeps `LoadImageA`/`LoadImageW` and its `LoadImage` macro.
- Keep original PsyQ names on the public compatibility surface when the implementation preserves that API's contract. Implement that entry directly in the owning shared subsystem; do not insert one-line `psx_*` or `xport_*` forwarding trampolines between game code and the implementation. Use `gpu_*`, `spu_*` and `gte_*` consistently for internal subsystem functions, types and constants, and reserve `xport_*` for genuine host services and required game bindings beneath that surface. Do not retain a parallel `PsyQ*` or `psx_gpu_*`/`psx_spu_*` compatibility layer with duplicate state, give an internal binding a second PsyQ-looking name or treat a host adapter as proof of original PsyQ behavior.
- Do not merge PsyQ routines merely because their names or resulting command words are similar. Bind the exact classified callee address and audit observable packet layout. In particular, keep one-word draw-mode construction distinct from the two-word draw-mode-plus-texture-window macro; a null texture-window argument does not prove that the original call used the one-word routine.
- Preserve exact integer lookup data for classified PsyQ numeric routines. Extract or verify the SDK table against the immutable game image; a floating-point-generated approximation is not equivalent even when it differs by only one fixed-point unit.
- Do not publish an unused PsyQ entry as a body of `(void)parameter` suppressions. Implement the modeled contract, record the unresolved contract when the game reaches it, or omit the unneeded entry until a real consumer and implementation exist.
- Preserve the original PsyQ `LIBETC.H` controller names and aliases, including `PADi` through `PADo`, `PADh`, `PADL1`, `PADL2`, `PADR1`, `PADR2`, `PADstart`, `PADselect` and `_PAD(controller, button)`. Do not replace SDK names with a modernized naming scheme.
- Little-endian MIPS I: audit branch delay instructions on both paths, including JAL/JALR/JR; link address and nonstandard link register matter. A pending load can leave the next instruction using the old register. Respect HI/LO, sign-vs-zero extension, SRA/SRL and signed/unsigned comparisons. Translate wrapping arithmetic without C signed-overflow UB; implement unaligned LWL/LWR/SWL/SWR merges explicitly. Do not replace division/multiply corner behavior with unchecked host operations. [CPU reference](https://psx-spx.consoledev.net/cpuspecifications/)
- Treat the PS-X EXE header GP as a hint, not authority. The accepted IDA profile must contain a nonzero runtime GP plus reviewed evidence that agrees with the loaded image. Accept the unique adjacent `lui $gp`/`addiu $gp,$gp` initializer or another explicitly named derivation with equivalent byte evidence. Zero, ambiguous, inherited without reviewed evidence or mismatched GP fails before IDA export; never generate pseudocode first and repair its base later
- For every `$gp` memory operand, compute the effective address as `runtime_gp + sign_extend(imm16)` from the immutable listing. Run `X gp_audit --report status/audits/gp-address-audit.json` after translating a frontier that contains GP-relative accesses. Any wrong or inferred base must be corrected before acceptance. A missing literal may be valid only when the C body demonstrably represents the same access through an indexed contiguous range, a copied aggregate, an unreachable original instruction or an explicit unresolved gap; record that classification and keep incomplete functions uncovered
- Main RAM is 2 MiB with cached/uncached aliases. Scratchpad is separate 1 KiB at `0x1F800000..0x1F8003FF` (cached mirror `0x9F800000`); do not treat the KSEG1 scratchpad range as ordinary RAM. Do not apply `addr & 0x1FFFFF` to arbitrary addresses: it aliases scratchpad, MMIO and BIOS incorrectly. VRAM and sound RAM are separate device memories. Overlay/self-modifying code requires cache/context awareness; stored RAM bytes need not equal cached instructions currently executing. [Memory map](https://psx-spx.consoledev.net/memorymap/)
- Decode fixed hardware addresses through a typed bus, not guessed host pointers: GPU GP0/GP1 `0x1F801810/814`, pad/memory-card serial `0x1F801040`, interrupt and DMA/timer regions per I/O map. Hardware access width/order can matter; do not model all registers as normal memory. [I/O map](https://psx-spx.consoledev.net/iomap/)

- GTE is stateful: preserve control/data registers, MAC/IR arithmetic, FIFO effects, saturation/FLAG and fixed-point conventions. Replacing transformations with floating point can change branches as well as pixels. [GTE reference](https://psx-spx.consoledev.net/geometrytransformationenginegte/)
- Audit GP initialization per executable/overlay before trusting global accesses. Caller conventions, stack arguments, preserved registers and real structure stride beat inferred prototypes. A pointer in a0 is not evidence of C++ `this`; a table of pointers is not automatically a vtable.
- IDA can infer wrong function boundaries/chunks, stack deltas, prototypes, signedness, structure sizes, array stride, tail calls and jump-table targets. Inline assembly, reused registers and overlapping data/code can invalidate pseudocode. Never implement guessed `undefined` types literally. Fix metadata only with byte/caller evidence; preserve the initial export and failures. Validate pseudocode-reordered delay-slot side effects against raw instruction order. These are audit risks, not a claim that every MIPS decompilation is wrong. [Hex-Rays MIPS examples](https://docs.hex-rays.com/user-guide/decompiler/introduction-to-decompilation-vs-disassembly/comparisons-of-mips-disassembly-and-decompilation), [failure handling](https://docs.hex-rays.com/user-guide/decompiler/failures)
- Native pointers/host endian/alignment differ from guest addresses. Use explicit load/store helpers and documented guest struct offsets; never serialize raw host pointers/padding as raw runtime state. Clear/reuse scratchpad only as original code does, not at every function/frame.
- VBlank, GPU submission, game logic tick and menu/sequence phase may differ. Preserve callback ordering/RNG/time during accelerated runs; PAL/NTSC rates and phase resets are project facts. Do not align solely by wall time or equal frame numbers.

- Immediate reconstruction: `LUI imm16` produces `imm16 << 16`; audit hex digit positions before transcribing constants. For `SRA`, cast the complete wrapped 32-bit expression to a signed type before the shift, not after an unsigned shift.
When translating inline GTE projection followed by `AVSZ3` or `AVSZ4`, use `gte_project_full_depth` for each projected vertex before `AverageZ3` or `AverageZ4`. `gte_project` and `RotTransPers` return the PsyQ `SZ3 / 4` result and must not be substituted for the full GTE `SZ` FIFO values consumed by the averaging opcodes.
