# Refactoring technical contracts

Read only sections applicable to the current family; read whole-project cleanup passes once before the planned editorial pass. This is the mandatory technical appendix to [REFACTOR.md](REFACTOR.md), not a separate workflow or additional proof gate. Preserve direct user restrictions and the v2 change-class/reuse policy.

## Naming and structure

Place all `#include <...>` directives before `#include "..."` directives in each include block. Separate the two groups with a blank line and preserve dependency order within each group

Choose naming from the project's recorded target language before writing or reorganizing a translation. Apply these rules during decompilation as well as refactoring:

- C: functions, variables, parameters and structure fields use `lower_snake_case` (`camera_update`, `target_pos`); structure tags and structure typedef names use `UPPER_SNAKE_CASE` (`CAMERA_CFG`)
- C++: classes, structures, type aliases, free functions and methods use `PascalCase` (`Effect10d`, `Effect10d::ReadMasked`, `CameraUpdate`); constructors and destructors use the class name (`Effect10d::Effect10d`, `Effect10d::~Effect10d`). Variables, parameters and data members retain `lower_snake_case`
- C++ implementations use `.cpp`, never `.c` with a C++ compiler override. Organize established object operations as methods of their owning class; renaming a file alone does not complete object-oriented translation
- Mixed-language boundaries retain required SDK/ABI names and explicit linkage. Document compatibility adapters separately from class methods; do not rename mandated PsyQ interfaces

Do not infer the original language solely from the target language. Preserve original address provenance and record uncertain object ownership instead of inventing classes or semantic names.

Do not prefix game-owned names with the project's `SHORT_NAME` (`xport-project.json` `short_name`), in any letter case. This applies to functions, variables, parameters, fields, structure tags and typedef names: use `camera_update` and `BOAT_STATE`, not `rr_camera_update` or `RR_BOAT_STATE`. Remove existing project-short-name prefixes and update every reference/mapping; use subsystem names for organization. Required external SDK/ABI symbols retain their mandated names.

C function names follow `subsystem_action`; C++ free functions and methods use the corresponding `PascalCase` form (`CameraUpdate`, `Camera::Update`). Omit qualifiers that distinguish no supported alternative (`text_format_decimal_digits` -> `text_format_digits` when only base10 exists); retain qualifiers for real differences such as fixed-length digit parsing versus signed integer parsing. Use common abbreviations: `current` -> `cur`, `previous`/`prior` -> `prev`, `display` -> `disp`, `screen` -> `scr`, `direction` -> `dir`, `source` -> `src`, `destination` -> `dst`, `average` -> `avg`, `cosine` -> `c`, `sine` -> `s`, `temporary` -> `tmp`, `transformed` -> `t`, `projection` -> `proj`, `sprite` -> `spr`, `texture` -> `tex`, `primitive` -> `prim`, `rectangle` -> `rect`, `subdivide`/`subdivision` -> `subdiv`, `iteration` -> `i`, `normalized`/`normal` -> `n`, `palette` -> `pal` (`palettes` -> `pals`), `square`/`squared` -> `sq`, `quaternion` -> `quat`, `magnitude` -> `mag`, `length` -> `len`, `initialization` -> `init`, `synchronization` -> `sync`, `position` -> `pos`, `index` -> `idx`, `descriptor` -> `desc`, `projected` -> `proj`, `adjustment` -> `adjust`, `deformation` -> `deform`, `record` -> `rec`, `coordinate` -> `coord`, `controller` -> `pad`, `configuration`/`configurations` -> `cfg`, `selected` -> `sel`, `group` -> `grp`, `value` -> `val`, `increment` -> `inc`, `decrement` -> `dec`, `red` -> `r`, `green` -> `g`, `blue` -> `b`, `alpha` -> `a`, `segment` -> `seg` (`segments` -> `segs`), `collision` -> `col`, `saturation` -> `sat`, plus `init`, `sync`, `pos`, `idx`, `desc`, `proj`, `subdiv`, `prims`, `ot`, `ot_entry`; vertex arguments use `v0`...`v3`. Apply to name components (`squared_length` -> `sq_len`, `render_projection` -> `render_proj`, `transformed_force` -> `t_force`); Plural forms follow the same rule (`sprites` -> `sprs`); transformed scalar components omit the separator (`transformed_x/y/z/w` or verified transformed components `transform_x/y/z/w` -> `tx/ty/tz/tw`). Origin scalar components use `origin_x/y/z` -> `ox/oy/oz`. Use `t` for a transformed vector when its scope makes that role clear; resolve collisions before renaming. Sine/cosine output parameters use `s_ret`/`c_ret`. Keep `s`/`c` in a clear trigonometric context and resolve scope collisions. Use `pix` for pixel samples/buffers and `img` for an image asset or complete picture formerly named `pixels`; choose by verified role, not blind replacement. A palette buffer uses `pal`, and an image rectangle uses `img_rect`. Preserve required SDK fields. Apply these abbreviations only to game functions, variables, fields and arguments. Do not abbreviate type names, module filenames or their include guards unless the user explicitly requests that exact rename. Retain user-selected names such as `VEC3` and `QUAT`; preserve required SDK/ABI identifiers and asset strings. Avoid obscure abbreviations (`dis` is not `disp`). Remove a prefix only when it carries no required namespace meaning.

Use zero-based numeric suffixes for numbered peer values: `first_texture`, `second_texture`, `third_texture` -> `tex0`, `tex1`, `tex2`; use `disp0`/`disp1`, never `first_disp`/`second_disp`. Prefer a typed array (`uint32 tex[3]`, `DISPENV *disp[2]`) when the elements form one group and indexed access simplifies their consumers. Preserve independent lifetimes and side-effect order; do not combine unrelated values solely because their names contain ordinal words. Retain semantic range endpoints or chronological roles such as `first`/`last` when they do not denote numbered peers. Array names may be singular when their elements belong to one object: use `scr[4]` for its projected corners, not `scrs[4]`.

When explicitly requested by the user, remove redundant `_STATE` in game structure names when the shorter semantic name remains clear and does not collide with an existing identifier (`CAMERA`, `MENU`, `RESULT`). Retain a qualifier when needed to distinguish owners/roles; preserve mandated SDK/ABI type names. Name modules/types from verified game roles and consumers: a racing game's course-section owner can be `track`/`SECTION`; do not copy that terminology to another genre. Replace a vague `global` owner with coherent helpers or existing subsystem owners; do not move unrelated mutable state into `utils` solely to rename the file.

Replace address-derived function names (`fn_8004c740`, `sub_8004C740`, `FUN_8004c740`, including subsystem-prefixed variants) with verified `subsystem_action` names in C or `PascalCase` free/member names in C++. Replace decompiler placeholders for parameters, locals, globals and fields (`a1`, `v12`, `DAT_...`, `field_...`) with names describing their established role. Update declarations, definitions, every caller/reference and source mappings together; retain original addresses in provenance. Preserve required SDK/ABI symbols and meaningful conventional names such as vertex `v0`...`v3` or loop indices.

Do not invent semantics to eliminate a placeholder. Investigate its dataflow, consumers and original code; if its literal historical role remains unknown but execution is understood, use an established neutral role and record the qualification. Resolve or explicitly qualify residual names in the single editorial pass; unknown execution contracts remain blockers under Workflow v2.

Introduce named constants/enums only for established semantic domains; keep unrelated mode/flag domains separate. Keep immutable data const and private single-consumer tables in the owning module. Retain original function boundaries and reuse original helpers; introduce new game functions only with explicit authorization. Never split a function solely because of length. Remove arguments/returns only after checking all callers, indirect dispatch and original register-carried effects. Use packed XY/color/UV fields when the device ABI defines them; do not replace a word copy with needless byte decomposition. Use PsyQ setters (`setRGB0/1/2/3`, `setUV0/3/4`, `setXY0/2/3/4`, `setWH`, `setSemiTrans`, `setShadeTex`) for complete groups assembled from individual components. Preserve service bytes and command/length/OT bits; never initialize a packet solely to replace a color write. Keep existing packed copies as one assignment; retain individual fields for partial updates.

## Original layout and module reconstruction

Stage input: reviewed original MIPS, image-aware function/data addresses, call/data references and current source mappings. Reconstruct candidate subsystem boundaries before bulk renaming or moving definitions. Address ordering often reflects linked source/object groups; it is evidence to investigate, not proof of a module boundary.

1. Inventory functions, globals and tables by `(image, address)`; inspect contiguous ranges, alignment/gaps, callers/callees, shared data, initialization/reset paths and callbacks. Keep overlays and distinct images separate even when numeric addresses coincide. Distinguish code, data, SDK bodies and compiler-generated helpers
2. Confirm each candidate subsystem through original operations and shared ownership. Nearby functions with related state and consumers can form one module; distant functions may belong to it too. Do not merge unrelated neighbors or split a subsystem solely at an address gap. Keep genuine SDK functionality in xport
3. Rename functions, parameters, variables, structure tags/types and fields by verified roles using the naming rules above. Infer structures from access widths/offsets, repeated layouts and all producers/consumers; an address alone cannot establish a field's meaning. Retain unresolved roles as explicit audit items rather than inventing names
4. Consolidate related functions, private types, tables and state into semantic `.c/.h` modules. Merge fragmented modules when they share one responsibility/owner; move reusable operations to an appropriate common owner. Keep only cross-module APIs/types in headers; reorder definitions to minimize forward declarations. Module/type names describe the verified role and genre, not original addresses or another project's conventions
5. Update every caller, callback table, include, project build input and SQL/source mapping together. Preserve original `(image, address)` provenance through markers/reference mappings, including merged, inlined or removed bodies; module relocation must not lose traceability. Record many-to-one replacements explicitly; do not infer coverage status from a rename

Stage output under project `status`: original image/ranges and identities -> chosen module, final symbols/type/field roles, ownership rationale, affected consumers, unresolved items and validation. Completion requires every affected reference/build input updated and all remaining address-derived placeholders classified. Do not claim original source-file reconstruction from address order alone; the delivered modules are the confirmed native organization.

## C++ ownership reconstruction

Maintain one current inventory keyed by `(image, original_address)`: current symbol/source, receiver type or absence, field accesses, direct/indirect callers, callback ABI, candidate owner, ownership evidence and confidence. Preserve earlier inventories as historical evidence. Count original identities separately from physical definitions and retained marker aliases.

1. Identify instance methods through repeated access to one object argument, consistent field widths/offsets, initialization and object lifecycle. Check every caller and callback before converting the argument to `this`. A first pointer argument alone does not prove a receiver. Retain `const` when all operations are read-only; do not infer it from one caller
2. Build candidate class groups from shared receiver layouts, constructor/destructor paths, member dispatch tables, common globals, resources and original address ranges. Address proximity supplies a candidate, not proof. Keep distinct executable images separate. Record whether an ownership assignment is confirmed or inferred; an inferred assignment requires the user's authorization for that uncertainty
3. For a non-SDK free function with ambiguous or conflicting ownership, inspect its callers, arguments and state; use preceding/following methods in the same image and stronger non-neighbor candidates as additional evidence. Do not repeat neighbor investigations when receiver/state/lifecycle already establish its owner. Add a function as an instance method when it has the established receiver; add it as a static method when its operation belongs to that class but has no receiver. Keep unrelated utilities free. Do not add a dummy receiver, wrapper or extra forwarding function to reduce the free-function count
4. Recover inheritance only from compatible base layouts, base initialization/destruction, dispatch-table relationships and actual base operations. Shared prefixes, repeated fields and neighboring addresses alone do not prove inheritance. Preserve composition, embedded records and tagged unions when those models match the evidence
5. Move each original definition, declaration, callers, function-pointer tables and source/address mappings together. Retain every `FUNCTION_MARKER` inside its original body. Naming changes never create a second definition. Preserve callback calling conventions and parameter/return effects; keep a boundary adapter only when the ABI requires it and record its removal condition
6. Put methods of one established class in its matching header/source module; colocate supporting value records used by that owner. Do not generate an empty source file for a header-only value type. Place each global definition once, with unchanged default values, initialization dependencies, lifetime, reset and release. Merge data-only fragments into an explicitly requested global-data module; leave methods with their class and keep substantial original constant tables in their deliberate data owner
7. Sort method declarations and definitions by original address. For a definition retaining several primary markers, use its smallest primary address. Preserve all markers, field order and each member's access. Repeat access labels when needed; never reorder fields to obtain method ordering. Declare static members with `static` inside the class; omit `static` on out-of-class definitions, as required by C++
8. Report remaining free functions with separate counts for SDK/CRT/compiler helpers, native entry/platform boundaries, original game functions and unresolved ownership. Count a function once by original identity; report aliases separately. Zero free functions is not an acceptance requirement

Preserve original control flow while reconstructing C++. Confirm loops from original induction/pointer updates and back edges; a repeated sequence of coordinate operations is not proof of a loop. Keep unrolled X/Y/Z or W/X/Y/Z operations explicit when that is what the reviewed MIPS contains. Do not introduce recursion, iteration, common helpers, exceptions, aborts or fallback returns to simplify the recovered body. Preserve low-word products, arithmetic shifts, alias-dependent reloads, callback order and original error results. Behavioral bug fixes require separate authorization and evidence.

Use the user-selected language feature subset. Do not introduce STL, exceptions, RTTI, type inference, anonymous namespaces or modern casts merely because the host compiler supports them. Hide file-private functions with `static` when requested. Remove redundant `this->` only after checking local/parameter/member bindings; rename a shadowing local by its role and preserve necessary `this->*` member-pointer expressions. Do not invent getters for directly accessed state.

Replace opaque `words`/`bytes` storage with fields or established components, not another wrapper around the same anonymous storage. Keep real homogeneous arrays. Name semantic index domains with an enum ending in a count sentinel and use that sentinel as the array bound. Keep serialized storage separate from native owners; binary buffers and genuine vector components remain justified arrays.

Before adding or retaining a cast, inspect whether the source variable, parameter, field or whole homogeneous array has the wrong type. Select the type from all producers, arithmetic, comparisons, shifts, callers and serialized widths. Audit both operands of a product. A cast at one use does not prove that a signed field should become unsigned. A destination conversion does not replace intermediate narrowing or required widening. Record numeric/ABI conversion rules per type or family, with individual entries only for meaningful exceptions.

Apply identifier mappings to code tokens and current symbol/type keys. Preserve asset strings, original image identities and existing evidence filenames/paths. Update debugger expressions, fixture selectors and current source manifests after type/member renames; do not rename immutable historical evidence through a global text replacement.

## Residual scalar-access gate

- Inventory all game-source `r_*`, `w_*`, `xport_load_*`, `xport_store_*`, other endian load/store helpers, numeric-address casts, pointer aliases and project-local access wrappers. Assign every occurrence to native game state, decoded resource data, serialized input/output, GPU packet/OT storage or an actual SDK/device boundary
- Replace native state access with its owning field/array. Do not close an item by renaming `r_u32`/`w_u32` to `xport_memory_read`/`xport_memory_write`, casting the same address at every use or introducing a replacement accessor. A bus API is justified only at an identified BIOS/device boundary, with its address domain, width, mask and side effects recorded
- Bind retained GPU buffers through a typed pointer over the required mapped span. Use shared packet fields, packed words and typed OT entries. Preserve high-byte lengths, low-24-bit links and reloads after potentially aliasing writes. Do not cast MMIO registers to host pointers or bypass device callbacks
- Use direct typed fields/arrays for aligned decoded records. Keep endian helpers only for genuine serialized byte boundaries; do not apply them to an already typed native field. Add a shared packed SDK field only after establishing unchanged size, alignment and offsets; do not duplicate the SDK record in a game header
- Do not use `xport_load_*`/`xport_store_*` to read or update native game state, decoded object fields or known GPU packet fields. Replace such accesses with the owning typed field/array or the established PsyQ packet setter. Example: replace `xport_store_le32(&object->health, value)` with `object->health = value`; replace a byte-offset access to an established native position with `object->pos.y`. Changing the helper name, adding a wrapper or casting a native owner to a byte buffer does not satisfy this requirement
- Retain `xport_load_*`/`xport_store_*` only at a demonstrated serialized, unaligned variable-format or SDK/device byte boundary. Group retained sites by one demonstrated format/device contract; record owner, widths, byte order, alignment/span bounds and why typed fields or an existing SDK API are unsuitable. List per-site exceptions instead of duplicating the contract. A known typed GPU packet is not an exception merely because its representation is packed. Preserve required endian conversion and device callbacks
- When the user limits a project to native little-endian targets, remove endian access helpers from little-endian game resources too. Bind established aligned records/tables once and use their typed fields/elements; copy complete matching records when appropriate. At a bounded byte-cursor interface, copy the native scalar with `memcpy` when a typed view is unsuitable. Do not add renamed load/store wrappers, byte assembly or hypothetical big-endian support. Preserve span checks, widths, signedness and actual device callbacks; this project restriction does not change shared SDK contracts for other consumers
- At final verification, require zero unclassified occurrences and zero game-state address/accessor adapters, including native-state accesses hidden behind `xport_load_*`/`xport_store_*`. List every retained binary/device boundary explicitly. Passing builds, coverage counts and searches with no `r_*/w_*` or `DRAM`/`SCRATCHPAD` matches do not prove complete native ownership or original control-flow fidelity
- Keep unchanged-body/layout checks across moves and renames. For intentional operation changes, retain complete before/after definitions and original evidence; plan whole-operation checks against independent pre-change or MIPS oracles, including aliasing, signed extremes, truncation and packed service bits, for final verification. A generated after-state snapshot is not a behavioral oracle. Fixtures must execute current definitions; archived bodies serve only as explicitly identified references

## Typed access, conversions and scopes

- Prefer `src[idx]`/`dst[idx]` for real typed arrays. For an aligned native `const uint16 *src`, `src[1]` reads the second halfword; `*(const uint16 *)(bytes + 2)` is equivalent only when alignment, object/aliasing rules and byte order permit it. A pointer-to-integer cast does not load memory
- If an established aligned resource record exactly matches an SDK/native structure on the supported target, view its validated span as a const typed array and assign whole records (`face->v[v] = vertices[idx]`). Preserve payload fields such as `SVECTOR.pad`; verify size/layout and byte order. Do not decode identical structures field by field or add per-record copy helpers. Keep decoding for formats whose layout/encoding differs
- Use fixed-width uint32 for game resource sizes/offsets/counts and bounded runtime capacities; do not propagate host size_t into game state or APIs. Keep size_t only at standard-library/platform interfaces that require it, validate before narrowing to uint32, and retain overflow/bounds guards. Audit alignment rounding and additions after changing width; sizeof and allocator arguments still use their mandated host types
- Replace repeated byte assembly with established typed fields/arrays when the resource and supported host byte order match. Use existing width/endian helpers only where the target or device contract requires them and the project's explicit target policy permits them. Do not introduce a helper around every ordinary field access. Preserve real byte swaps and packed encodings. Original MIPS alignment alone does not establish every host C access contract
- Remove a whole-expression cast when the assignment/initialization destination or fixed function parameter already performs exactly that conversion. Example: `uint8 tag = word >> 24`, `select_track(idx)` for a `uint32` parameter. Verify the declared source/destination types and all arithmetic after the cast; variadic arguments have no target parameter conversion
- Remove same-type duplicate casts. Remove signed reinterpretation in `==`/`!=` to a representable nonnegative constant only when the source already has the same integer width; preserve truncation from wider sources. Example: a `uint16 mode` needs no `(sint16)` for `mode == 6`; `(sint16)mode < 0` can test its high bit and must not be simplified on that basis
- Preserve casts that establish arithmetic width/signedness, shift behavior, fixed-point truncation, wrapping, saturation or sign/zero extension before another operation. A final implicit conversion does not replace intermediate narrowing (`(uint16)signed_value` passed to a `uint32` parameter)
- Audit whole array subscripts and pointer offsets separately from argument/assignment casts. Drop value-preserving promotions (`records + (sint32)idx` for a sint16 idx). Drop signed/unsigned conversions only with established index bounds; Prefer explicit signed bounds for rendering depths and indices when clearer: `(uint32)depth < limit` -> `depth >= 0 && depth < limit`, and `(uint32)depth >= limit` -> `depth < 0 || depth >= limit`, only for a proven positive limit <= INT32_MAX. Keep all negative-value rejection; retain unsigned range-test casts when the unsigned domain is required. A cast in pointer arithmetic does not set the pointed-to element type
- For paired-buffer allocation prefer `calloc(count, 2u * sizeof(*packet))` over `calloc((size_t)count * 2u, sizeof(*packet))` when both describe the same layout. Keep the total-size overflow guard; do not remove a size-width cast before arithmetic merely because the allocator parameter is `size_t`
- Remove standalone compound blocks that only hide a temporary copy or return sequence. Never place an unrelated `{ ... }` immediately after an unbraced `if`, `for`, `while` or `do` body; use separate explicit conditions or a clearly named coherent helper. Retain intentional scopes for lifetime/shadowing/conditional compilation only with a clear boundary: brace the preceding control body and separate the independent scope with a blank line; flattening must preserve declaration binding, goto/loop targets and observable ordering

### Bounded destination-cast planning without a compiler

`tools/refactor_assignment_casts.py` exposes `plan_function` for one complete C function using pycparser syntax only. Supply actual fixed-width aliases, syntax-only type names, all visible macro names and optional reviewed direct-call result aliases. Pin these inputs and source hashes in the consuming family report. Stub typedefs provide parsing only, never ABI or integer-type evidence. The planner returns prefix deletions for complete initializer, plain assignment or return cast chains at known local fixed-integer destinations; unknown globals, fields, pointer domains, SDK results and preprocessing bodies remain unchanged. It preserves operand arithmetic and intermediate narrowing. Enable `twos_complement` only for established fixed-width target representation; that option permits removing an outer integer conversion at least as wide as the final destination by low-bit congruence. Preserve the inner explicit pointer-to-integer crossing. Review exact reversible edits, reparse affected functions and retain exclusions; this bounded pass does not close the full numeric audit or prove runtime/MIPS acceptance. Run focused checks with `python -B -m unittest discover -s tools/tests -p test_refactor_assignment_casts.py` from `[XPORT_ROOT]`.

### Automatic integer-expression pass

Use `python -B [XPORT_ROOT]/tools/refactor_c_integer.py --project PROJECT --config CONFIG.json --report REPORT.json` for a static dry run. Add `--apply` to apply unambiguous rules to a fixed point. Repeat `--source src/module.c` for an affected subset. This command runs the Clang frontend only; it never builds or executes the game

Configuration inputs: `compiler` is the pinned Clang executable; `arguments` supplies target, includes and game defines without a source or AST action; `configurations` maps names to additional preprocessor flags; `sources` lists project C translation units. `header_inputs` maps current absolute header paths to SHA-256. Set `type_spellings.signed32/unsigned32` to the project's declared aliases. Enable `twos_complement` only for an established fixed-width target contract; host `long`, pointer-width types and `size_t` are excluded. Keep `audit_queries` enabled for consuming projects

The engine binds uses to declarations with Clang IDs, applies integer promotions/usual conversions, propagates immutable-local intervals, and normalizes low-word congruences through ring operations. Division, comparisons, right shifts and intermediate narrowings are observation barriers. It can remove identity/destination/implicitly supplied conversions, move an unsigned domain to a literal, and change a local signedness only when all reads already consume the opposite word view and its address does not escape. It preserves shared declarations or splits a simple declaration without changing initializer order. It rejects conflicting preprocessor configurations and simultaneous edits that depend on each other

On the established two's-complement target, unsigned32 ring values retain a separate interval for their signed low-word interpretation. Propagate that interval through addition/subtraction/multiplication modulo 2^32; use the full signed32 hull when a mathematical interval crosses a signed wrap boundary. A subsequent signed32 destination can recover this range instead of losing it at an intermediate unsigned conversion. This never licenses overflowing signed arithmetic: each proposed signed operation must still fit its natural domain. Division/right shifts and intermediate narrowings keep their own observation domains. Direct local declarations may use macro initializer ASTs for range inference even when those initializer tokens are not editable

Repeated stable operands can be cached in a `const uint32` working value to establish their actual arithmetic domain once. For example, `const uint32 half_width = width / 2` preserves signed division for every signed width, including negative values; `cur_x - half_width` then supplies the same unsigned32 subtraction as `(uint32)cur_x - (width / 2)`. The default rule requires multiple uses, immutable/nonescaping referenced scalars, a total expression over declared types, and a dominating declaration point; it rejects labels/gotos and partial arithmetic. This rule needs no game-specific bounds or assumptions about callers

Repeated signed observations of a stable unsigned32 expression can similarly share a `const sint32` producer on an established two's-complement target. Preserve the original unsigned expression before initialization;do not replace wrapped arithmetic with signed overflow. For either cache rule, local scalar inputs must be initialized and nonescaping. Veto unknown lexical uses and configurations in which an input declaration exists but the proposed cache has no matching use;never hoist an uninitialized read out of a conditional

Optional `closed_world_parameters` infers parameter ranges from all configured C callers and both configurations before rewriting. It preserves public API declarations, leaves callbacks/address-taken functions at full ranges, rejects unparsed call sites, and propagates immutable parameter forwarding to a fixed point. Use only for an explicitly closed program; keep it disabled when full public helper input domains must remain valid. It is not required for the repeated-operand rule above

Optional `counted_loop_ranges` bounds induction reads inside canonical `for (i = 0; i < stable_limit; ++i)` bodies, including comma-separated companion assignments/increments. The comparison must use signed32 operands. Limits must be immutable, nonescaping automatic scalars or total expressions over them. The initial and final increments must fit the declared induction type; body mutations, address escape, other writes and functions with goto/labels veto inference. Bounds never transfer to reads after the loop. Source/profile agreement and original-query handling remain mandatory

Optional `bounded_mutable_ranges` computes the hull of an initialized automatic signed32 scalar's initializer and every plain assignment. It also handles standalone unit increments guarded by `current < target` and decrements guarded by `current > target`; all target intervals join the hull. Such steps cannot leave the hull containing the initial/reset values and targets. Require complete reference/write closure; reject address escape, compound updates, unguarded/wrong-direction steps, observed updates and goto/switch-label/assembly cases. Start from full domains, propagate only already sound bounds, and preserve every assignment and update. Keep the guarded-step arithmetic/interval invariant proof with the consuming family. Unknown source arithmetic remains unknown; never initialize an iterative analysis from only a mutable variable's initializer

`atomic_parentheses_functions` maps project C paths to explicitly selected stable function names for post-cast cleanup. Remove grouping only around directly spelled scalar/postfix atoms, retaining sum/shift grouping, comments, macro boundaries, sizeof grouping and call-callee parentheses that can suppress a function-like macro. Match all profiles that parse the site and preserve token separation. Optional `enabled_rules` restricts proposals to named rules (including imported clang-tidy proposals); a fixed point under this restriction does not close other rule families

Optional `signed_pow2_division` supplies `source` and `sha256` for the existing `mips_div_pow2_trunc` implementation. The engine recognizes only its exact tokenized signed32-input/unsigned32-shift bias-and-arithmetic-shift body and matching external call signature. With an established two's-complement target and a proved shift range 0..31, bound the result by signed division toward zero at the input/shift interval endpoints. Unknown shifts, static lookalikes and changed bodies supply no intrinsic range. Keep a full-domain numeric proof for this helper contract; it does not establish caller bounds or original-function acceptance

Optional `global_field_contracts` binds reviewed resource ranges to direct global scalar fields. Supply `report`, pinned `sha256` and an identical `fields` map. The schema1 report contains fields with `range` and `writer` (`function`, `parameter`, complete `callers`), hashed resource `inputs`, `missing_inputs`, body-pinned `protected_functions`, optional exact `protected_text` table windows, and exact `header_declarations` for root globals. Review the binary-reader-to-parameter bridge against complete relevant originals and current code before supplying this report; an asset scan alone is insufficient

The engine requires the complete configured caller program. It independently inventories direct writes in every profile, rejects changed writers/callers, compound writes, field/aggregate address escapes, explicit aggregate initialization, static/local lookalikes and unparsed root uses in all game C/H (including inactive branches/macros). Ranges must include static zero state. Changed resources, newly available missing inputs, producer bodies or protected tables fail closed. Computed validation outputs cannot be imported as configuration inputs. Protected producer functions are excluded from automatic edits; re-review their bridge before changing them. These are corpus-scoped facts, never full-domain assertions about arbitrary replacement assets

Macro expansions, bitfields, volatile/atomic operands, native-width boundaries, type observers, mixed signed consumers and unresolved provenance remain in the report for manual work. Existing semantic-map identity lookup does not promote its semantic status. Before applying, the tool runs the required original queries for affected identities. Exact source/header hashes guard stale inputs. Changed translation units are reparsed between iterations; unchanged analysis is reused in memory. A failed reparse rolls back only the preceding unparsed edits whose exact owned bytes remain unchanged

Optionally set `clang_tidy` to an installed LLVM/Visual Studio `clang-tidy` executable and provide PyYAML in the Python environment. The tool runs only `readability-redundant-casting`, imports prefix-only fixes within selected project function bodies, rejects header/macro fixes, and requires the same configuration consensus as the Python rules. ## Whole-project cleanup passes

Apply accepted general cleanup rules to every game module/header, not only user-reported lines. Inventory all occurrences and classify residual exceptions. Preserve SDK/device/binary contracts; a count or a clean build does not close the audit. Use token/AST-aware edits, resolve collisions and update direct/indirect references; automatic replacement must exclude comments, strings, type/module names and required ABI symbols unless explicitly authorized.

During family migration fix ownership, types, numeric contracts and meaningful names immediately. Run exhaustive editorial cleanup once after native interfaces stabilize; collect candidates with static tools instead of repeatedly scanning every module. Revisit only affected scopes after new edits. Apply the verification policy above:

1. Names: address-derived placeholders, approved substitutions, ordinal words and stale project prefixes/guards. Numbered peers use suffixes or one coherent array: `SVECTOR first_three[3]; SVECTOR fourth;` -> `SVECTOR v[4]`. Preserve first/last range endpoints and chronological roles. Private static names normally omit the owning module prefix
2. Types: replace semantic vector/quaternion arrays with project-owned component structs; provide an indexed union when both access patterns are needed. Signed coordinates/velocities require signed components. Distinguish native math from SDK VECTOR/SVECTOR and serialized layouts; flatten single-consumer wrappers without a distinct contract. A rename requested for one project's type does not authorize the same rename in other projects
3. Conversions: inspect all uint8/sint8/uint16/sint16/uint32/sint32/uint64/sint64 casts, including indices and macro arguments. Correct inaccurate field/parameter/result types from all producers and consumers first. A signed16 API result can return sint16 directly instead of casting a wider return and every caller. Document conversion rules per type/family and significant exceptions; never delete casts by regex
4. Parentheses: clean again after removing casts. Preserve precedence, associativity, casts, comma expressions, sizeof and postfix operands. Keep parentheses around an arithmetic sum/difference used as a shift operand: `(r + g + b) << 12`; the grouping must show which complete value is scaled even when precedence permits omission. `shared = (tex[0] ^ tex[1]);` becomes `shared = tex[0] ^ tex[1];`; `(*ptr)--` keeps its grouping. Inspect macro expansion before changing argument grouping. Automated edits must preserve parsed operations and types
5. Temporaries: collapse one-use relays and pack-then-unpack sequences. `TYPE *items = owner->items; TYPE *item = items + idx;` becomes direct item selection. Retain typed local pointers for repeated element access. Prefer direct component assignments and compound updates. Hoist loop-invariant reads only after required guards and before mutation/callbacks that can change them; follow project declaration placement conventions
6. Arithmetic: use ordinary negation, abs, sum, subtraction, division and remainder when established ranges permit. Express negation with unary `-x`, not `0 - x` or `0u - x`; preserve the required operand type, integer promotions and wrapping semantics without introducing signed-overflow undefined behavior. Retain arithmetic widening, intermediate narrowing and required wrapping. User authorization to simplify one game's bounded arithmetic does not change other projects' contracts. Express powers of two as correctly typed shifts; briefly explain fixed-point units and approximation domains. Use PsyQ `ONE` for Q12 unity in matrix/vector initialization; do not replace button masks, file sizes or world-space distances merely because they equal 4096. Reuse a project-owned `clamp(x, a, b)` for equivalent two-sided saturation; its arguments must have no side effects, bounds must be ordered, and operand signedness must preserve the original comparisons. Do not replace a state-changing branch with a clamp. Reuse original math helpers; introducing a new game helper requires explicit authorization. A game approximation is not automatically PsyQ
7. Constants/packets: remove redundant literal suffixes only if promotions, shifts, comparisons and overflow behavior remain unchanged. Use PAD masks, getClut/getTPage, primitive initializers and packed XY/UV/RGBC copies. Assign direct fields instead of creating a packed temporary solely to split it again. Preserve genuine binary encodings and service bits
8. Visibility: audit whole-project callers, callback/function-pointer tables and ABI consumers. Remove private header declarations, mark private functions/globals static, move private types into their module and order definitions to minimize forward declarations. Remove empty/unreferenced functions only after checking side effects and external uses
9. Ownership: embedded images belong to the module or one deliberate image translation unit; private single-consumer tables need no separate data headers. SDK stubs/algorithms/tables and platform synchronization belong to xport behind PsyQ calls. Shared SDK tables must be independent of game addresses; verify affected existing consumers. Preserve callbacks and thread behavior
10. Final scan: close collected names, casts, parentheses, temporaries, packed accesses and visibility candidates once; after repairs rescan only affected scopes unless evidence of a systemic omission requires a wider pass. Keep current source/executable hashes, reviewed exceptions, test scopes and acceptance in one compact project report. Refresh locations after renaming/formatting; preserve historical reports as historical

Do not add speculative arithmetic guards, compatibility mirrors, allocations or platform hooks to ease translation. Do not remove required boundary guards because a failure has not occurred. Separate behavior repairs from readability edits and verify original semantics for repairs. Name wrappers by their complete operation: loading vertices + RTPT + reading outputs is broader than the PsyQ `gte_rtpt_b()` instruction macro.

## Packet and resource access

Repeated accesses to one structure-array element: introduce a local typed pointer (`TYPE *face = faces + idx`, `face->field`) within the narrowest coherent scope. Preserve `const`; establish it after bounds checks/index selection and before its uses. Do not reuse it across index/base changes, reallocation or a changed owner. Keep scalar-array indexing when a pointer adds no clarity. Known GPU packet kinds use shared packet types and their typed/packed fields instead of byte pointers plus numeric offsets. Use `poly` for `POLY_*` locals and `line` for `LINE_*` locals, with numeric suffixes when required. Shared GPU views are `XY`, `UV`, `RGBC`, `POINT_C/T/CT`; packets expose only `p[]` for vertices and `rgbc.rgbc` for packed color words. Do not recreate named vertex aliases or game-owned packet structs where shared types suffice. Initialize known primitive kinds with `setPoly*`, `setLine*`, `setSprt` or `setTile`; line initializers own polyline termination. A DMA tag length does not identify its GPU command. Use `setlen` for deferred/already filled packets, preserving command bits, raw-texture/semitransparency flags and OT links; never reinitialize these packets blindly. Keep raw buffers only at actual variable-format boundaries. Briefly comment confirmed non-padding payloads at their producer/consumer; preserve device widths and do not infer meanings from field names.

Four-byte resource IDs: after establishing alignment and a complete four-byte span, compare a typed `uint32` field against explicit `CHUNK_*` constants in the supported host byte order. Preserve genuine endian conversion for numeric sizes; do not apply byte swapping to ASCII IDs. Record whether the original used word comparison or a string routine; byte-equivalent native simplification does not establish literal original-MIPS implementation. File lengths/counts/offsets use justified fixed-width game types; keep `size_t` only at standard/platform API boundaries and validate narrowing.
