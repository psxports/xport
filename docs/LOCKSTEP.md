# Lockstep pipeline

The lockstep pipeline replaces the prior public `record` and `converge` routes. It replays an initial DuckStation save state and one effective controller state per `FrameDone`, matches original and native semantic events, and compares memory only after matching events.

Recorded controller state updates physical input only. It must not write a guest PAD
report at `FrameDone`. The PAD SDK completion publishes its completed receive buffer
before starting the next exchange, preserving the receive buffer restored from the
initial state. Seed physical input at a handoff from the already applied recorded input
and preserve it in the native checkpoint. Do not implement this ordering as a frame delay
or copy Original guest reports into Native during replay.

## Frozen contracts

`tools/lockstep_contract.py` is the machine-readable authority for build, peer mapping, event, reviewed stack and compact compare-reply validation. Unknown fields and versions fail closed.

The first implementation supports Windows Debug x86. `LOCKSTEP_DEBUG` is the only switch that enables mapped memory and debugger boundaries. A lockstep build has two mandatory mappings: 2 MiB DRAM and 1 KiB scratchpad. A missing mapping is an error and never falls back to local arrays. Builds without the switch retain the ordinary arrays and have no Win32 mapping dependency.

Memory equality covers DRAM and scratchpad outside compiled exception ranges. VRAM and SPU RAM are outside the first implementation. Ordering tables remain part of DRAM and have no separate comparison.

Exceptions use `xport-lockstep-exceptions-v1`. `xport_trace.c` owns common firmware and PsyQ ranges; every enabled game compiles a `src/game_except.c` array for evidence-backed title ranges such as its guest stack. CDB reads both arrays from the stopped process, validates sorting, overlap, region bounds, kind and ownership, then sends the complete identity to DuckStation with `qXportLockstepExceptions`. There is no JSON parser or runtime policy file.

The supervisor compares memory only for matched `PRE_CALL`, `POST_CALL`, or `VBLANK` events. Event mismatch is `control_flow_divergence`; comparing memory across different semantic events is invalid. DuckStation performs the exact comparison against read-only native mappings. Python receives only a compact verdict and bounded difference.

For an audited deferred file load, the scheduler holds Original at the first deferred boundary,
advances Native until the shared deferred generation closes, and queues every validated Native
event. It then holds Native and pairs Original against that queue. Deferred boundaries never
advance confirmed progress. The resolving comparison is a ranged match, and only the following
full memory match can advance the rolling checkpoint.

## Native memory publication

`xport_lockstep_memory_init` validates `XPORT_LOCKSTEP_RUN_ID`, `XPORT_LOCKSTEP_DRAM_MAPPING`, and `XPORT_LOCKSTEP_SCRATCHPAD_MAPPING` before creating either mapping. Names must match the canonical run-specific names. Existing objects are rejected as `mapping_collision`; this prevents a stale or foreign mapping from becoming runtime memory.

The mapped views are the backing storage referenced by `DRAM` and `SCRATCHPAD`, so there is no synchronization copy. `sizeof(DRAM)` remains `0x200000` and `sizeof(SCRATCHPAD)` remains `0x400`. Initialization errors have stable names for the supervisor handshake. The consuming Windows entry point must call initialization before any PSX runtime access and shutdown after game execution.

Without `LOCKSTEP_DEBUG`, `psx.c` defines the original arrays. The lockstep translation unit rejects compilation without the flag or on a platform other than Windows x86.

## DuckStation peer and comparison

The patched GDB server advertises `qXportLockstepAttach`, `qXportLockstepExceptions`, `qXportLockstepMode`, `qXportLockstepReplay`, `qXportLockstepSeed`, `qXportLockstepCompare`, `qXportLockstepDiff`, and `qXportLockstepDetach`. Attach validates the canonical run identity, opens both named objects with a read-only view, verifies their kernel section sizes, and rejects a second run until detach. Repeating an identical attach is idempotent.

DuckStation publishes an ordered shared timeline for SPU key-on, key-off and voice-envelope reads. Native consumes the matching event before applying that operation and advances its SPU to the event's exact sample tick in both `PREFIX_GUARD` and `DETAILED`. At VBlank it advances only from the last consumed event tick to the published end-of-frame tick. Restoring the checkpoint for frame `N-1` restores the timeline cursors and SPU clock before any function in frame `N` executes. Prefix and detailed instrumentation must therefore produce identical SPU and guest-memory state at the next VBlank.

The native process stops at `xport_lockstep_memory_ready` immediately after it creates the DRAM, scratchpad, VRAM and deferred-state mappings and before game code can access PSX memory. The supervisor then loads the record save state in a paused DuckStation process and issues one identity-bound seed request. DuckStation synchronously reads back canonical VRAM, temporarily opens writable mapping views, copies its restored 2 MiB DRAM, 1 KiB scratchpad and 1 MiB VRAM, flushes and closes those views, and retains read-only views for later comparisons. Boundary tracking cannot start before seeding, and a second seed is rejected. This makes the save state the sole initial-memory authority without allowing a late reseed to hide divergence.

`qXportLockstepExceptions:<identity>:<region>,<offset>,<size>[;<region>,<offset>,<size>...]` registers sorted, non-overlapping compiled exceptions for `dram` and `scratchpad`. The identity hashes the complete contract, so any changed range invalidates it. The emulator scans both regions outside those exceptions and returns the first contiguous difference, capped at 64 bytes per side. `qXportLockstepDiff` can retrieve a bounded subrange only from the latest request.

Compare is accepted only while emulation is stopped. Detach releases both views and handles; GDB shutdown also detaches. Mapping protocol metadata remains in the supervisor and never occupies guest memory.

## Native boundary ABI

In a `LOCKSTEP_DEBUG` build, every existing `FUNCTION_MARKER` calls the exported, non-inline `xport_lockstep_boundary_break` through `xport_lockstep_function_marker`. CDB needs one symbol breakpoint for all translated functions. The hit record contains a monotonic sequence, image/address/function/source identity, semantic arguments, return kind, and a native GTE snapshot. Builds without the flag compile the marker exactly as before and contain no lockstep boundary reference.

The default marker declares no arguments and an unspecified return. A reviewed project binding can use `XPORT_LOCKSTEP_BOUNDARY` with up to 16 normalized `XportCallValue` arguments and an explicit void, scalar, or guest-pointer return kind. Scalars retain all 64 bits. Guest pointers carry region, offset, and byte extent rather than a host address. Host and opaque pointers remain unsupported equality values.

Translated project functions can use `FUNCTION_MARKER_ARGS` to preserve the ordinary audit marker in non-lockstep builds while publishing reviewed argument descriptors under `LOCKSTEP_DEBUG`. The scheduler compares original MIPS argument registers against native scalar or guest-pointer descriptors before memory comparison, and compares non-void return values at POST. An argument or return mismatch is a control divergence and never triggers a RAM comparison.

Each ABI argument may declare an original `register` such as `a0` or `t0`. Without the field, positions zero through three use `a0` through `a3`; a fifth or later argument requires an explicit register. Only boundaries with an explicit register annotation incur one GDB `g` read at PRE_CALL. The adapter verifies that GDB's `a0` through `a3` equal DuckStation's event snapshot before replacing the argument list with the declared register values. A missing or inconsistent register snapshot fails closed. This supports nonstandard MIPS helpers that carry pointer arguments in `t0` through `t3` without changing the emulator's event format or reading RAM through Python.

The sequence identifies an entry observation, not an invocation. The CDB controller assigns invocation IDs and pairs temporary return breakpoints, so recursion and repeated host return addresses cannot collapse distinct calls. Binary, linker PDB, source, and contract hashes form the native handshake.

## Original MIPS boundaries

DuckStation's debug interpreter maintains a dynamic call stack while lockstep is active. It recognizes `jal`, `jalr` with any link register, taken `bgezal` and `bltzal`, ordinary `jr` returns, and only explicitly reviewed `j` or `jr` tail calls. Interrupt and exception handlers use a separate execution context, so their calls cannot change the interrupted call tree.

The project ABI registry supplies the exact original targets observed by lockstep. `qXportLockstepBoundary` installs those targets after tracker reset. Calls outside the frontier execute without events; a registered call inside an unregistered function still has the nearest registered invocation as its semantic parent. CDB applies the same address set to native markers. Static coverage rejects duplicate marker identities, missing original listings, unsupported indirect calls and unreviewed tail jumps as `missing_boundary_binding` before replay. `reviewed_indirect_returns` permits a nonstandard saved-`$ra` return only when its save and `jr` opcodes, addresses, destination register and complete listing SHA-256 match the reviewed registry entry. A changed listing fails closed.

`PRE_CALL` is raised before the first callee instruction, after the call delay slot has executed. `POST_CALL` is raised before the next caller instruction, after the return delay slot has executed. Each event retains its callsite address and word, delay-slot address and word, resolved target, link register and value, register snapshot, return value, `HI/LO`, and a stable identity of all 64 GTE registers. Only a `PRE_CALL` register snapshot is valid as callee entry arguments. For a divergent `POST_CALL`, the attention packet's `arguments` comes from the preceding matched `PRE_CALL` with the same function, frame and invocation; otherwise the argument field is unavailable. The packet records the source boundary for each side.

The bounded repair context exposes these values as `entry_arguments`. It omits the `arguments` field from `expected_original_event` when that event is `POST_CALL`, so post-return register values cannot be mistaken for call inputs in a model request.

The bounded repair context includes reachable same-file C helpers by default, subject to its 65,536-byte cap, because an owner's MIPS listing may inline their behavior. An explicit `related_helper_symbols` list narrows that selection. A helper omitted by the cap is named in `omitted_local_c_helpers`; an audit that needs its behavior must not guess it.

The GDB server exposes `qXportLockstepStart`, `qXportLockstepTail`, and `qXportLockstepNextEvent`. Only one event can remain pending. The emulator pauses before publishing it and resumes at the same unexecuted instruction after the supervisor consumes it. Starting boundary tracking requires an attached shared-memory peer; detaching disables tracking.

## Native CDB controller

`tools/lockstep_cdb.py` owns one persistent x86 CDB process and accepts protocol decisions only from tokenized `XPORT` markers emitted by debugger commands. It never treats localized debugger prose as protocol state. Before launch it reads the PE CodeView record and the PDB information stream directly and requires matching RSDS GUID and age.

The controller sets one breakpoint on `xport_lockstep_boundary_break`. The boundary record includes the host return address captured in the translated function itself. CDB installs a one-shot breakpoint at that address and reinstalls it only while another recursive invocation needs the same address. Controller-assigned invocation IDs therefore remain distinct even when recursion shares a host return address.

The target remains stopped after every PRE, POST, FAULT, or PROCESS_EXIT event. Structured APIs expose x86 registers, the semantic invocation stack, source location, continue, interrupt, and explicit breakpoints. The watchdog sends Ctrl+Break only to the CDB process group it created, checks that the target PID is unchanged, and reports the stopped instruction. Access violations and process exit use debugger event commands with machine markers.

## Event scheduler

`tools/lockstep_gdb.py` attaches DuckStation to the two native mappings, registers reviewed stack exclusions and tail calls, retrieves compact original events, and requests in-emulator comparison. It never reads DRAM or scratchpad. `tools/lockstep_events.py` advances DuckStation and CDB concurrently to their next events, leaving the first process stopped while the second catches up.

The scheduler requires monotonic event sequences and call ordinals. It compares event kind, frame, image, function/target, invocation context, depth, parent, and call ordinal without searching ahead or realigning. Missing, extra, wrong-target, stack, frame, runtime, exit, and watchdog divergence are stable outcomes. A mismatch halts both streams and never requests a memory comparison.

For a matched PRE, POST, TAIL, or VBLANK, the scheduler sends one request ID to DuckStation. DuckStation scans its RAM against the read-only native mappings and returns only MATCH, a bounded first difference, or a stable error. A second pending event per side is impossible because neither process resumes until the current pair and its comparison have been accepted.

## Timer migration observations

`lockstep.timer_observation: true` requests a compact `qXportLockstepTimerState` observation at the paused handoff and at a divergent VBlank. The reply contains serializer version 85, the original CPU clock including pending ticks, pending SysClk event ticks, and the exact 59-byte timer serializer. Reading it must not advance timers, deliver IRQs, clear mode flags or export DRAM. Preserve counter modes, counting/gate flags, IRQ history and the SysClk/8 carry; serialized counters may lag the reported CPU clock by the explicit pending SysClk ticks.

The supervisor writes `handoff-timers.json` and includes `original_timer_state` in the divergent result. These are migration evidence, not a paired checkpoint, a memory exception or a MATCH. Never copy a divergent game counter from this observation or replace the timer scheduler with a per-frame increment. Import the handoff device phase and preserve the emulated clock and interrupt timeline before enabling timer callbacks.

## Deterministic FrameDone record

`tools/lockstep_record.py` owns `xport-lockstep-record-v1`. A record identifies the initial save state, every disc file, original executable, DuckStation commit and patch, settings, PAL or NTSC field rate, and one effective two-port controller state per FrameDone. Every file is size and SHA-256 checked before reuse. The canonical record identity also covers the complete input schedule.

Frame numbers in this protocol are lockstep ordinals rather than DuckStation UI frame numbers or a game's VSync counter. The first FrameDone after the initial state is ordinal zero. Its VBLANK event is compared at zero, then PRE and POST events in the following interval use ordinal one. This gives the original and native processes the same clock even when their internal counters have different origins.

DuckStation captures input after its normal `InputManager::PollSources` call and before the next frame executes. Replay applies the recorded state at that same hook and rejects a missing, duplicated, out-of-order, unsupported, or busy controller. Native replay reads a compact identity-bound input file at startup, applies the corresponding pad packets in `psx_vblank_signal`, and emits the same VBLANK boundary before guest callbacks execute. All SIO polls until the next FrameDone therefore see one stable state.

The scheduler compares the two effective controller states before requesting a memory comparison. An input mismatch is `input_schedule_divergence`, so memory from different input histories is never treated as a C implementation defect.

Exhausting the last recorded FrameDone is a normal terminal condition. The DuckStation adapter converts `missing_frame_input` to `PROCESS_EXIT` only after it verifies that every recorded frame was consumed; an early missing input remains a fault. MATCH requires the native process to reach the same event sequence after the final matched boundary.

## Diagnostic refinement

`tools/lockstep_packet.py` turns the first scheduler divergence into one `xport-lockstep-attention-v1` packet. A fresh replay runs in prefix mode through VBlank `N-1` for a divergence in frame `N`, enters a new detailed epoch, and seeks the saved semantic boundary inside that frame. It does not repeat the original global PRE/POST event count. A memory interval installs data watchpoints for the bounded first difference on both processes. A control interval records the original branch slice, full MIPS registers for its operands, and the current native source location.

DuckStation watchpoints cover the physical DRAM or scratchpad address and its CPU aliases. Native CDB resolves the exported mapped-memory pointer and installs a one-byte hardware write watchpoint without copying RAM through Python. Boundary stops inside the interval remain visible; a replay backend continues them until it observes a writer or reaches the divergent boundary.

Control refinement also captures all original GTE control registers and the native GTE snapshot at the divergent boundary. The native runtime exports the read-only `xport_lockstep_gte_state` pointer only in `LOCKSTEP_DEBUG`, so CDB can inspect POST boundaries after the translated function has returned. Ordinary Debug, Release and Web builds contain neither this pointer nor lockstep mappings.

The refinement contract records whether the complete interval was observed. A first writer is always evidence, but it becomes a proven `missing_store`, `extra_store`, or `wrong_pointer` classification only when interval coverage and the required address evidence are complete. Control packets distinguish `wrong_branch`, proven `wrong_target`, and a registry-backed `bad_stack_argument`. Incomplete evidence retains a broad divergence class.

Every packet includes the last matching boundary, both current events, invocation paths maintained by the scheduler, exact call and delay-slot addresses and words, targets, arguments and returns, complete required MIPS/C context, available pseudocode with completeness metadata, reviewed stack exclusions, source and binary identities, and an exact reproduce command. The packet has a 1 MiB budget and drops optional context before required audit evidence. It never contains a full RAM region or trace.

## Repair supervisor

`tools/lockstep_supervisor.py` owns the durable validate, launch, attach, replay, diagnose, repair, rebuild and replay loop. A matched VBlank checkpoint supports same-process diagnostic replay and, while the supervisor stays alive, a new native EXE after repair. The latter keeps the stopped DuckStation process and its run identity, reopens its shared mappings only with an explicit portable-load request, and restores the last matched frame before running the new native process. If terminal writer evidence still needs a bounded watchpoint interval, supervisor first restores the held DuckStation checkpoint and launches only a new native process from the retained native checkpoint. A complete interval preserves DuckStation for the repair attempt; an incomplete or failed interval falls back to fresh diagnostic replay. A supervisor restart restores a verified durable pair; a missing, changed or rejected durable pair falls back to a fresh replay. The state receipt records launches and their reasons, actual Debug build invocations and reuses, checkpoint captures and reuse, attention packets, phase durations, accepted repairs, transition history, and a permanently zero Python-memory byte counter. Historical `model_calls` counted attention requests, not API calls; actual model usage remains unknown until a model executor reports it.

Unchanged game/shared source, project build inputs, exact MSBuild command, normalized environment and MSBuild executable reuse the verified Debug x86 EXE/PDB, including after a supervisor restart. The project run directory holds one atomic `debug-build.cache.json` receipt with the build-input key and exact EXE/PDB paths and SHA-256 hashes; missing, malformed, changed or overwritten outputs force MSBuild. Diagnostic-only Python, analysis database and DuckStation patch changes do not affect this native cache key. The first build after a change uses incremental MSBuild `Build`; a changed or externally overwritten EXE/PDB cannot be reused. A matching POST_CALL memory difference can issue an observed function-audit packet from the existing boundary evidence without another replay. Other differences retain the data-watchpoint refinement path. New packets also bind `shared_source_identity` to the configured toolset's `src` C/H snapshot. The supervisor records this aggregate identity as build metadata and a cache input. Changes to that aggregate hash do not block Debug/Release builds, packet creation, repair requests or the attention wait loop. EXE/PDB validation, complete function audits and atomic proposal source checks remain mandatory. A supervisor-applied shared repair binds both identities in its audit receipt and rolls back both trees on failure. Existing packets without this field retain their prior contract. The packet's `case_key` identifies the logical call and difference location across source revisions; `failure_signature` binds both game and shared source identities for new packets. Related attempts in the same function are linked in the packet when space permits.

After an audited C repair, the supervisor rebuilds only the derived source index with `source_index.py --rebuild --no-format`, then checks that the source identity still equals the audited identity. It never formats C during a converge attempt or at attention. Global formatting is deferred until the entire record has reached MATCH; formatting changes source identity, so any subsequent validation must use the formatted identity.

At converge startup, the toolset checks the indexed source hashes, ledger hash and parser version before launching either participant. A stale index is rebuilt once with `--no-format`; an unchanged index is not rewritten. Startup fails if that rebuild changes any C/H source or leaves the index stale. The result of a required rebuild is saved as `source-index-startup.log` in the converge run directory.

Do not treat a matching PRE_CALL memory difference as a callee defect: the callee has not executed, and the last writer can be a callback or device outside the apparent callsite owner. Require observed writer evidence for PRE_CALL before skipping its separate refinement replay. A memory-observer ring is incomplete while translated code or PsyQ wrappers can write through raw guest pointers; incomplete journal evidence must not replace the data-watchpoint fallback.

For a fresh diagnostic replay with a known differing byte, the supervisor passes `XPORT_LOCKSTEP_WATCH_REGION`, `XPORT_LOCKSTEP_WATCH_OFFSET` and `XPORT_LOCKSTEP_WATCH_LENGTH` to the native process. The shared frame runtime in `xport_trace.c` attaches a 128-event process-local observer ring after `xport_memory_init`, limited to that DRAM or scratchpad range, and clears it after each FrameDone. For checkpoint replay in a process launched before the byte is known, CDB writes a bounded request at the stopped `MODE_TRANSITION`; the native runtime attaches the ring immediately after that break returns and before the next game instruction. CDB reads at most 16 most recent events while the target is stopped, including source file, function and line when the diagnostic access wrapper supplied them. The result reports retained count, overwritten count and truncation; a missing ring or read failure is explicit. The separate refinement path includes this native ring in `pointer_evidence`; the primary detailed replay retains it in its result when a watch target was armed. Neither path treats ring absence as proof of a missing store, and both retain hardware watchpoints for evidence outside observer coverage.

For a PRE_CALL memory packet with an original writer PC, resolve the function containing that instruction from the immutable image-qualified listing and make it the audit owner. If that function is classified SKIP, use its link register to identify the nearest non-SKIP caller and include the complete library-writer listing plus available pseudocode as dependency evidence. Keep the boundary callee and exact callsite in the packet, but never present the unentered callee as the writer. Fail closed if a reported original writer cannot be resolved to an immutable function. A reviewed SKIP library writer is also a required MIPS-audit row: its complete listing and available pseudocode appear once in the model context, and all machine checks must map to the owning game C function or reachable helpers when the library effects are inlined there. Missing or partial pseudocode is recorded and does not reject the packet. An unspent saved packet upgrades to this requirement without a replay; old packets and receipts remain immutable.

For a POST_CALL memory packet with a completed writer probe, use the same original-writer resolution. The containing writer function becomes the audit owner while the original boundary, invocation path and callsite remain in the packet. An unresolved reported writer fails closed. This prevents a wrapper POST mismatch from sending a model the broad wrapper instead of the helper that actually wrote the differing byte.

`lockstep_refine.py` also emits `attention-refined.json` beside `refinement.json`. It rebuilds the attention packet from the observed writer evidence, verifies that the stable case key still matches the source packet and leaves the original packet immutable. The refined packet is ready for local audit or a single bounded repair request; no second emulator replay is needed to select its owner.

If a PREFIX_GUARD VBlank difference supplies a byte address, the next detailed replay arms byte-targeted original and native data watchpoints only after `MODE_TRANSITION`. The original watch range also covers the three preceding start addresses so an unaligned target byte inside a 32-bit MIPS store is observed. Each watchpoint records the first writer in one matched-boundary interval and is rearmed at the next boundary. If detailed replay finds an earlier semantic difference at another byte address, the supervisor restores the same paired checkpoint once more and replays that frame with a watchpoint for the new address. It accepts this evidence only if the same frame, event, invocation and byte difference recur. This needs no new processes; an unavailable checkpoint or changed result falls back to the first diagnostic result. Both observed writers enter the packet as observations without claiming complete provenance. The CDB watchpoint is one-shot (`ba /1`), and DuckStation's three CPU aliases are removed after its first stop.

Prearmed first-writer evidence identifies a writer only when its final `after` bytes on both sides cover the entire differing range and equal the terminal original/native comparison. A complete interval selects the last original write that materially changes a differing byte to its terminal value; earlier or no-op stores cannot determine the audit owner. If no recorded store produces a terminal differing byte, packet construction fails closed instead of assigning an arbitrary writer. When the supervisor holds a paired checkpoint but lacks sufficient writer evidence, it emits a bounded boundary-owner packet with `interval_complete: false` and waits for targeted causal evidence or a repair proposal. It does not spend or invalidate the live checkpoint on mandatory refinement. With no checkpoint, the existing bounded refinement fallback remains available. The `state.json` top-level `live_checkpoint` reports process-local availability; an attempt's `checkpoint_pair_available` is historical capture evidence and does not mean that pair is still live.

Run `python -B tools/lockstep_metrics.py PROJECT/status/lockstep-converge/NAME/state.json` from the xport repository to inspect comparable counts and phase times, including checkpoint captures, their measured DuckStation save-call time and copied bytes, diagnostic reuses and checkpoint writer reuses. Historical attempts without capture timing report that measurement as unknown. The command reports historical `model_calls` as attention packets. New runs record a known zero when no model executor was invoked; older states or an executor result without invocation accounting remain null. Token totals remain null when any invoked model lacks usage data.

Each new attention attempt records the exact saved packet byte count and, when complete audit evidence permits construction, both the compact evidence byte count and the full candidate prompt byte count. Summary `candidate_model_prompt_bytes` is a cumulative historical measurement, not the size of the current request. When the state is `ATTENTION_REQUIRED`, `lockstep_metrics.py` also rebuilds the saved packet's current prompt and reports `current_packet_bytes`, `current_model_prompt_bytes` and `current_model_prompt_status`; it accepts only a packet in the state file's own run directory, and unavailable or stale context is reported without inventing a size. These are payload sizes for cost planning, not token counts or claims that a model was called. The model input excludes runtime EXE, patch and manifest hashes, failure signatures, receipt metadata and redundant debugger event fields. It retains the complete MIPS listing, available IDA pseudocode with completeness metadata, current translated C, required machine-check IDs and bounded causal writer evidence. An ordinary packet requires full MIPS audit of its proven owner function. Missing or partial pseudocode never rejects the packet. Static two-level callees are not automatically made required audit functions: the graph includes unmapped library calls and functions not shown to contribute to this divergence. A causal packet may explicitly require related mapped helpers when evidence proves their role. From same-translation-unit C helpers reached within two calls, the prompt selects only helpers explicitly named by causal evidence. The nearest preceding call is insufficient: a write after its return belongs to the caller. It fits selected bodies within the 64-KiB limit and names omissions. A selected guest-address C helper must also have its original MIPS audit in the required function cluster; otherwise prompt construction fails before a model call. Included helper C is context, not a claim that its original MIPS was supplied. The model must abstain and name any missing helper body or original listing needed to prove the repair. An incomplete owner body or oversized owner-only prompt fails before a model request.

When a classified PsyQ writer has a relevant C reference, place `causal-request.json` in the waiting run with `{"kind":"library_reference","alias":"MulMatrix2","expand_callees":true,"sources":[{"path":"ABSOLUTE.c","sha256":"64-hex","symbols":["MulMatrix2"]}]}`. Up to four files may supply named function or macro definitions and optional `line_ranges` of at most 20 lines each, including current shared wrapper declarations. The supervisor verifies each whole-file SHA-256 and caps total reference evidence at 7 KiB. With `expand_callees: true`, it recursively adds directly called functions or macros defined in those files, subject to eight symbols per file and the same byte budget; without it, an omitted available callee rejects the request. It creates a new packet under the same defect case without emulator replay. The packet's evidence signature binds the selected reference bytes, so a corrected reference can receive one fresh model request while an identical reference cannot silently trigger another. For a configured executor, the waiting supervisor requests that repair immediately after adopting the new reference; it does not require another restart or emulator replay. Reference C is explanatory evidence, never proof of the game binary; the model must check it against original MIPS. A missing helper audit or over-budget prompt rejects the request without invoking the model.

A waiting run created by the earlier static-callee rule is migrated once, without changing its original packet: `attention-NNNN-scope.json` keeps the defect `case_key`, binds only the complete owner function, lists omitted original callee addresses and changes the evidence signature. Migration is permitted only when no model was invoked for that attempt and the source identity is unchanged. It does not assert that omitted callees are correct or authorize a partial MIPS audit of the owner.

After a bounded external writer refinement, atomically submit `{"kind":"writer_refinement","run_name":"REFINEMENT_RUN"}` as `causal-request.json` in the waiting converge directory. The supervisor reads that run's `refinement.json`, verifies complete interval coverage, matching source identity, terminal comparison and defect `case_key`, and checks the rebuilt model context before adopting a new immutable attention packet. Repeating a request never overwrites a different packet; it adds a numbered suffix. The evidence signature includes stable original writer PCs, bytes, interval coverage and native byte changes, but excludes volatile native host PCs. Thus refinement changes evidence identity while `case_key` continues to identify the same defect. When the final original writer is a library routine, the model context includes its complete original MIPS and available pseudocode as supporting evidence; the caller remains the required full-audit function.

When a downstream value differs but a candidate upstream writer receives matching inputs, atomically submit a `paired_entry` causal request with `diagnostic_file`, `sha256`, `writer_file`, `writer_sha256`, `image`, `owner_function`, `native_symbol` and `input_addresses`. Supply one address only for a native entry captured with `second_storage: "none"`; otherwise supply exactly two addresses. Both named JSON files must be immutable, complete instruction probes from the divergent frame's preceding VBlank. The first probe must align the original breakpoint with the native function entry and show identical sampled guest memory at every input address. The second must contain an original data-watchpoint hit within the proposed function. The supervisor verifies the hashes and boundaries, then issues a new packet requiring the complete MIPS/C audit and explicit pseudocode-completeness metadata for that function under the same defect case. An input difference rejects the request and requires further backtracking.

When the first detailed boundary already differs but a checkpoint replay captures a full-width original watchpoint sequence within one function that first writes the native terminal bytes and then the original terminal bytes, submit `{"kind":"writer_sequence","diagnostic_file":"NAME.json","sha256":"64-hex","image":"MAIN.EXE","owner_function":"0x80000000"}` as `causal-request.json`. The supervisor requires the probe's `checkpoint_pair_resumed` to equal the preceding frame, verifies the sampled address and bytes against the waiting comparison, and retargets the complete-function audit without another converge replay. A partial-width or nonterminal sequence cannot claim the owner.

The adopted packet binds the external refinement report hash, measured duration and observed writer counts. The supervisor records each named report once; a repeated request with identical bytes reuses its packet and does not add process launches or seconds again. A changed report under the same name is rejected. `lockstep_metrics.py` reports external refinement pairs/seconds separately and adds each pair to inclusive DuckStation/native launch totals. An unregistered wait continuation fails capture explicitly; add its complete continuation before enabling it.

Checkpoint reuse is opt-in through `lockstep.same_revision_checkpoint: true`. At each matched PREFIX_GUARD VBlank, supervisor captures DuckStation and the native process captures its project-defined continuation state plus shared DRAM/scratchpad for immediate same-process replay. On divergence at frame `N`, that replay exports one replaceable native cold-start file. After a source rebuild, supervisor keeps the stopped DuckStation checkpoint, launches the new EXE from that file and resumes the full-record PREFIX_GUARD scan at `retained_frame + 1`. Before native launch, the loader checks the portable header's record ID and `next_frame == retained_frame + 1`. The loader file and the resumed process export file must be different. If the suffix produces no new matched paired capture, the retained frame continues to reference the unchanged loader file. If a later suffix advances the rolling checkpoint, supervisor switches both the frame and file together. Full-record validation remains required after a checkpoint suffix match.

Protocol-4-or-later repaired-process resume loads the retained native file in the rebuilt native process and restores the retained DuckStation checkpoint in the surviving emulator. Both resume PREFIX_GUARD toward the same full-record target, avoiding detailed calls in the matched suffix; a new matched VBlank replaces the one logical rolling checkpoint through the alternate native export file. A difference in frame `N` may enter DETAILED only from the paired checkpoint for `N-1`. The native game must capture its in-process checkpoint only in PREFIX_GUARD, matching DuckStation's capture policy; otherwise a later detailed frame overwrites one half of the retained pair. Reject a missing, stale or non-reproducing diagnostic checkpoint. Never replace it with an anchor replay or a detailed replay from the initial state.

`xport_lockstep_vblank_break` and `xport_lockstep_transition_break` are distinct exported symbols, so CDB needs no per-call breakpoints during the prefix. Every event carries its mode and epoch; mixed mode or epoch pairs fail closed.

The supervisor owns the progress window in its process and updates it through an in-process queue. The ordinary 512-by-116-pixel window is placed near the upper-right corner, is not topmost, and contains two 480-pixel bars with `frame/count` labels for the furthest confirmed VBlank match and the current attempt. A status line names the frame under diagnosis or awaiting repair even when the current-attempt bar is reset to zero. A full-record scan target and a checkpoint suffix are not evidence of a confirmed full-record match. Completed attempts retain their highest confirmed VBlank count for restart recovery; older attempts recover conservatively from a matched VBlank or a verified paired checkpoint. No progress file or helper process is used.

The loop calls only `build_debug`; a Release build cannot start during repair attempts. `build_debug` uses `paths.native_debug_executable`, which must name `bin/[SHORT]_debug.exe`. After complete MATCH, the project binding must synchronously rebuild Release x86 from `finalize_match` and must not return until `paths.native_executable`, `bin/[SHORT].exe`, exists and its hash is recorded. A Release build failure fails convergence. `trace_workflow converge NAME` always selects this supervisor. A project without the lockstep schema fails with `LOCKSTEP_PROJECT_NOT_MIGRATED`; a historical trace fails with `record_contract_unsupported`.


Each project defines a fixed reviewed guest-stack exclusion from its boot stack, heap contract and observed minimum stack pointer. A project may lower that fixed boundary only after a complete original watchpoint proves a deeper firmware or SDK frame; an arbitrary current runtime `sp` is insufficient. Ordering-table data remains covered by DRAM equality. VRAM and SPU RAM remain trusted wrapper boundaries for this first migration.
