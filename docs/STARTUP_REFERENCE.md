# Startup technical contracts

Read only the section selected by a supervisor attention/failure. Host dependencies: [HOST_TOOLS.md](HOST_TOOLS.md). Shared context/indexing: [CONTEXT.md](CONTEXT.md). Build policy: [BUILD_POLICY.md](BUILD_POLICY.md).


## Disc extraction

Use extract_data through startup's extraction gate. Preserve original images and names, strip ISO version suffixes, validate all volumes/tracks/paths and reject traversal or truncated inputs. Retry may reuse identical files but must not overwrite different bytes. Scan every file sector before selecting logical extraction: any Mode2 Form2 (0x20) or realtime (0x40) submode requires retaining every full physical sector of that file, including Form1 sectors/subheaders. EOF/EOR differences alone do not select raw format. Only files with no raw trigger use 2048-byte payloads trimmed to ISO length. Raw overlay discovery/profile acceptance belongs to decomp, not filename guesses during startup.

## STR video preparation

Use X convert_video and the bundled executable in [HOST_TOOLS.md](HOST_TOOLS.md); no new FFmpeg download. Scan bin/DATA STR files case-insensitively, or exactly video.sources when configured. Reject duplicate, missing or escaping selections. The converter accepts validated standard STR frame chunks in complete 2352-byte Mode2 sectors (optional RIFF/CDXA wrapper) and extracted video-only 2048-byte sectors. Preserve source sector/frame identities, require complete ordered frame chunks, consistent dimensions/video channel and supported audio layout. Temporarily wrap extracted user sectors only for FFmpeg; never modify originals or infer missing audio. Unsupported containers, mixed streams and isolated MDEC blocks remain explicit project work. Do not search packed containers merely by size/name.

The converter writes prepared MP4/index registrations and unsupported-format reasons to startup-video evidence. [FMV.md](FMV.md) owns Web payload policy and media API scope. A prepared MP4 or low-level decoder check does not prove in-game frame/audio/pause/skip behavior.

### Indexed TIM converter contract

`python -B [XPORT_ROOT]/tools/tim_to_ico.py INPUT.tim OUTPUT.ico [--offset 0xOFFSET] [--palette INDEX] [--report REPORT.json]` converts an indexed 4-bit or 8-bit TIM into one unscaled 8-bit Windows DIB icon with 256 palette entries and an AND transparency mask. Require dimensions from 1 through 256, valid bounded TIM blocks and a complete selected CLUT. Palette indices are zero-based; embedded TIM offsets accept explicit hexadecimal values. Existing outputs require `--force`; input and output paths must differ.

The converter expands PSX BGR555 components by bit replication, reads 4-bit pixels low nibble first and makes exactly color word `0x0000` transparent, regardless of its palette index. Nonzero words, including STP colors, remain opaque; the indexed ICO does not reproduce PSX blending. It rejects true-color TIMs, missing palettes, malformed lengths, truncation and oversized images. The optional report records source/output hashes, dimensions, palette selection and transparent-pixel count. Extract packed or VRAM-atlas resources with a project-owned evidence-backed adapter before conversion; retain the original CLUT/pixels and extraction provenance. Conversion alone does not change the Windows resource binding.

Run `python -B -m unittest tools.tests.test_tim_to_ico` from `[XPORT_ROOT]` to verify 4-bit/8-bit layouts, palette selection, scanline padding, transparency and malformed-input rejection.

### Red Book conversion

Run only `X convert_music`. It reads the single configured CUE, starts each `AUDIO` track at `INDEX 01`, and writes decimal track names under the configured music output using the pinned shared ADPCM-XQ encoder. Missing or ambiguous CUE data, non-sector-aligned audio and unexpected output format fail closed. Use input/output overrides only for a recorded project exception.

## 2. Export original code; establish SQL

1. Identify known executable revisions for startup. Do not require discovery or classification of unidentified overlays; decompilation adds their reviewed profiles later. For each configured image, record SHA-256, file segments/offsets, load addresses, entry, GP and overlay residency. Identity is `(image revision, virtual address)`, never name/address alone.
2. Create `tools/ida/[IMAGE].json`: `image`, `entry`, `gp`, `segments` (`start/end/name/class`), `loads` (`path/base/offset`), `seeds`, `code_ranges`, optional `external_symbols`. Use actual image facts. IDA auto names are not debug symbols.
3. Supply the licensed IDA path and reviewed image profiles through the current startup attention packet. The supervisor plans under `startup-ida-plan`, executes under `startup-ida-v1`, canonicalizes, and accepts the result as one guarded gate.

GP validation is a mandatory blocking gate between steps 2 and 3. Treat the PS-X EXE header GP as a hint. Derive the runtime value from the unique adjacent MIPS32 `lui $gp` plus `addiu $gp,$gp` initializer in the exact loaded payload, or retain another explicitly reviewed machine-level derivation. Store the nonzero value in `gp` and its exact derivation in `gp_evidence`. Before creating an IDA command, the supervisor rereads the configured executable bytes and requires one unambiguous initializer whose value equals both fields. For a PSLZ executable whose GP is supplied by BIOS Exec, use `gp_evidence.source: "bios_exec_pslz"` with `original_path`, `original_sha256`, `bios_path`, `bios_sha256` and `bios_exec_offset`. The validator rereads both inputs, requires the exact BIOS MIPS sequence loading entry/GP from EXEC offsets 0/4 before `jalr`, verifies the configured load against the separately decoded payload, executes the complete original PSLZ unpacker with branch and load delays, and requires byte-identical output plus unchanged header GP at the metadata-derived entry. Cache-flush and critical-section BIOS calls are modeled as RAM-preserving; any other instruction or transfer is rejected. Hash changes, differing payload/load/entry or GP changes fail closed. Header values alone do not satisfy this route. Run `python -B [XPORT_ROOT]/tools/psx_pslz.py --project PROJECT_ROOT` and `python -B [XPORT_ROOT]/tools/psx_pslz_mips.py --project PROJECT_ROOT`; their project-owned outputs are `status/pslz-review/*.payload.bin`, `report.json` and `mips-verification.json`. Original packed inputs remain immutable; IDA profiles load only verified decoded payloads with offset 0. Zero GP, multiple distinct candidates, missing evidence, stale offsets, or a header/runtime mismatch blocks startup for review. Do not launch IDA, export a listing, run Hex-Rays or accept an existing IDB until this gate passes.

Raw overlays that inherit GP from a reviewed executable use `gp_evidence.source: "inherited_runtime_initializer"`. Configure exactly one offset-zero raw OVL load, a nonzero GP equal to the accepted direct parent initializer, observed aligned entry seeds inside PS1 RAM, and reviewed code ranges; do not declare the entire overlay as code when it includes data. Evidence binds `parent_config`, `parent_original_path`, `parent_acceptance_receipt`, `overlay_original_path`, `runtime_observation`, `runtime_provenance` and `bios_path`, each with its exact `_sha256` companion. Paths remain project-owned; parent configs are under `tools/ida`, acceptance receipts under `status/ida/accepted`, and runtime observations/provenance under `status`.

## Windows runtime template

Keep `src/platform/win/xport.vcxproj` custom runtime configuration when generating projects. Debug on both architectures uses the normal CRT; Release on both architectures includes shared `platform/win/xcrt.c` by default; each architecture also assembles its matching `platform/win/xcrt_x86.asm` or `platform/win/xcrt_x64.asm` through the canonical MASM imports. `/p:UseXcrt=false` restores the standard CRT in the same Release configuration. Runtime/file/format limits and Release linker settings: [LIBRARY.md](LIBRARY_SYSTEM.md#windows-release-crt). Do not introduce local CRT replacements or new runtime configurations.

### Select supplemental original inputs for the analysis index

`build_database` may select accepted supplemental original analysis through `analysis.index_exports`. Each entry supplies `image`, `receipt`, `receipt_sha256`, `canonical_functions_sha256` and `original_sha256`. The image must already have a canonical export; duplicate selections fail. The receipt must have role `supplemental_original_analysis` and a destination under `status/ida/snapshots`. Selection does not overwrite canonical exports, change function identities, promote semantic completeness or transfer runtime acceptance. Existing original workflow consumers continue to use `paths.ida_exports`; this option selects database inputs only.

Before formatting sources or opening the output database, `tools/ida_index.py` checks the receipt hash, complete accepted artifact manifest, current profile hash, GP/image, unique functions, retained canonical body hashes/chunks/sizes/ends and every instruction against the hash-bound original raw load. Only single-load images are supported. Missing/stale receipts, original/profile/artifact changes, dropped/changed canonical bodies, duplicate functions and instruction/chunk mismatches reject selection. Correct a failed selection by restoring its bound immutable inputs or accepting a fresh labelled original-analysis snapshot; never edit an acceptance receipt to match changed artifacts.

Final verification must exercise configured and unconfigured selection, stale/missing/foreign receipts, changed profiles/originals/artifacts, duplicate identities, canonical body deletion or mutation and instruction/chunk mismatches. Supplemental discovered entries remain unreviewed until their separate complete-body evidence establishes otherwise.

### Hash-bound archive record overlays

Additional archive overlays may use `gp_evidence.source: inherited_archive_loader` through `tools/overlay_gp_archive.py`. Bind parent config/original/accepted receipt, overlay original, original archive, static discovery and complete loader review with SHA-256 companions. The review binds complete original loader bodies, explicit archive record selector/destination/completion/dispatch semantics, the entire raw parent GP-destination inventory, a matching original context-save/restore slot, and executable/noncode partition. ### Exact-body decompilation work units

Set `analysis.function_queue: "unique_exact_bodies"` before `X build_database` to group the ordinary queue by exact original instruction hash, complete original chunk-byte hash (including embedded data), GP and relative chunk layout. The importer rereads and hashes each original load, retains every image-qualified function/instruction/call edge, and writes `status/decompilation-units.json` plus SQL work-unit membership. It uses an indexed reuse view instead of materializing every pair in large duplicate groups. Without this setting, retain the existing exhaustive similarity workflow.

`X project_context queue` returns one task per exact body and separate `image_qualified_counts`; each task retains bounded occurrence references and the full membership evidence path. Do not normalize immediates/NOPs for exclusion. SDK identity and complete source acceptance remain occurrence-specific: an unreviewed alias stays uncovered; an existing complete member becomes a reuse/rebinding review, never an automatic completion transfer. The common body is a translation template; per-image caller ABI, data, residency and direct/indirect dispatch still require review. These groups do not establish context-independent semantic equivalence.

For explicitly user-selected exclusions, set `analysis.decompilation_exclusions` to a project-relative JSON file with `schema: 1` and `groups`. Each group has `image`, integer `representative`, and `copies` containing integer `address` and indexed original `sha256`; include the representative exactly once. The queue excludes the other addresses, retains the representative and reports `excluded_occurrences`. Missing identities, changed hashes, duplicate identities and invalid representatives fail the queue. This is a work selection only: it does not certify identical instructions or behavior and does not transfer completed-body acceptance to excluded addresses.

Validate queue changes with `PYTHONPATH=[XPORT_ROOT]/tools python -B -m unittest tools.tests.test_function_work_units tools.tests.test_project_context`. Archive-loader validation also requires the consuming project's positive original-MIPS fixtures and negative GP/hash/partition/record/fixture checks; `tools.tests.test_ghidra_supplemental` exercises independent export rejection.
`analysis.function_queue_ghidra_evidence` may bind `{ "path": "PROJECT_RELATIVE_SELECTION.json", "sha256": "..." }` using schema `xport-work-unit-ghidra-evidence-v1`.
