# Shared PSX host runtime

`FIELD_RATE` remains the nominal SDK rate. The default physical VBlank ratio follows DuckStation: FIELD_RATE=50 selects 53203425/(3406*314) Hz (PAL); FIELD_RATE=60 selects 53693175/(3413*263) Hz (NTSC). Other rates retain FIELD_RATE/1. Explicit FIELD_RATE_NUMERATOR / FIELD_RATE_DENOMINATOR overrides remain supported; define both for a custom profile. Native VBlank polling, field pacing, GPU skip deadlines and Windows-null/Web PCM counts share this ratio. Consumers must use the physical ratio for logic frame indices and render interpolation phases; nominal SDK tick constants remain unchanged.

Set `XPORT_AUDIO_VBLANK_QUEUE=1` for native Windows to render PCM on the game thread before each VBlank IRQ and queue it for waveOut. The output worker consumes complete PCM blocks and never advances SPU voices. In this mode device buffers affect output latency, not note quantization or envelope reads. The two-second FIFO preserves order; capacity overflow aborts rather than dropping samples. Defaults retain the legacy worker-rendered path; other consumers require no migration. Verify `python -B -m unittest tests.test_audio_field_clock -v` from tools. P2 paired 40-second, 24-voice evidence: `Pandemonium2-xport/status/audio/review-audio-clock-20261017.json`.

Set `XPORT_SPU_VOICE_CAPTURE` to a writable filename before native audio starts to capture raw 44100 Hz signed little-endian 16-bit PCM. Each frame contains 24 stereo voices in voice-index order, after ADSR/voice volume and before master volume/reverb. An unset variable leaves capture disabled. Opening or writing failure aborts; normal exit flushes the final block. Forced termination can omit the last buffered 256 frames. `spu_voice_capture_sample_count` counts captured frames for debugger start markers. No game bindings or ABI changes are required. Paired Goon City evidence: `Pandemonium2-xport/status/audio/goon-city-channels/comparison.json`.

These writes update the same mixer/reverb state as native SDK calls. Manual transfer batches are synchronous, limited to32 halfwords; FIFO reads and other transfer controls remain unsupported. Existing ABI and consumer registrations are unchanged. Verify with `gpu_observer_test --fixture spu_control` and `--fixture spu_pending_key`. Unsupported conversions or a second decimal argument abort explicitly. This is a limited compatibility formatter for reviewed callers, not full variadic sprintf. `_96_remove()` preserves BIOS A0:72: enter the critical section, close the five CD event handles in DRAM, then dequeue both BIOS CD interrupt nodes at priority zero. ## Native game saves

- Declare `sint32 xport_save(const void *data, sint32 size)` and `sint32 xport_load(void *data, sint32 capacity)` in `xport.h`; implementations belong to the Windows/web backend
- `save`: return `1` after storage completes, `-1` on failure. Require a non-null buffer and positive size
- `load`: return bytes copied, `0` when no save is found, `-1` on failure or invalid arguments. Require a non-null buffer and positive capacity. Reject empty or oversized saves before copying; never truncate
- Windows: `%APPDATA%\xport\SHORT_NAME.sav`. Define `SHORT_NAME="PROJECT_SHORT_NAME"` on the shared Windows `main.c` compile item; startup renders it from the project template. Debug and Release share the same save, without `_debug`. Save through a sibling `.tmp` and replace the destination only after a complete write; unavailable file attributes are treated as no save
- Web: IndexedDB database `XPORT_SAVES`, object store `saves`, key `SHORT_NAME` from the consuming Makefile. Keep saves separate from the replaceable asset cache. Asyncify waits for transaction completion; return failure for unavailable/blocked storage. Saves remain scoped to the browser origin and profile
- Game code owns payload layout, version/checksum validation, packing/unpacking and any slots inside the payload. The backend stores raw bytes without a memory-card header or serialization wrapper
- Call from the game/main thread. Keep load destinations valid until return. Do not invoke from interrupts, audio callbacks or overlapping Asyncify calls
- Project migration replaces card management and asynchronous completion handling with these synchronous calls. Do not save native pointers or substitute these calls blindly for every individual memory-card sector transfer
- Verification: from `tools`, run `python -B -m unittest tests.test_game_saves -v`. Requires MSVC, bundled Emscripten, Node with `playwright` available through `NODE_PATH`, and Chrome (`CHROME_EXE` overrides its path). Tests compile the actual backend functions; Windows files stay inside `_build`, web tests use real WASM/IndexedDB and reload the page. No game runs or user saves are modified

Native `SpuSetKey(SPU_OFF, mask)` cancels unrendered SDK key-on bits for the same voices after queuing key-off. This prevents a later SDK stop from leaving a voice in Sustain when both operations reach one native mixer buffer. API signatures and raw MMIO key-latch handling are unchanged. Current Gran Turismo pause PCM evidence and consumer scope: `GranTurismo-xport/status/function-coverage/first2/pause-quit-progress.json`; other consuming games are not runtime-validated by that scenario. Native `SpuGetKeyStatus` reports a queued SDK key-on as `SPU_ON` until the mixer evaluates its first envelope; this prevents an immediate status poll from stopping Rapid Racer short effects before they start. Explicit `SPU_OFF` still cancels the queued start, and `LOCKSTEP_DEBUG` keeps the original four-state status. Full Rapid Racer MIPS branches: `RapidRacer-xport/orig/images/MAIN.EXE/functions/80036990.lst` and `80077620.lst`; verify both native paths with `gpu_observer_test.py --fixture spu_pending_key`

PsyQ `sint32 catan(sint32 a)` in `psx.c` evaluates the original COR_06 twelve-step fixed-point slope angle, including the final zero increments and unsigned low-word arithmetic with signed shifts. It owns immutable SDK constants and does not read a game DRAM table. Original identity: Apocalypse `SLUS_003.73` `0x8008702C`, reviewed Ghidra PsyQ `LIBGTE.LIB` `COR_06.OBJ` matches 410-470; prototype: `D:/psyq/include/LIBGTE.H:445`. Project evidence: `Apocalypse-xport/status/refactoring/stage-2/native-angle-steps-migration.json`; run `python -B tools/verify_native_trig_math.py` in that project for the complete saved/native arithmetic check and bounded raw MIPS samples. Those checks do not certify other consumers or all 32-bit inputs.

Projects compile this canonical PSX/PsyQ runtime directly. Game code calls its PsyQ-compatible API; shared subsystems call required game-owned symbols declared in `xport.h`. No callback registration or fallback is permitted; missing bindings fail at link time.

`XPORT_DISABLE_FUNCTION_MARKERS` makes `FUNCTION_MARKER(address, image)` a compile-time no-op without evaluating arguments. It is opt-in per consuming build configuration; other projects retain their existing marker behavior. Native projects that no longer use lockstep can keep simple provenance markers in source, enable `XPORT_ENABLE_AUDIT` in Debug and disable function markers in Release. Do not disable markers in a lockstep/converge configuration.

At the native host-file boundary, `xport_cd_file_size_native(src, root, size)` and `xport_cd_file_read_native(src, root, dst, cap, size)` accept ordinary string and buffer pointers. They strip leading separators and the CD version suffix, convert backslashes, enforce the 260-byte host path capacity and reject colons in the CD path and `..` sequences in the resulting path, matching the existing guest path resolver. The caller owns the strings and destination through the synchronous call. Native reads use `xport_file_read` directly and do not publish guest-copy memory events. The existing guest-address file APIs retain their prior behavior for other consumers. RR migration and bounded codec/ISO checks: `RapidRacer-xport/status/audits/native-stage6/cd-native-path-native.json`.

For a consuming project that supplies `xport_gpu_guest_dispatch`, define `XPORT_GAME_GPU_GUEST_DISPATCH=1` for its complete native build. This disables only the legacy shared fail-fast definition in `psx_gpu.c`; the existing declaration, signature and callers remain unchanged. Supply the symbol in an already registered project binding module and fail fast when its GPU adapter is absent. With the macro absent or zero, existing consumers retain the shared definition and need no new source or binding. RRJ uses this mode to keep the missing-boundary body outside the optimized GPU caller translation unit without disabling C4702 or reducing GPU optimization.

## Graphics presentation

### Color and alpha fog

- `vid_fog(fog)` enables two-stage fog for subsequent custom-shader draws in the active frame. Supply `VID_FOG` with radial world distances `0 < near_dist < far_dist < horizon_dist`, normalized RGB `color`, and positive `focal[2]` matching the current projection (`clip.x = camera.x * focal[0]`, `clip.y = -camera.y * focal[1]`, `clip.w = camera.z`). `vid_fog(NULL)` disables it. Each draw snapshots the parameters
- The vertex shader reconstructs camera-space position and computes its length. It clamps logarithmic coefficients `log(max(d,near)/near)/log(far/near)` and `log(max(d,far)/far)/log(horizon/far)`, then squares each to reduce early fog density. Rasterization interpolates the coefficients; the fragment shader performs no distance, logarithm or smoothstep calculation. This approximation depends on polygon tessellation
- Custom fragment shaders call `vidFog(color)` after computing their surface color. Opaque/alpha RGB first blends into the supplied fog color; alpha then fades to zero using the second coefficient. Fully transparent fragments are discarded before depth writes. Additive/subtractive materials fade RGB toward zero using the first coefficient. Default VID shaders do not apply fog
- Fog-enabled opaque custom-shader materials use ordinary source-alpha blending; other blend modes and depth-write policies remain intact. Render horizon first and disable fog before UI. The second range reveals existing framebuffer contents, including any earlier geometry; no background texture, GPU copy or extra texture sample is used
- Rapid Racer implementation and native/WebGL pixel evidence: `RapidRacer-xport/status/audits/hd-fog/report.json`

### HD float transforms

`xport.h` defines `VEC3F` (`x/y/z`, `v[3]`) and `QUATF` (`x/y/z/w`, `v[4]`). `psx.h` defines `VECTORF` (`vx/vy/vz`) and `MATRIXF` (`float m[3][3]`, `float t[3]`). These types and the float operations in `psx.c` serve HD rendering only. Consuming projects retain their integer physics, collision, AI and simulation state; HD reads a simulation sample and must never write float transform results back to it.

Float coefficients use identity `1.0f`, translations use world units, and rotation angles use radians. Convert encoded assets and simulation inputs at the consuming game's render boundary. Build float poses from source angles, quaternions or basis vectors; converting a completed fixed-point render matrix is not a completed HD migration. Float operations accept valid finite inputs and non-null pointers, do not use the COP2 register bank, and do not emulate fixed-point rounding, wrapping or saturation.

`ApplyMatrixf` applies the 3x3 part only; `RotTransf` also adds translation. `MulMatrix0f(left, right, dst)` computes `left.m * right.m` and preserves `dst.t`; `MulMatrixf` writes the left operand and `MulMatrix2f` writes the right operand. `CompMatrixf` composes both rotation/scale and translation. `TransposeMatrixf` transposes only the 3x3 part and preserves destination translation. All these operations support destination aliasing an input. `IdentityMatrixf` resets both rotation and translation.

Axis rotations premultiply the 3x3 part and preserve translation. `RotMatrixf` builds `Rx * Ry * Rz`; `RotMatrixYXZf` builds `Ry * Rx * Rz`; both preserve destination translation. `ScaleMatrixf` scales columns, and `TransMatrixf` replaces translation. `NormalizeVectorf` returns the original length and outputs a unit vector; zero input outputs zero. `NormalizeQuatf` returns the original norm and outputs a unit quaternion; zero input outputs identity quaternion. `MulQuatf` uses Hamilton multiplication and supports in-place destinations. `QuatMatrixf` normalizes the input orientation, builds its 3x3 rotation and preserves translation.

`OuterProductf` computes a cross product and supports destination aliasing either input. `ProjectVertexf` projects an already transformed camera-space vector. `RotTransPersf` first applies the supplied matrix, then delegates to `ProjectVertexf`. Both projection entries return homogeneous clip coordinates, retain float depth in `w`, and reverse camera Y for OpenGL/WebGL presentation. Callers supply focal coefficients and `0 < near_z < far_z`. Near/far map to NDC depth -1/+1. They perform no perspective divide, viewport rounding or visibility rejection; the renderer owns clipping and viewport policy.

Run `python -B xport/tools/tests/gte_float_test.py --output PROJECT_ROOT/status/audits/vid` on a Windows MSVC host. The fixture compiles the exact current float function closure with `/Od /MDd /D_DEBUG` and enabled assertions. It checks rotation order, composition, in-place aliases, fractional vectors, normalization, scale, projection planes and quaternion poses. It does not prove game integration or a complete runtime COP2 snapshot comparison. RapidRacer migration status is in `RapidRacer-xport/status/audits/vid/float-plan.json`; build and test Release only when explicitly requested and authorized by that project's user policy.

The shared shader-only VID interface, OpenGL/WebGL build inputs, resource ownership and OG/HD transition contract are in [VID.md](VID.md).

Single-segment Gouraud GP0 `50/52` lines use native integer color interpolation with the existing clipping, draw offset and semitransparency path. The GPU observer fixture covers endpoints, midpoint, clipping, offset and blending; this does not establish hardware-exact line coverage or interpolation. Gouraud polylines are outside this implementation.

## Modules

Ordinary native and Web builds enable whole-frame raster catch-up at startup. Each blocking `VSync(0)` or `VSync(n>1)` advances an independent planned frame deadline by its requested field span; query-only VSync modes do not create a frame. The first deadline includes the initial requested field span rather than starting one span behind. Native waits count fields since the preceding completed blocking VSync; fields already delivered by event polling or query modes satisfy that wait. A skipped boundary does not consume this completed-wait counter. Provider-bound and SDK-sampled waits retain their existing paths. When the next boundary is already overdue, VSync returns without another wait and latches raster suppression until the following blocking VSync. All primitive/OT passes, DRAWENV background fills, ClearImage and menu-surface clearing retain their existing framebuffer pixels; presentation retains the last displayed image. Draw state and image upload/copy/readback still execute. Framebuffer readback can therefore observe older complete buffers; feedback-heavy games require separate acceptance. The policy does not accelerate expensive simulation/packet construction and cannot guarantee real-time play when those alone exceed the field budget.

The policy starts enabled in every ordinary build and is compiled out for `LOCKSTEP_DEBUG` coverage. Host startup needs no configuration. `gpu_frame_skipped()` reports the latched decision; `gpu_skipped_frames()` counts dropped frame boundaries. Graph reset/load rebase scheduling; monotonic-clock rollback or a gap greater than one second cancels backlog. Host policy and wall-clock deadlines are outside portable GPU snapshots. LOCKSTEP_DEBUG, transfer/link/sync observers and device trace disable suppression; they retain exact VRAM operation behavior. Validate actual raster/state/transfer behavior with `gpu_observer_test.py --configuration Debug`, VSync binding isolation with its `--fixture vsync_callback`, and Web waits with `python -B -m unittest tests.test_native_timing tests.test_web_timing tests.test_pad_ports` from `tools`. The native fixture runner defaults to Debug; selecting Release requires an explicit configuration argument

`gpu_frame_begin` and `gpu_frame_end` bracket a complete host frame across blocking VSync and every viewport/OT submission. `gpu_present` suppresses output while a scope is active; call it after the final end to display completed pixels. Scopes nest, do not suppress GPU commands or transfers, and reset on GPU reset/load. RapidRacer uses this boundary to prevent automatic VSync output from exposing an untouched skipped display page during recovery or the first half of a split-screen frame

Native Windows/Web input owns two independent digital pad ports. P1: WASD directions; I/J/K/L Triangle/Square/Cross/Circle; 1/Q/3/E L2/L1/R2/R1; Enter Start; Backspace Select. P2: arrow cluster directions; NumPad 5/1/2/3 Triangle/Square/Cross/Circle; NumPad 7/4/9/6 L2/L1/R2/R1; NumPad Enter Start; NumPad Plus Select. NumPad 0 is unmapped. Windows distinguishes NumPad Enter and Num Lock off navigation keys through the extended-key flag. Arrow keys belong only to P2. XInput/browser gamepads use the first two connected devices in enumeration order, one per port. Touch and the existing input override API affect P1 only. Invalid port indices return zero.

After `PadInitDirect`, call `PadStartCom` to enable native packet publication. Active polling publishes connected `0x41` packets for both keyboard ports and any bound SDK owner packets; it preserves active-low button byte order. `PadStopCom` suspends polling. Replay-bound pads retain recorded packets and bypass native publication. Native serial state is independent per port. Verify with `python -B -m unittest tests.test_pad_ports -v` from `tools`; actual Win/Web C closures, sparse gamepad enumeration, SDK packets, stopped polling and replay isolation are exercised. Game-specific split-screen evidence belongs to the consuming project.

It sign-extends the two indices, preserves wrapping address arithmetic and returns the wrapped separation offset. `GetODE()` returns GPUSTAT bit31 through the existing supplied GPU status source when bound. Native execution owns `GpuScanoutState` in `psx_gpu.c`: GP1 display origin, vertical range and mode configure scanout; the platform timer advances raster ticks at the PAL/NTSC nominal video clocks. Progressive mode uses display-origin plus scanline parity; interleaved mode uses the latched display field within the active range. Native `PutDispEnv` publishes these commands without guest PsyQ bindings. The scanout state, fractional tick carry and native display cache belong to the size-bound GPU snapshot; prior scalar-block sizes are rejected and loading rebases the host timer. - `platform/win/main.c`: Windows process entry, timer, exhaustive message/input polling, window, WaveOut audio, audio synchronization and file services

Each platform backend owns the native process entrypoint and calls the required game-owned `void xport_main(void)`. The backend consumes common flags directly and receives the result through `xport_set_exit_code`. A port to another operating system implements the platform service declarations from `xport.h` in its own `platform/<name>/main.c`; `psx.c` contains no operating-system calls.

`psx.c` loads a `PSX_EXE` description into shared guest RAM and provides common CD path, size and read helpers. Games own only executable addresses, paths and the call into their translated entry. `xport_trace.c` owns memory access, audit, device events and lockstep diagnostics; a game-owned `game_except.c` provides the static exception arrays used by lockstep builds; no configuration parser runs inside the game.

Translated code must include `psx.h` and use the shared debugger-visible `r_u8`, `r_u16`, `r_u32`, `r_s8`, `r_s16`, `r_s32`, `w_u8`, `w_u16`, `w_u32` and `w_masked_u32` functions for numeric guest-memory access. These functions preserve PSX aliases, unaligned little-endian access, DRAM/Scratchpad selection through the canonical `psx_addr` mapping, MMIO dispatch and trace observation. Do not add game-owned memory helpers, macros or DRAM/Scratchpad address decoders. Debug builds export stable function symbols so a debugger can break on every read or write; memory diagnostics may wrap writes with source metadata but still call the same shared symbols. The shared `w_u8_at`, `w_u16_at`, `w_u32_at` and `w_masked_u32_at` diagnostic adapters attach C source metadata and are never implemented or called explicitly by a game.

PsyQ entries are implemented directly in their owning shared module. Internal subsystem functions, types and constants use the `gpu_*`, `spu_*` and `gte_*` namespaces. Platform presentation and quit state use `xport_present` and `xport_isquit`; do not add `psx_*` forwarding aliases, parallel `PsyQ*` compatibility state or game-owned GPU trampolines.

The optional `psx_seq.c` module owns `_SsSeqPlay`, `_SsGetSeqData`, `_SsReadDeltaValue` , `_SsSetControlChange` , `_SsContNrpn2` , `_SsContNrpn1` , `_SsSetProgramChange` and `_SsNoteOn`. They implement the PsyQ LIBSND duration/countdown loop, explicit and running-status event decode, and variable-length delta values using numeric guest records. Bind the guest pointer table with `xport_libsnd_bind_sequence_table` and the 17-word event/control handler table with `xport_libsnd_bind_sequence_handlers`. Both bindings belong to `LIBSND_STATE`, are included in the existing size-bound snapshot, validated on restore and cleared on subsystem reset. Register `psx_seq.c` in each consuming native project and implement the required `xport_libsnd_sequence_call(target, argc, arguments)` service to dispatch original numeric handler targets synchronously. Only consumers of this optional module acquire that link dependency; existing SPU consumers and voice APIs are unchanged. `_SsSeqGetEof` remains an explicit fail-fast SDK boundary. Original provenance and current integration: `SyphonFilter-xport/status/native-startup/seq-data-native-review.json`. This implementation does not establish audible sequence playback or original equivalence.

Valid voices require a bound table and compare signed halfwords at offsets `24`, `20` and `14` in that order against the arithmetic `bank_program >> 8`, its low byte and the signed16 note. All matches return zero; any mismatch returns `-1`. Missing binding aborts. This additive API changes neither existing callers nor snapshots. Original complete MIPS and confirmed PsyQ identity: `SyphonFilter-xport/status/native-startup/voice-check-native-review.json`; no original equivalence is claimed

## SPU reverb work-area transfers

`SpuClearReverbWorkArea` and the `0x100` clear flag in `SpuSetReverbModeParam` use transfers of at most1024 bytes, rounded up to64-byte DMA blocks with SPU RAM wrapping. Mode4's final992-byte chunk therefore also clears32 bytes at SPU RAM offset0. Each block invokes the existing transfer wait/completion boundary outside the audio lock. Clear temporarily suppresses the completion callback and changes normalized mode1 to0, restores those fields on success and failure, and never changes the normal `SpuWrite` completion word. The attribute clear path disables reverb writes through both control bit7 and its existing enabled state, then restores them. Ordinary `SpuWrite` and callback delivery contracts are unchanged.

`spu_clear_reverb_transfer(mode, source, binding, direction)` is a synchronous scoped adapter for translated SDK state. The caller supplies a readable1024-byte source and live existing transfer fields; optional direction storage receives0. It never installs or replaces the global binding. Both clock/wait callbacks must be present together or absent together; absence selects an already-completed native upload, not a physical timing model. Completion-event delivery is mandatory for every block. An absent guest-address callback uses `xport_guest_buffer_address`; native default clears use an opaque host zero buffer. The FF adapter supplies its original guest buffer and a scoped native BIOS event with real Open/Enable/Deliver/Test/Close operations. No new persistent binding, queue or snapshot layout is introduced. Original raw/C, failure restoration, native/guest portable roundtrip and consumer checks: `FightingForce-xport/status/implementation-completion/reverb-clear-acceptance.json`. These checks do not prove physical DMA timing, original PCM or full-game convergence.

## Windows Release runtime contract

- Release uses ordinary `fseek`/`ftell`; native disc/stream files and offsets must fit signed 32-bit positions
- Windows Release omits separate resource `ferror` checks and PC-file `fflush`; reads retain their returned byte counts, and closing a stream commits buffered writes
- `--collect` is Debug-only; Release omits collection state and logging
- Debug retains resource error checks and PC-file flushing
- Release disables compiler stack probes with `/Gs2147483647`; do not provide an empty `__chkstk` implementation
- Before accepting a probe-free Release, check generated code for remaining probes and audit large or dynamic stack allocations; move page-sized buffers to heap or persistent storage when necessary

SPU rendering and XA sector decoding use private transient static workspaces under the existing audio lock. They are not serialized state. Clear render sends for each chunk; never allocate the 37632-byte XA decode workspace on an unprobed thread stack.

## Windows Release CRT

`src/platform/win/xcrt.c` is the shared custom C runtime for Windows x86/x64 Release. Architecture-specific ABI helpers live in `src/platform/win/xcrt_x86.asm` and `src/platform/win/xcrt_x64.asm`; both require the MASM build customization. The canonical Windows template and synchronized consuming Windows projects enable it by default; local project icons override the shared default through an adjacent `icon.rc`. Debug on both architectures keeps its standard CRT. Build either existing Release architecture with `/p:UseXcrt=false` to exclude xcrt and restore standard `/MT` linking; do not add separate runtime configurations.

`xcrt.c` supplies `atoi`, `strncpy` and `sprintf`. `atoi` accepts ASCII whitespace, optional sign and decimal digits with 32-bit unsigned accumulation. `strncpy` copies at most the requested count and pads the remaining bytes with zero. Debug and standard-CRT Release do not compile these definitions.

C++ consumers include shared `platform/win/xcrt.h` with `XCRT_CPP_IMPLEMENTATION` defined in exactly one C++ translation unit. The header emits definitions only under `XPORT_XCRT`; Debug, Web and `UseXcrt=false` retain their platform runtime. Scalar/array `new` use `malloc`, and scalar/array, nothrow and compiler-emitted sized `delete` use `free`. Zero-size allocations request one byte. Ordinary allocation failure aborts because XCRT has no C++ exception unwinding; nothrow allocation returns null on failure. Placement forms remain supplied by `<new>`. C++98 syntax is retained; sized deallocation is enabled for current MSVC and compilers advertising it. `_purecall` aborts in `xcrt.c`. This does not supply STL, `atexit`, dynamic global constructors/destructors, `new_handler`, exception objects or aligned allocation. Keep required Release registries in zero-initialized POD storage and avoid relying on CRT startup initialization.

Enabled: `/NODEFAULTLIB`, `/ENTRY:WinMainCRTStartup`, `/Zl`, kernel32/user32/gdi32/winmm/shlwapi imports only. Both Release architectures disable C++ exceptions, RTTI, GS, SDL, CFG, ASLR/relocations, manifest and ordinary stack probing; x86 also disables SAFESEH; omits frame pointers and enables COMDAT/ref elimination. DEP remains enabled. Read-only data merges into `.text`; retain `.data` separately to avoid expanding zero-initialized memory on disk. Large Release automatic allocations must move to suitable owned storage before stack probing can remain disabled. Both architectures use `/Gs2147483647`. XCRT x64 still supplies `__chkstk` for objects compiled with other probe thresholds, without linking the Microsoft CRT.

Runtime contracts: process-heap allocation; WinAPI memory/string helpers implemented in C; x86 integer arithmetic helpers and non-unwinding setjmp/longjmp in `xcrt_x86.asm`; x64 non-unwinding setjmp/longjmp preserving RBX/RBP/RSI/RDI/R12–R15, XMM6–XMM15, MXCSR and x87 control words; minimal WinMain startup without argc/argv parsing or environment lookup; strtoul; unbuffered native files. `FILE *` carries a HANDLE and must never be dereferenced or passed to another CRT. File positions use signed32 fseek/ftell and SetFilePointer; files must be smaller than 2 GiB. Append uses FILE_APPEND_DATA, including after seeks. Text modes retain raw bytes without CRLF translation. Serialize compound operations on a shared file handle in the caller.

`snprintf` calls `wvnsprintfA` with the supplied capacity and va_list; `sprintf` calls `wvsprintfA` for existing resource-name callers. Both use WinAPI formatting; `sprintf` requires caller-owned capacity and a result shorter than 1024 bytes. It uses WinAPI format syntax and truncation/error return semantics, without C99 extensions or float formatting. No remove/rename/vsnprintf, printf/scanf, standard streams, fprintf/vfprintf, vsprintf, fgetc/fputc/fputs, fflush or 64-bit seek APIs. Console diagnostics and journal/trace-stream helpers are Debug-only. Resource reads retain size bounds; additional read-error diagnostics are Debug-only. Debug `--collect` truncates the log on startup and writes each normalized resource path once through `fwrite`, using at most 1024 in-memory name hashes.

Windows `XPORT_AUDIO_OUTPUT` and `XPORT_AUDIO_BACKEND` are read only under `_DEBUG`. Release uses ordinary audio output; headless execution uses the null sink.

Only Debug WinMain recognizes the exact `--collect` argument; Release compiles out collection and ignores the switch. Neither build creates argc/argv. Under LOCKSTEP_DEBUG, WinMain checks --lockstep-replay and --lockstep-boundary-selftest directly with strstr; LOCKSTEP_DEBUG is a Debug-only build flag; other builds ignore these switches. Windows has no platform argument array or executable-path buffer. xport_arg_count/xport_arg_values are removed from the shared API; consuming projects own migration of any former callers.

XCRT startup initializes the process heap and calls WinMain with GetModuleHandleA(NULL), NULL, GetCommandLineA() and SW_SHOWDEFAULT, then ExitProcess. No GetStartupInfoA, environment block, command copying or executable-name parsing. XPORT_RASTERIZE/XPORT_VERIFY_VRAM environment overrides are Debug-only; Release headless rasterization is disabled.

MDEC floor rounding uses arithmetic shifts, including negative values, in IDCT and YUV conversion. Do not implement division by powers of two through general 64-bit division helpers in these hot paths. XCRT x86 integer division uses shared MASM helpers: hardware DIV for 64/32, a 32-step remainder loop for a wide divisor. x64 uses native integer instructions. Its sin/cos/atan2/sqrt float/double entry points marshal XMM arguments/results to a balanced x87 stack; trigonometric arguments retain the same practical game-range limits as the x86 x87 helpers.

Windows Release template uses /O1 and /Gw. Collect output uses ../src/platform/web/collect.log relative to the native working directory (bin). abort terminates pseudo-handle (HANDLE)-1. No GetLastError/SetLastError, GetCurrentProcess, GetModuleFileNameA, VirtualQuery or UpdateWindow calls. Presentation owns drawing; there is no custom WM_PAINT handler. Windows xport_memory_readable performs only numeric native-address/nonempty/overflow checks, not OS page validation; callers own pointer validity. Lockstep publication opens an existing named mapping first and accepts it only when reuse is requested, otherwise creates a mapping.

Canonical Windows template and RapidRacer share Debug/Release compiler, linker and xcrt settings. Debug enables XPORT_ENABLE_AUDIT and XPORT_MEMORY_DIAGNOSTICS; Release disables function markers. Keep game-specific bindings such as XPORT_NATIVE_GPU_CD in the consuming project, not the template.

## Analog gamepad input

Windows XInput and web Gamepad input latch both sticks when xport_input_read is called. xport_input_analog returns the availability flag and four PS1 bytes in RX,RY,LX,LY order: left/up=0, center=128, right/down=255. Physical D-pad and mapped keyboard directions on both ports override only the pressed left-stick axes; web touch directions do the same on P1. Opposite directions on one axis produce 128; untouched axes retain their sampled analog values. Right-stick values and analog-device availability are unchanged. Missing devices otherwise center the axes, and input overrides return centered axes with no live analog device. Windows inverts XInput Y; browser axes already point down. The left stick also ORs digital D-pad directions above 40% per axis, allowing diagonals and preserving physical D-pad/keyboard buttons. Keep these synthesized bits separate from physical directions so ordinary analog movement never becomes full-scale. Right-stick motion never generates D-pad buttons.

Native direct PAD buffers, owner packets and serial read replies publish 0x73 and all four axes for analog gamepads in analog mode, or 0x41 in digital mode or for keyboard input. Serial replies latch a single report at command 0x42. Replay-bound packets retain their recorded analog values and bypass native publishing.

Native PadSetMainMode accepts ports 0/0x10 and modes 0=digital, 1=analog for a connected analog-capable device after PadStartCom. It completes synchronously and refreshes direct/owner reports; subsequent serial replies use the selected mode. Keyboard-only input, missing initialization/devices, invalid ports/modes and lock values outside 0..3 return 0. Lock 2 unlocks, 3 locks the host mode button, 0/1 preserve the lock state; host input has no analog-mode button, and explicit game API requests remain allowed while locked. Both ports have independent mode/lock state, reset to analog/unlocked by PadInitDirect.

Native PadInfoMode terms: 1=current ID (4 or 7), 2=extended analog-capable model ID (7 or 0), 3=current mode offset (0 or 1), 4=supported ID table (offset -1 returns count; entries 4 and 7 for analog-capable input, only 4 for keyboard). It exposes analog capability even while the selected mode is digital. An explicitly bound SDK owner takes priority in PadInfoMode and PadSetMainMode, retaining its query fields and queued commands even outside replay; the native analog override applies only when no owner is bound. Replay-bound and LOCKSTEP_DEBUG paths retain the existing guest-owner command handling and recorded modes.

Bind SDK key storage through `spu_bind_key_guest(state, event_mode, event_flags, pending_mask, registers)` after guest memory binding. Pass the original SDK addresses; `registers` names the eight-byte pending key-on/key-off halfword block. `SpuSetKey` masks voices to 24 bits, rejects modes other than 0/1, publishes immediate key-state writes, and implements event-mode queue writes and cancellation of opposite pending bits. An unbound consumer retains direct host key operations. Binding changes configuration only; it must not seed or copy guest key state. RRJ binds this storage from `rrj_memory_bind` on initial load and restore. Original authority: `RoadRashJailbreak-xport/status/lockstep-converge/trip2/spu-key-frame33-audit.json`; executable branch checks: `tools/tests/test_spu_key_guest.py`.

Native `SsVabOpenHead` permits reserved tone groups: the header program count locates the sample-size table, while nonempty program records select packed tone groups. The active group count must fit the declared capacity; equality is not required. Apocalypse `level7.vab` has five reserved groups and four active programs. Original image evidence: `Apocalypse-xport/status/audits/audio-level-fixes-20261015/repair.json`; regression: `gpu_observer_test --fixture spu_pending_key --configuration Debug`.

Native platform flags, x64 builds, host/guest pointer boundaries and x86-only converge policy are defined in [PLATFORMS.md](PLATFORMS.md).


`spu_clear_reverb_guest(guest, begin, bytes, source, direction)` clears an explicitly reviewed SPU byte range through the common synchronous block-transfer core. The caller owns the original allocation-table check and range derivation. Source maps a readable 1024-byte guest buffer; direction maps four guest bytes. The adapter installs a native guest transfer binding only when none is active, rejects mismatched existing guest fields, active transfers, failed backends and ranges outside SPU RAM, and preserves the requested mode, normalized mode and callback. It does not change ordinary SpuClearReverbWorkArea binding behavior. Native validation: `python -B tools/gpu_observer_test.py --fixture spu_control --configuration Debug` from a consuming project; covers two-block writes, adjacent sentinels, field restoration and binding/range rejection. This native backend does not establish physical DMA or BIOS interrupt timing.

BIOS legacy joypad entry points `PAD_init2(type, destination)` and `PAD_dr()` use the existing pad polling service. Valid types are `0x20000000/1`; initialization returns 2, invalid types return 0. The packed destination uses each controller's original button-byte order, excludes unsupported IDs and is updated only while pad communication is active. A successful direct `InitPAD` supersedes the legacy destination. Kernel heap reinitialization clears legacy buffer ownership. Existing consumers require no migration. Run `python -B -m unittest tests.test_bios_pad_optional_port -v` from `tools`; the test covers two ports, packed legacy input, rejection and stopping.
