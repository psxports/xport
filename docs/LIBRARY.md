# Shared PSX host runtime

`psx_identity_matrix` is the immutable fixed-point identity MATRIX with diagonal4096 and zero translation. `psx_identity_rotation_words[5]` is the same rotation in packed GTE control-register order,including zero upper padding in the fifth word. Use the matrix for native PsyQ matrix inputs and the words for packed register/record copies;neither depends on a consuming game's DRAM or executable tables. Preserve non-const SDK signatures by passing a local matrix copy when required;do not cast away const.

`FIELD_RATE` remains the nominal SDK rate. The default physical VBlank ratio follows DuckStation: FIELD_RATE=50 selects 53203425/(3406*314) Hz (PAL); FIELD_RATE=60 selects 53693175/(3413*263) Hz (NTSC). Other rates retain FIELD_RATE/1. Explicit FIELD_RATE_NUMERATOR / FIELD_RATE_DENOMINATOR overrides remain supported; define both for a custom profile. Native VBlank polling, field pacing, GPU skip deadlines and Windows-null/Web PCM counts share this ratio. xport_frame_fract(uint64 *idx) returns the phase and publishes the frame index from one timestamp; xport_frame_time(idx) returns the absolute microsecond boundary rounded up. Platform waits compute their next deadline from absolute elapsed time, without accumulating rounded periods. Consumers use these helpers for logic indices and interpolation phases; nominal SDK tick constants remain unchanged.

Set `XPORT_AUDIO_VBLANK_QUEUE=1` for native Windows to render PCM on the game thread before each VBlank IRQ and queue it for waveOut. The output worker consumes complete PCM blocks and never advances SPU voices. In this mode device buffers affect output latency, not note quantization or envelope reads. The two-second FIFO preserves sample order. When full, the producer releases the audio lock and waits for the WaveOut worker to consume samples; it does not drop PCM or advance another SPU field while waiting. Oversized submissions, invalid queue occupancy and a stopped output worker still abort. Absolute read/write counters are 64-bit so a 32-bit boundary cannot change physical ring indexing. The queue check exercises backpressure, lock release, PCM order and crossing that boundary. Defaults retain the legacy worker-rendered path; other consumers require no migration. Verify `python -B -m unittest tests.test_audio_field_clock -v` from tools. P2 paired 40-second, 24-voice evidence: `Pandemonium2-xport/status/audio/review-audio-clock-20261017.json`.

Set `XPORT_SPU_VOICE_CAPTURE` to a writable filename before native audio starts to capture raw 44100 Hz signed little-endian 16-bit PCM. Each frame contains 24 stereo voices in voice-index order, after ADSR/voice volume and before master volume/reverb. An unset variable leaves capture disabled. Opening or writing failure aborts; normal exit flushes the final block. Forced termination can omit the last buffered 256 frames. `spu_voice_capture_sample_count` counts captured frames for debugger start markers. No game bindings or ABI changes are required. Paired Goon City evidence: `Pandemonium2-xport/status/audio/goon-city-channels/comparison.json`.

## Native decoded SPU PCM

### Color and alpha fog

- `vid_fog(fog)` enables two-stage fog for subsequent custom-shader draws in the active frame. Supply `VID_FOG` with radial world distances `0 < near_dist < far_dist < horizon_dist`, normalized RGB `color`, and positive `focal[2]` matching the current projection (`clip.x = camera.x * focal[0]`, `clip.y = -camera.y * focal[1]`, `clip.w = camera.z`). `vid_fog(NULL)` disables it. Each draw snapshots the parameters
- The vertex shader reconstructs camera-space position and computes its length. It clamps logarithmic coefficients `log(max(d,near)/near)/log(far/near)` and `log(max(d,far)/far)/log(horizon/far)`, then squares each to reduce early fog density. Rasterization interpolates the coefficients; the fragment shader performs no distance, logarithm or smoothstep calculation. This approximation depends on polygon tessellation
- Custom fragment shaders call `vidFog(color)` after computing their surface color. Opaque/alpha RGB first blends into the supplied fog color; alpha then fades to zero using the second coefficient. Fully transparent fragments are discarded before depth writes. Additive/subtractive materials fade RGB toward zero using the first coefficient. Default VID shaders do not apply fog
- Fog-enabled opaque custom-shader materials use ordinary source-alpha blending; other blend modes and depth-write policies remain intact. Render horizon first and disable fog before UI. The second range reveals existing framebuffer contents, including any earlier geometry; no background texture, GPU copy or extra texture sample is used

### HD float transforms

`xport.h` defines `VEC3F` (`x/y/z`, `v[3]`) and `QUATF` (`x/y/z/w`, `v[4]`). `psx.h` defines `VECTORF` (`vx/vy/vz`) and `MATRIXF` (`float m[3][3]`, `float t[3]`). These types and the float operations in `psx.c` serve HD rendering only. Consuming projects retain their integer physics, collision, AI and simulation state; HD reads a simulation sample and must never write float transform results back to it.

Float coefficients use identity `1.0f`, translations use world units, and rotation angles use radians. Convert encoded assets and simulation inputs at the consuming game's render boundary. Build float poses from source angles, quaternions or basis vectors; converting a completed fixed-point render matrix is not a completed HD migration. Float operations accept valid finite inputs and non-null pointers, do not use the COP2 register bank, and do not emulate fixed-point rounding, wrapping or saturation.

`ApplyMatrixf` applies the 3x3 part only; `RotTransf` also adds translation. `MulMatrix0f(left, right, dst)` computes `left.m * right.m` and preserves `dst.t`; `MulMatrixf` writes the left operand and `MulMatrix2f` writes the right operand. `CompMatrixf` composes both rotation/scale and translation. `TransposeMatrixf` transposes only the 3x3 part and preserves destination translation. All these operations support destination aliasing an input. `IdentityMatrixf` resets both rotation and translation.

Axis rotations premultiply the 3x3 part and preserve translation. `RotMatrixf` builds `Rx * Ry * Rz`; `RotMatrixYXZf` builds `Ry * Rx * Rz`; both preserve destination translation. `ScaleMatrixf` scales columns, and `TransMatrixf` replaces translation. `NormalizeVectorf` returns the original length and outputs a unit vector; zero input outputs zero. `NormalizeQuatf` returns the original norm and outputs a unit quaternion; zero input outputs identity quaternion. `MulQuatf` uses Hamilton multiplication and supports in-place destinations. `QuatMatrixf` normalizes the input orientation, builds its 3x3 rotation and preserves translation.

`OuterProductf` computes a cross product and supports destination aliasing either input. `ProjectVertexf` projects an already transformed camera-space vector. `RotTransPersf` first applies the supplied matrix, then delegates to `ProjectVertexf`. Both projection entries return homogeneous clip coordinates, retain float depth in `w`, and reverse camera Y for OpenGL/WebGL presentation. Callers supply focal coefficients and `0 < near_z < far_z`. Near/far map to NDC depth -1/+1. They perform no perspective divide, viewport rounding or visibility rejection; the renderer owns clipping and viewport policy.

Run `python -B xport/tools/tests/gte_float_test.py --output PROJECT_ROOT/status/audits/vid` on a Windows MSVC host. The fixture compiles the exact current float function closure with `/Od /MDd /D_DEBUG` and enabled assertions. It checks rotation order, composition, in-place aliases, fractional vectors, normalization, scale, projection planes and quaternion poses. It does not prove game integration or a complete runtime COP2 snapshot comparison. For Rapid Racer use tools/check.py and status/checks.json; build and test Release only when explicitly requested and authorized by that project's user policy.

The shared shader-only VID interface, OpenGL/WebGL build inputs, resource ownership and OG/HD transition contract are in [VID.md](VID.md).

## Modules

Ordinary native and Web builds enable whole-frame raster catch-up at startup. Each blocking `VSync(0)` or `VSync(n>1)` advances an independent planned frame deadline by its requested field span; query-only VSync modes do not create a frame. The first deadline includes the initial requested field span rather than starting one span behind. Native waits count fields since the preceding completed blocking VSync; fields already delivered by event polling or query modes satisfy that wait. A skipped boundary does not consume this completed-wait counter. Provider-bound and SDK-sampled waits retain their existing paths. When the next boundary is already overdue, VSync returns without another wait and latches raster suppression until the following blocking VSync. All primitive/OT passes, DRAWENV background fills, ClearImage and menu-surface clearing retain their existing framebuffer pixels; presentation retains the last displayed image. Draw state and image upload/copy/readback still execute. Framebuffer readback can therefore observe older complete buffers; feedback-heavy games require separate acceptance. The policy does not accelerate expensive simulation/packet construction and cannot guarantee real-time play when those alone exceed the field budget.

The policy starts enabled in every ordinary build and is compiled out for `LOCKSTEP_DEBUG` coverage. Host startup needs no configuration. `gpu_frame_skipped()` reports the latched decision; `gpu_skipped_frames()` counts dropped frame boundaries. Graph reset/load rebase scheduling; monotonic-clock rollback or a gap greater than one second cancels backlog. Host policy and wall-clock deadlines are outside portable GPU snapshots. Each platform backend owns the native process entrypoint and calls the required game-owned `void xport_main(void)`. The backend consumes common flags directly and receives the result through `xport_set_exit_code`. A port to another operating system implements the platform service declarations from `xport.h` in its own `platform/<name>/main.c`; `psx.c` contains no operating-system calls.

`psx.c` loads a `PSX_EXE` description into shared guest RAM and provides common CD path, size and read helpers. Games own only executable addresses, paths and the call into their translated entry. `xport_trace.c` owns memory access, audit, device events and lockstep diagnostics; a game-owned `game_except.c` provides the static exception arrays used by lockstep builds; no configuration parser runs inside the game.

Translated code must include `psx.h` and use the shared debugger-visible `r_u8`, `r_u16`, `r_u32`, `r_s8`, `r_s16`, `r_s32`, `w_u8`, `w_u16`, `w_u32` and `w_masked_u32` functions for numeric guest-memory access. Do not add game-owned memory helpers, macros or DRAM/Scratchpad address decoders. Debug builds export stable function symbols so a debugger can break on every read or write; memory diagnostics may wrap writes with source metadata but still call the same shared symbols. The shared `w_u8_at`, `w_u16_at`, `w_u32_at` and `w_masked_u32_at` diagnostic adapters attach C source metadata and are never implemented or called explicitly by a game.

PsyQ GPU packet types remain declared in `psx.h`. Use their fixed-width fields directly: signed SDK `long` fields require `sint32`, unsigned words require `uint32`, coordinates require `sint16`. Do not duplicate these types in consuming games. Packet sizes include the four-byte DMA tag: `POLY_FT4` and `POLY_GT3` are 40 bytes, `LINE_F3` is 24 bytes, `SPRT` is 20 bytes, and `DR_MODE` is 12 bytes.

GPU packet views: `XY.xy` or `XY.x/y`; `RGBC.rgbc` or `RGBC.r/g/b/code`; `UV.uv` or `UV.u/v`. Vertex records are `POINT_C` (RGBC rgbc + XY xy, 8 bytes), `POINT_T` (XY xy + UV uv + uint16 attr, 8 bytes) and `POINT_CT` (RGBC rgbc + XY xy + UV uv + uint16 attr, 12 bytes). `P_TAG` has `RGBC rgbc` at byte 4 and remains 8 bytes; generic command access uses `rgbc.code`. Flat packets keep one `RGBC rgbc`; all vertices are stored only in `p[]`. `attr` is CLUT at vertex 0, texture page at vertex 1, and the original format's reserved/depth-bias word at later vertices; retain each audited consumer's meaning. `LINE_F2..5` use `XY p[]`; `LINE_G2..5` use `POINT_C p[]`. F5/G5 are xport extensions, not original PsyQ typedefs; repeat vertex 0 at vertex 4 to close a quad. `setLineF/G2..5` preserve command/length/terminator semantics. Binary packet layouts remain unchanged; source callers must migrate removed named vertex/color/UV/texture fields to these views. Sprite/tile owners use `p[0]`; generic PsyQ setters remain callable.

In native builds, Red Book EOF detection in `spu_render` records one pending `CdlDataEnd` notification under the internal audio lock. `xport_gte_execute` uses the existing MVMVA engine for its supported commands: `0x480012` transforms V0 with translation, `0x49E012` transforms IR without translation, and `0x486012` transforms V0 without translation for `MulMatrix0`. Ordinary SPU initialization creates internal native transfer state when no explicit transfer binding exists. `SpuInit` and `SsInit` share that initialization path. Explicit custom or guest bindings retain their existing selection. Native state uses eight-byte addresses, 64-byte DMA blocks, initial address units `0x200`, and a completed initial transfer. `SpuWrite` accepts native source pointers under this internal owner; it reads only `byte_count` bytes, zero-fills the alignment tail, and supports SPU RAM wrapping. Guest sources keep their original rounded-block reads. Internal native transfer completes synchronously; physical DMA timing and interrupt callbacks are not established. Games need no transfer clock, wait callback or state binding. Private size-tagged SPU state includes native transfer fields; bound transfers remain outside the portable guest-only snapshot contract. The common `SpuSetTransferStartAddr` return is an aligned byte address; the reviewed RR original returns eight-byte units. Its caller ignores the result; callers requiring the original return must account for that documented difference.

`SpuInitMalloc(count, records)` uses the caller's aligned native buffer for `(count + 1) * 8` bytes of allocator records. The extra record holds the terminal free span. A nonpositive count, null buffer or unaligned buffer returns zero without replacing the allocator. Positive initialization writes the first record, owns the last index inside SPU state, binds a limit of `count`, and returns `count`. The caller must keep the buffer alive until the next initialization. Native addresses in these records are SPU RAM byte offsets, not game DRAM addresses. `SpuInit` clears the allocator binding and reverb reservation and restores the reviewed SDK default work address `0xF204` in eight-byte units. Use `SpuReserveReverbWorkArea` to reserve it and let mode changes update the allocator reservation. Legacy explicit guest heap bindings remain available for unmigrated consumers. Native record buffers are outside the portable guest-only snapshot contract; size-tagged SPU snapshots include the native last index but do not serialize caller-owned record buffers.

`SpuGetVoiceAttr` must preserve the caller's `voice` and `mask` fields because PsyQ treats `mask` as invalid output. A caller may reuse the same structure with `SpuSetVoiceAttr`; clearing the mask would convert a selective update into an all-fields update.

Explicit reconstructed calls to `__ltdf2`, `__floatsisf`, `__fixsfsi`, `__divsf3`, `__extendsfdf2`, `__fixdfsi`, `__floatsidf` and `__truncdfsf2` use the shared runtime rather than native casts/operators. Their source algorithms preserve PsyQ bit ordering, half-up rounding, variable-shift count masking, saturation and non-IEEE zero/division behavior. `__ltdf2` returns only `-1` or `0` and orders NaN encodings by magnitude; it is not a host three-way comparator. `__fixsfsi(-0.0f)` returns `INT_MIN`. `__floatsisf(INT_MIN)` preserves the original nonterminating normalization loop; do not use this entry to introduce a new integer-conversion policy.


`__mulsf3PSX(uint32, uint32)` accepts and returns encoded binary32 words, matching the original soft-float register carriers. Do not return this result through a native `float` function: x86 x87 quiets signaling NaNs and changes the original result bits. Preserve words across nested arithmetic calls. `psx_float_bits` and `psx_float_value` marshal native numeric values at the boundary; native conversion to a numeric float is not a guarantee of signaling-NaN bit preservation. The multiply uses the original high-part product and separately truncated cross-products, not a native floating-point multiplication or a full 48-bit mantissa product.

`__extendsfdf2` normalizes nonzero binary32 subnormals and rebases every nonzero exponent literally, including exponent `255`; this differs from native infinity/NaN promotion. `__fixdfsi` preserves the original negative-zero result and reports overflow for either sign. `__truncdfsf2` preserves half-up rounding and original modulo-32 underflow shift counts. Both integer-to-float entries retain the original nonterminating normalization for `INT_MIN`.

`__adddf3PSX`, `__muldf3PSX` and `__divdf3PSX` accept and return encoded binary64 values through `uint64` carriers. Keep nested arithmetic encoded; use `psx_double_bits` and `psx_double_value` only at native numeric boundaries, where signaling NaNs may be quieted. Addition preserves signed mantissa alignment and guard-bit-dependent rounding. Multiplication omits the low-21-bit product and truncates each cross-product separately. Division uses the original 54-bit restoring quotient and a 32-bit masked underflow rounding increment; a zero denominator produces the signed all-ones NaN encoding without an error event. Overflow reports `0x22` at points `0x0b`, `0x0d` and `0x0f` respectively. These contracts derive from complete original MIPS, not native IEEE arithmetic. Consumer caller audits remain separate requirements.

The native `LIBMATH` globals `math_errno` and `math_err_point` belong to `psx.c`. `_err_math` writes both before delivering class `0xF4000002`, specification `0x301` for error `0x21` or `0x302` for error `0x22`; other error values deliver no event. Original title-specific DRAM addresses of these SDK globals are not automatically native-symbol aliases. A consumer reading those guest addresses needs an audited mapping. These helpers do not establish equivalence for every reconstructed caller or every possible operand pair.

`VectorNormal` and `VectorNormalS` use the immutable 192-entry PsyQ reciprocal square-root table owned by `src/psx.c`. ## Windows Release CRT

`src/platform/win/xcrt.c` is the shared custom C runtime for Windows x86/x64 Release. Architecture-specific ABI helpers live in `src/platform/win/xcrt_x86.asm` and `src/platform/win/xcrt_x64.asm`; both require the MASM build customization. The canonical Windows template and synchronized consuming Windows projects enable it by default; local project icons override the shared default through an adjacent `icon.rc`. Debug on both architectures keeps its standard CRT. Build either existing Release architecture with `/p:UseXcrt=false` to exclude xcrt and restore standard `/MT` linking; do not add separate runtime configurations.

`xcrt.c` supplies `atoi`, `strncpy` and `sprintf`. `atoi` accepts ASCII whitespace, optional sign and decimal digits with 32-bit unsigned accumulation. `strncpy` copies at most the requested count and pads the remaining bytes with zero. Debug and standard-CRT Release do not compile these definitions.

C++ consumers include shared `platform/win/xcrt.h` with `XCRT_CPP_IMPLEMENTATION` defined in exactly one C++ translation unit. The header emits definitions only under `XPORT_XCRT`; Debug, Web and `UseXcrt=false` retain their platform runtime. Scalar/array `new` use `malloc`, and scalar/array, nothrow and compiler-emitted sized `delete` use `free`. Zero-size allocations request one byte. Ordinary allocation failure aborts because XCRT has no C++ exception unwinding; nothrow allocation returns null on failure. Placement forms remain supplied by `<new>`. C++98 syntax is retained; sized deallocation is enabled for current MSVC and compilers advertising it. `_purecall` aborts in `xcrt.c`. This does not supply STL, `atexit`, dynamic global constructors/destructors, `new_handler`, exception objects or aligned allocation. Keep required Release registries in zero-initialized POD storage and avoid relying on CRT startup initialization.

Enabled: `/NODEFAULTLIB`, `/ENTRY:WinMainCRTStartup`, `/Zl`, kernel32/user32/gdi32/winmm/shlwapi imports only. Both Release architectures disable C++ exceptions, RTTI, GS, SDL, CFG, ASLR/relocations, manifest and ordinary stack probing; x86 also disables SAFESEH; omits frame pointers and enables COMDAT/ref elimination. DEP remains enabled. Read-only data merges into `.text`; retain `.data` separately to avoid expanding zero-initialized memory on disk. Large Release automatic allocations must move to suitable owned storage before stack probing can remain disabled. Both architectures use `/Gs2147483647`. XCRT x64 still supplies `__chkstk` for objects compiled with other probe thresholds, without linking the Microsoft CRT.

Runtime contracts: process-heap allocation; WinAPI memory/string helpers implemented in C; x86 integer arithmetic helpers and non-unwinding setjmp/longjmp in `xcrt_x86.asm`; x64 non-unwinding setjmp/longjmp preserving RBX/RBP/RSI/RDI/R12–R15, XMM6–XMM15, MXCSR and x87 control words; minimal WinMain startup without argc/argv parsing or environment lookup; strtoul; unbuffered native files. `FILE *` carries a HANDLE and must never be dereferenced or passed to another CRT. File positions use signed32 fseek/ftell and SetFilePointer; files must be smaller than 2 GiB. Append uses FILE_APPEND_DATA, including after seeks. Text modes retain raw bytes without CRLF translation. Serialize compound operations on a shared file handle in the caller.

`snprintf` calls `wvnsprintfA` with the supplied capacity and va_list; `sprintf` calls `wvsprintfA` for existing resource-name callers. Both use WinAPI formatting; `sprintf` requires caller-owned capacity and a result shorter than 1024 bytes. It uses WinAPI format syntax and truncation/error return semantics, without C99 extensions or float formatting. No remove/rename/vsnprintf, printf/scanf, standard streams, fprintf/vfprintf, vsprintf, fgetc/fputc/fputs, fflush or 64-bit seek APIs. Console diagnostics and journal/trace-stream helpers are Debug-only. Resource reads retain size bounds; additional read-error diagnostics are Debug-only. Debug `--collect` truncates the log on startup and writes each normalized resource path once through `fwrite`, using at most 1024 in-memory name hashes.

Windows `XPORT_AUDIO_OUTPUT` and `XPORT_AUDIO_BACKEND` are read only under `_DEBUG`. Release uses ordinary audio output; headless execution uses the null sink.

Only Debug WinMain recognizes the exact `--collect` argument; Release compiles out collection and ignores the switch. Neither build creates argc/argv. Do not implement division by powers of two through general 64-bit division helpers in these hot paths. ## Analog gamepad input

Windows XInput and web Gamepad input latch both sticks when xport_input_read is called. xport_input_analog returns the availability flag and four PS1 bytes in RX,RY,LX,LY order: left/up=0, center=128, right/down=255. By default, analog axes and digital D-pad/keyboard/touch buttons remain independent. Windows inverts XInput Y; browser axes already point down. Missing devices center the axes, and input overrides return centered axes with no live analog device.

XPORT_PAD_HACK defaults to 0. Define XPORT_PAD_HACK=1 only in a consuming project that requires the compatibility mapping: the left stick ORs digital D-pad directions above 40% per axis, and physical D-pad/keyboard directions on both ports override the pressed left-stick axes; web touch directions also do this on P1. Opposite directions produce 128, untouched axes retain sampled analog values, and right-stick values/device availability remain unchanged. Synthesized D-pad bits never feed back into analog axes. Keep the option identical across all compiled input units; do not enable it globally or in the startup template.

Native direct PAD buffers, owner packets and serial read replies publish 0x73 and all four axes for analog gamepads in analog mode, or 0x41 in digital mode or for keyboard input. Serial replies latch a single report at command 0x42. Replay-bound packets retain their recorded analog values and bypass native publishing.

Native PadSetMainMode accepts ports 0/0x10 and modes 0=digital, 1=analog for a connected analog-capable device after PadStartCom. It completes synchronously and refreshes direct/owner reports; subsequent serial replies use the selected mode. Keyboard-only input, missing initialization/devices, invalid ports/modes and lock values outside 0..3 return 0. Lock 2 unlocks, 3 locks the host mode button, 0/1 preserve the lock state; host input has no analog-mode button, and explicit game API requests remain allowed while locked. An explicitly bound SDK owner takes priority in PadInfoMode and PadSetMainMode, retaining its query fields and queued commands even outside replay; the native analog override applies only when no owner is bound.
