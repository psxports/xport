# Shared PSX host runtime

Native `SpuSetKey(SPU_OFF, mask)` cancels unrendered SDK key-on bits for the same voices after queuing key-off. This prevents a later SDK stop from leaving a voice in Sustain when both operations reach one native mixer buffer. API signatures and raw MMIO key-latch handling are unchanged. Current Gran Turismo pause PCM evidence and consumer scope: `GranTurismo-xport/status/function-coverage/first2/pause-quit-progress.json`; other consuming games are not runtime-validated by that scenario

Projects compile this canonical PSX/PsyQ runtime directly. Game code calls its PsyQ-compatible API; shared subsystems call required game-owned symbols declared in `xport.h`. No callback registration or fallback is permitted; missing bindings fail at link time.

`XPORT_DISABLE_FUNCTION_MARKERS` makes `FUNCTION_MARKER(address, image)` a compile-time no-op without evaluating arguments. It is opt-in per consuming build configuration; other projects retain their existing marker behavior. Native projects that no longer use lockstep can keep simple provenance markers in source, enable `XPORT_ENABLE_AUDIT` in Debug and disable function markers in Release. Do not disable markers in a lockstep/converge configuration.

At the native host-file boundary, `xport_cd_file_size_native(src, root, size)` and `xport_cd_file_read_native(src, root, dst, cap, size)` accept ordinary string and buffer pointers. They strip leading separators and the CD version suffix, convert backslashes, enforce the 260-byte host path capacity and reject colons in the CD path and `..` sequences in the resulting path, matching the existing guest path resolver. The caller owns the strings and destination through the synchronous call. Native reads use `xport_file_read` directly and do not publish guest-copy memory events. The existing guest-address file APIs retain their prior behavior for other consumers. RR migration and bounded codec/ISO checks: `RapidRacer-xport/status/audits/native-stage6/cd-native-path-native.json`.

For a consuming project that supplies `xport_gpu_guest_dispatch`, define `XPORT_GAME_GPU_GUEST_DISPATCH=1` for its complete native build. This disables only the legacy shared fail-fast definition in `psx_gpu.c`; the existing declaration, signature and callers remain unchanged. Supply the symbol in an already registered project binding module and fail fast when its GPU adapter is absent. With the macro absent or zero, existing consumers retain the shared definition and need no new source or binding. RRJ uses this mode to keep the missing-boundary body outside the optimized GPU caller translation unit without disabling C4702 or reducing GPU optimization.

## Modules

Native Windows/Web input owns two independent digital pad ports. P1: WASD directions; I/J/K/L Triangle/Square/Cross/Circle; 1/Q/3/E L2/L1/R2/R1; Enter Start; Backspace Select. P2: arrow cluster directions; NumPad 5/1/2/3 Triangle/Square/Cross/Circle; NumPad 7/4/9/6 L2/L1/R2/R1; NumPad Enter Start; NumPad Plus Select. NumPad 0 is unmapped. Windows distinguishes NumPad Enter and Num Lock off navigation keys through the extended-key flag. Arrow keys belong only to P2. XInput/browser gamepads use the first two connected devices in enumeration order, one per port. Touch and the existing input override API affect P1 only. Invalid port indices return zero.

After `PadInitDirect`, call `PadStartCom` to enable native packet publication. Active polling publishes connected `0x41` packets for both keyboard ports and any bound SDK owner packets; it preserves active-low button byte order. `PadStopCom` suspends polling. Replay-bound pads retain recorded packets and bypass native publication. Native serial state is independent per port. Verify with `python -B -m unittest tests.test_pad_ports -v` from `tools`; actual Win/Web C closures, sparse gamepad enumeration, SDK packets, stopped polling and replay isolation are exercised. Game-specific split-screen evidence belongs to the consuming project.

`SsChannelMute(sequence, separation, mask)` writes the low16 mask at offset128 of the existing bound LIBSND sequence record (176 bytes per separation). It sign-extends the two indices, preserves wrapping address arithmetic and returns the wrapped separation offset. It requires the existing sequence-table binding; it adds no binding or snapshot state. `_SsNoteOn` already consumes this mask. SF original PsyQ `LIBSND.LIB/SSCMUTE.OBJ` evidence: `SyphonFilter-xport/status/native-startup/sequence-mute-native-review.json`.

`SsVoKeyOff(voice_program, note_volume)` extracts signed16 bank from bits8..23, low8 program and low16 note from bits8..23, then uses `_SsVmKeyOff` with identity33. The low8 second carrier is unused by the original downstream entry. This additive API reuses the existing libsnd VM binding and adds no consumer binding or snapshot state. SF evidence: `SyphonFilter-xport/status/native-startup/ss-vo-keyoff-signatures.json`.

`GsSortOtPSX(source_ot, destination_ot)` sorts a numeric guest five-word LIBGS ordering-table descriptor into another. It preserves packet-length bytes, follows 24-bit links to the terminal tag and retains alias-sensitive read/write order. This additive API requires no new consumer bindings or modules and leaves existing native GPU links unchanged. SF original PsyQ `LIBGS.LIB/GS_114.OBJ` evidence and integration: `SyphonFilter-xport/status/native-startup/sort-ot-native-review.json`.

`GetODE()` returns GPUSTAT bit31 through the existing supplied GPU status source when bound. Native execution owns `GpuScanoutState` in `psx_gpu.c`: GP1 display origin, vertical range and mode configure scanout; the platform timer advances raster ticks at the PAL/NTSC nominal video clocks. Progressive mode uses display-origin plus scanline parity; interleaved mode uses the latched display field within the active range. Native `PutDispEnv` publishes these commands without guest PsyQ bindings. The scanout state, fractional tick carry and native display cache belong to the size-bound GPU snapshot; prior scalar-block sizes are rejected and loading rebases the host timer. This raster-clock model does not establish CPU-cycle, DMA, IRQ or rendering timing equivalence and does not implement a complete native GPUSTAT register. Game code calls only `GetODE`, without host synchronization or guest MMIO reads. RR evidence and bounded tests: `RapidRacer-xport/status/audits/native-stage6/gpu-ode-native.json`.

`GsSetFlatLight(index, descriptor)` uses the existing integer `SquareRoot0` and wraps the direction square sum and negated fixed-point numerators to 32 bits. Zero length returns `-1` without publishing matrices. Indices `0..2` replace one direction row and one color column; other indices retain both matrices and return zero after color publication. Bind caller-owned native `MATRIX` objects with `gte_bind_gs_light_matrices` before the call and clear the binding before those objects expire. An absent binding aborts. This new entry adds no required consumer symbols or project modules. A translated guest consumer imports and exports its reviewed LIBGS matrices through its own typed adapter. The binding is transient host state and is outside the portable snapshot contract. Original evidence: `SyphonFilter-xport/status/native-startup/gs-flat-light-native-review.json`.

- `psx_mdec.c` / `psx_mdec.h`: incremental MDEC RLE, integer IDCT, color conversion, command/FIFO state and delayed output in four depths. IDCT takes the original hardware scale-matrix order. Numerical and state fixtures do not establish hardware equivalence
- `xport_trace.c` / `xport_trace.h`: guest-memory access, memory observation, audit events, call and device tracing, lockstep boundaries, frame replay, shared mappings and checkpoints
- `platform/win/main.c`: Windows process entry, timer, exhaustive message/input polling, window, WaveOut audio, audio synchronization and file services

Each platform backend owns the native process entrypoint and calls the required game-owned `void xport_main(void)`. The backend consumes common flags directly and receives the result through `xport_set_exit_code`. A port to another operating system implements the platform service declarations from `xport.h` in its own `platform/<name>/main.c`; `psx.c` contains no operating-system calls.

`psx.c` loads a `PSX_EXE` description into shared guest RAM and provides common CD path, size and read helpers. Games own only executable addresses, paths and the call into their translated entry. `xport_trace.c` owns memory access, audit, device events and lockstep diagnostics; a game-owned `game_except.c` provides the static exception arrays used by lockstep builds; no configuration parser runs inside the game.

Translated code must include `psx.h` and use the shared debugger-visible `r_u8`, `r_u16`, `r_u32`, `r_s8`, `r_s16`, `r_s32`, `w_u8`, `w_u16`, `w_u32` and `w_masked_u32` functions for numeric guest-memory access. These functions preserve PSX aliases, unaligned little-endian access, DRAM/Scratchpad selection through the canonical `psx_addr` mapping, MMIO dispatch and trace observation. Do not add game-owned memory helpers, macros or DRAM/Scratchpad address decoders. Debug builds export stable function symbols so a debugger can break on every read or write; memory diagnostics may wrap writes with source metadata but still call the same shared symbols. The shared `w_u8_at`, `w_u16_at`, `w_u32_at` and `w_masked_u32_at` diagnostic adapters attach C source metadata and are never implemented or called explicitly by a game.

PsyQ entries are implemented directly in their owning shared module. Internal subsystem functions, types and constants use the `gpu_*`, `spu_*` and `gte_*` namespaces. Platform presentation and quit state use `xport_present` and `xport_isquit`; do not add `psx_*` forwarding aliases, parallel `PsyQ*` compatibility state or game-owned GPU trampolines.

The optional `psx_seq.c` module owns `_SsSeqPlay`, `_SsGetSeqData`, `_SsReadDeltaValue` , `_SsSetControlChange` , `_SsContNrpn2` , `_SsContNrpn1` , `_SsSetProgramChange` and `_SsNoteOn`. They implement the PsyQ LIBSND duration/countdown loop, explicit and running-status event decode, and variable-length delta values using numeric guest records. Bind the guest pointer table with `xport_libsnd_bind_sequence_table` and the 17-word event/control handler table with `xport_libsnd_bind_sequence_handlers`. Both bindings belong to `LIBSND_STATE`, are included in the existing size-bound snapshot, validated on restore and cleared on subsystem reset. Register `psx_seq.c` in each consuming native project and implement the required `xport_libsnd_sequence_call(target, argc, arguments)` service to dispatch original numeric handler targets synchronously. Only consumers of this optional module acquire that link dependency; existing SPU consumers and voice APIs are unchanged. `_SsSeqGetEof` remains an explicit fail-fast SDK boundary. Original provenance and current integration: `SyphonFilter-xport/status/native-startup/seq-data-native-review.json`. This implementation does not establish audible sequence playback or original equivalence.

PsyQ GPU packet types remain declared in `psx.h`. Use their fixed-width fields directly: signed SDK `long` fields require `sint32`, unsigned words require `uint32`, coordinates require `sint16`. Do not duplicate these types in consuming games. Packet sizes include the four-byte DMA tag: `POLY_FT4` and `POLY_GT3` are 40 bytes, `LINE_F3` is 24 bytes, `SPRT` is 20 bytes, and `DR_MODE` is 12 bytes.

GPU packet views: `XY.xy` or `XY.x/y`; `RGBC.rgbc` or `RGBC.r/g/b/code`; `UV.uv` or `UV.u/v`. Vertex records are `POINT_C` (RGBC rgbc + XY xy, 8 bytes), `POINT_T` (XY xy + UV uv + uint16 attr, 8 bytes) and `POINT_CT` (RGBC rgbc + XY xy + UV uv + uint16 attr, 12 bytes). `P_TAG` has `RGBC rgbc` at byte 4 and remains 8 bytes; generic command access uses `rgbc.code`. Flat packets keep one `RGBC rgbc`; all vertices are stored only in `p[]`. `attr` is CLUT at vertex 0, texture page at vertex 1, and the original format's reserved/depth-bias word at later vertices; retain each audited consumer's meaning. `LINE_F2..5` use `XY p[]`; `LINE_G2..5` use `POINT_C p[]`. F5/G5 are xport extensions, not original PsyQ typedefs; repeat vertex 0 at vertex 4 to close a quad. `setLineF/G2..5` preserve command/length/terminator semantics. Binary packet layouts remain unchanged; source callers must migrate removed named vertex/color/UV/texture fields to these views. Sprite/tile owners use `p[0]`; generic PsyQ setters remain callable. RR ABI and packet checks: `RapidRacer-xport/status/audits/refactor-cleanup/gpu-types.json`.

`psx_gte.h` native inline load/store helpers use the canonical COP2 register services, not a consumer-owned register bank. NFSHS independently interprets the PsyQ 3.6 and 4.5 `INLINE_C.H` transfer programs and compares 17 actual helpers in an x86 Release harness: `NFSHS-xport/tools/test_gte_transfer_abi.py` and `status/gte-transfer-abi-comparison.json`. The 136 cases compare complete fixture buffers and data/control banks; matrix/vector padding is zero and register services are explicit fixtures. This verifies bounded operand/register/field-offset transfers, not core arithmetic, COP2 command execution, timing or every pointer/layout case.

For native packet owners, call `gpu_register_packet_range(begin, size)` before linking their packets. It returns one for a registered range, including an exact repeated registration, and zero for null, empty, unaligned, overlapping, guest-memory, exhausted-count or exhausted-link-space requests. Ranges must remain allocated at the same address for the process lifetime; no unregister operation exists. The registry accepts at most 32 disjoint ranges and allocates aligned 24-bit links in `[0x200000, 0x800000)`. Use the native PsyQ functions `ClearOTag`, `ClearOTagR`, `AddPrim` and `AddPrims`; the raw lowercase tag macros do not encode these registered links. `DrawOTag` resolves registered links alongside ordinary guest RAM chains and rejects a registered packet whose header length exceeds its range. Registration is opt-in; existing `gpu_register_dma_range` and legacy pointer tags retain their compatibility path. Do not combine registered links with unregistered native pointer tags in one chain: their 24-bit domains can overlap. Native or guest ordering tables with guest and registered packets are supported.

`PutDrawEnv` accepts a native `DRAWENV *` without narrowing the pointer to a guest address. Packet encoding, observer submission, raster application and the bound PsyQ cache use that same owner. `gpu_put_draw_env` and `gpu_draw_env` retain their explicit guest-address contracts for translated device boundaries. A native environment cannot be submitted to a guest-only linked-submit hook; that hook reports failure instead of inventing a guest mirror.

Use `rsincos(angle, &sine, &cosine)` when a translated game function reads PsyQ's packed `rcossin_tbl` directly. This function computes both original signed 16-bit table values for the same angle and is not equivalent to calling `rsin` and `rcos` separately. Do not expose or duplicate the packed guest table solely for those reads. The private `gte_sincos_quarter[1024][2]` in `psx.c` reconstructs all 4096 packed pairs by quadrant swaps and signs, preserving duplicated endpoints. The reconstructed 16384-byte table has SHA-256 `b106234165685d79392c926192d1b2f9e30125307abde6040747e401a35d0e87`; it matches both reviewed PsyQ `LIBGTE.LIB` distributions and the classified original library data. Scalar `rsin`/`rcos` retain their separate 1025-entry quarter table.

Game memory maps, translated game logic, title-specific resource loading, WIP behavior and checkpoint orchestration stay in each project. Extend the required game-binding section of `xport.h` only for public cross-platform contracts. The platform audio worker calls shared `spu_render`; games use PsyQ `Ss*`, `Spu*` and `Cd*` calls and own no render callback, mixer, VAB registry or Red Book decoder.

The host Red Book path interprets each `CdlATV` byte as a normalized 8-bit weight: `0xFF` is direct unity and two `0x7F` contributions form a unity mono sum. Apply the CD matrix before SPU CD volume, voice summation, final saturation and master volume. Saturate every decoded PSX and IMA ADPCM sample before storing it in predictor history.

`CdSetToc` installs the native disc catalogue. `CdGetToc` and `CdGetToc2` return its track count and copy the lead-out entry plus every track entry under the audio lock. A null output or an unset catalogue returns zero. The native model does not issue physical CD commands; the reviewed `MAIN.EXE` implementation ignores the `CdGetToc2` mode argument.

`DMACallback` keeps an independent native callback slot for each of the seven DMA channels and returns the previous binding. Both it and `CdDataCallback` accept and return `PsxInterruptCallback`, a native `void (*)(void)`; they do not use the CD status/result callback type `CdlCB`. Invalid channels return null. `CdDataCallback` uses channel 3. This registry implements registration and removal, not hardware DMA interrupt delivery.

Native SPU MMIO accepts the eight halfword registers of each voice, IRQ-address register `0x1F801DA4` and control IRQ-enable bit `0x40`. Existing unsupported volume-sweep and control-routing writes still fail. RAM reads/writes through ADPCM decoding, transfers and reverb latch one pending IRQ when they touch the enabled eight-byte IRQ address; clearing IRQ enable cancels the latch. Late address/enable changes inspect the current transfer address and decoded voice blocks. IRQ enable keeps silent voices advancing their ADPCM readers. Call `spu_dispatch_pending_irq` only on the game thread: it removes a pending notification under the audio lock, releases the lock and raises native IRQ9. Windows and Web deliver through `xport_audio_vblank`; the Windows mixer worker never enters game code. Existing callback APIs and project registrations are unchanged. Added latch fields change the private size-tagged SPU state; older state sizes are rejected. Capture-buffer IRQs, physical transfer timing, exact delivery timing and RRJ audible/playable behavior remain unverified. Source receipt: `RoadRashJailbreak-xport/status/repairs/start-cross/native-spu-irq-device.json`.

`psx_irq_native_mask_exchange(mask)` returns the previous 16-bit native IRQ mask and applies the new mask through `psx_irq_write` to the existing native interrupt state. It does not register or replace an MMIO handler, allocate additional state or dispatch interrupts. Existing consumers need no migration. Gran Turismo uses it for its reviewed `0x1F801074` mask exchange after the observed GPU reset blocker; other unresolved device registers retain fail-fast boundaries.

`psx_irq_native_acknowledge(sources)` clears the selected native IRQ status bits through the existing `psx_irq_write` state contract and rejects masks outside the eleven IRQ sources. `ResetGraph(1)` also supports the synchronous native rasterizer when distinct DRAM queue head/tail words are bound by `gpu_bind_soft_reset`, and no transfer observer, linked submit hook or asynchronous sync sampler is installed. It clears the bound queue, acknowledges GPU IRQ and issues GP1 IRQ/FIFO reset commands while retaining VRAM and drawing/display state. Native packet submissions are complete calls, so this path has no partial FIFO or active hardware DMA transfer. Other reset paths retain their previous contracts; asynchronous modes remain unsupported by this native path. Gran Turismo scopes this binding to its observed `0x1F8010A8` startup blocker and keeps unresolved hard-reset hardware accesses fail-fast.

In native builds, Red Book EOF detection in `spu_render` records one pending `CdlDataEnd` notification under the internal audio lock. The logical game-thread interrupt service dispatches it at `VSync`, native event polling, or critical-section exit, with a null result and without holding the audio lock. Disabled PsyQ interrupts defer delivery; the dispatch guard prevents recursive callback entry. Stopping or starting playback, resuming it, or replacing/removing the ready callback cancels an obsolete notification. Re-registering the same callback preserves it. Games must not lock host audio around their own state. Shared lockstep builds retain their existing direct renderer callback path. This native scheduling contract does not establish physical CD interrupt timing.

`CD_cw` dispatches through the immediate native CD command model and converts successful dispatch to zero, as required by `CdControlB`. `CD_sync` returns that model's completion status. Hardware command timing and interrupt delivery are not modeled by these native entries.

`xport_gte_execute` uses the existing MVMVA engine for its supported commands: `0x480012` transforms V0 with translation, `0x49E012` transforms IR without translation, and `0x486012` transforms V0 without translation for `MulMatrix0`. Other commands remain unsupported. All three preserve signed fixed-point rounding, MAC wrapping and IR saturation in that engine.

Ordinary SPU initialization creates internal native transfer state when no explicit transfer binding exists. `SpuInit` and `SsInit` share that initialization path. Explicit custom or guest bindings retain their existing selection. Native state uses eight-byte addresses, 64-byte DMA blocks, initial address units `0x200`, and a completed initial transfer. `SpuWrite` accepts native source pointers under this internal owner; it reads only `byte_count` bytes, zero-fills the alignment tail, and supports SPU RAM wrapping. Guest sources keep their original rounded-block reads. Internal native transfer completes synchronously; physical DMA timing and interrupt callbacks are not established. Games need no transfer clock, wait callback or state binding. Private size-tagged SPU state includes native transfer fields; bound transfers remain outside the portable guest-only snapshot contract. The common `SpuSetTransferStartAddr` return is an aligned byte address; the reviewed RR original returns eight-byte units. Its caller ignores the result; callers requiring the original return must account for that documented difference.

`SpuInitMalloc(count, records)` uses the caller's aligned native buffer for `(count + 1) * 8` bytes of allocator records. The extra record holds the terminal free span. A nonpositive count, null buffer or unaligned buffer returns zero without replacing the allocator. Positive initialization writes the first record, owns the last index inside SPU state, binds a limit of `count`, and returns `count`. The caller must keep the buffer alive until the next initialization. Native addresses in these records are SPU RAM byte offsets, not game DRAM addresses. `SpuInit` clears the allocator binding and reverb reservation and restores the reviewed SDK default work address `0xF204` in eight-byte units. Use `SpuReserveReverbWorkArea` to reserve it and let mode changes update the allocator reservation. Legacy explicit guest heap bindings remain available for unmigrated consumers. Native record buffers are outside the portable guest-only snapshot contract; size-tagged SPU snapshots include the native last index but do not serialize caller-owned record buffers.

`SpuGetVoiceAttr` must preserve the caller's `voice` and `mask` fields because PsyQ treats `mask` as invalid output. A caller may reuse the same structure with `SpuSetVoiceAttr`; clearing the mask would convert a selective update into an all-fields update.

An ADPCM loop-start block updates the voice repeat-address register. Preserve that register across later selective pitch and volume writes; an end-and-repeat block jumps to the registered address without restarting ADSR.

PsyQ reverb work units and ten 68-byte preset records are immutable defaults in `psx_spu.c`. Ordinary `SpuSetReverbModeParam` and `SpuClearReverbWorkArea` require no game table installation. The exact 40-byte work table and 680-byte preset table match both reviewed `LIBSPU.LIB` distributions; their SHA-256 values are `10fe46fe139ce95f76ad9d3cbc5a6f890df2767a828344f4c44374480930acec` and `795040d1dbeca4a4e6f2727cba671bf98a963f43c68edcb3ddebd0c347d82f4d`. `spu_bind_reverb_presets` remains a legacy override: it copies both inputs into private storage and selects those copies. Keep default SDK tables out of consuming games. Native common SPU attributes use the shared device register base directly; only the shared lockstep branch requires the historical game register-pointer data binding.

The SPU reverb processor uses the existing 32 parameter words and shared SPU RAM work area. It collects voice sends after ADSR and channel volume, collects CD sends after CD routing and volume, and processes the combined stereo input once per output frame before master volume. The wet network runs at 22.05 kHz with 39-tap input and output FIR filters. Disabling reverb stops work-area writes while retaining tail reads and cursor advancement. External input has no native stream source.

Private SPU snapshots include the reverb cursor, phase and FIR histories. This changes the size-tagged serialized state; snapshots written before this addition are rejected rather than partially restored. The public PsyQ ABI is unchanged. `tools/tests/native/spu_reverb.c` exercises the actual processor, original presets, voice and CD routing, disabled writes, work-area wrapping and snapshot continuity; these native checks do not establish hardware equivalence.

With `XPORT_NATIVE_GPU_CD` defined for every translation unit, `xport.h` selects zero GPU/CD address bindings at compile time; the game must omit those five definitions. This opt-in does not change guest or lockstep consumers. Without it, `GetGraphType` uses the required consumer-defined `const uint32 xport_gpu_graph_type_address` in `xport.h` to select its state owner. Zero explicitly selects the shared native rasterizer, which models the standard PS1 GPU and returns type zero without reading guest memory. A nonzero value preserves the unsigned guest-byte read for projects whose translated PsyQ state still lives in DRAM; define that address from the reviewed original entry. This address is distinct from the ResetGraph internal byte flag. Missing data binding still fails at link time. No registration or runtime fallback is added. RR migration and compatibility checks: `RapidRacer-xport/status/audits/native-stage7/graph-native.json`.

`OpenEvent` allocates one of 32 native records and returns an untagged handle in `1..32`; exhaustion returns `-1`. `EnableEvent`, `DisableEvent` and `CloseEvent` validate allocated native handles. `DeliverEvent` matches enabled class/specification records: mode `0x1000` calls the typed native callback, and mode `0x2000` sets a pending event consumed by `TestEvent`. Tagged BIOS handles retain their separate guest-table path. Root-counter IRQ and VBlank delivery use the shared interrupt state, including deferred delivery while interrupts are disabled. Hardware DMA interrupt delivery remains outside the native callback registry contract.

`PadGetState` reads an SDK owner installed through `psx_pad_bind_owner_packets` before using the unbound native connection model. Port selection uses bits `0xF0`, matching the original `_pad_get_port`. Upper control-word bits, a non-self owner link with a busy byte, or a nonzero packet-status byte select the error path: states 2/3 return 1 and state 6 returns 4; other states remain unchanged. Unbound consumers retain the existing active/connected result. This does not change PAD transport or prove serial scheduling. NFSHS complete original-MIPS comparison: `NFSHS-xport/status/pad-state-mips-comparison.json`, 1408 cases covering all 56 instructions of the query and port selector.

`PadSetAct` retains the caller-owned native buffer and the low byte of its length; it does not copy, clamp or read the buffer. The caller keeps the buffer alive while registered and replaces it before freeing it. Null pointers and zero lengths replace the previous registration. `PadSetActPSX` maps a nonzero numeric pointer independently of length and publishes the original address at owner offset `0x28` and the length byte at `0x34` when a numeric owner is bound. Native pointers remain private runtime state and are never narrowed into guest words. These actuator bindings are not serialized by `pad_state_io`. No host rumble output is implemented. NFSHS complete original-MIPS and isolated x86 Release body checks: `NFSHS-xport/status/pad-actuator-mips-comparison.json`, 198 cases covering the wrapper, port selector and `_padSetAct`, plus live buffer mutation/replacement checks.

Declare the required CD data bindings in `xport.h`: `xport_cd_sync_callback_address`, `xport_cd_ready_callback_address`, `xport_cd_status_address` and `xport_cd_setloc_table_address`. Native consumers select `XPORT_NATIVE_GPU_CD` for every translation unit and omit all four definitions (legacy native builds can still define them as zero); use typed `CdSyncCallback`/`CdReadyCallback`; guest consumers keep their reviewed nonzero addresses and unchanged guest paths. Zero Setloc-table binding selects the shared LIBCD command flags and typed callback owner in `CdControlB`. Preliminary Nop/Setloc commands suppress the native sync callback, the primary command restores it, and exhaustion restores it after four attempts, following the original SYS routine. Zero status binding makes `CdStatus` read the existing native controller Nop status under the audio lock: mounted media bit 1, XA reading bit 5 and XA error bit 0. This reuses the controller model; it does not add physical drive timing, seek/lid status or new Red Book status flags. No runtime fallback or registration is added. `CdSyncCallbackPSX`/`CdReadyCallbackPSX` remain guest-only entries and require nonzero guest callback slots. Use `qsortPSX`, `randPSX` and `srandPSX` instead of overriding host libc symbols. `qsortPSX` preserves the original middle-pivot and strict-less-than partition order, including equal keys. The random generator owns the BIOS seed in shared guest memory and returns a signed SDK integer in `0..32767`. `psyq_rand_next(uint32 *seed)` performs the same wrapping recurrence with an explicit native seed owner for LIBC2 consumers. Do not alias a game LIBC2 seed to the BIOS seed; consumer initialization and reseeding remain game-owned.

Explicit reconstructed calls to `__ltdf2`, `__floatsisf`, `__fixsfsi`, `__divsf3`, `__extendsfdf2`, `__fixdfsi`, `__floatsidf` and `__truncdfsf2` use the shared runtime rather than native casts/operators. Their source algorithms preserve PsyQ bit ordering, half-up rounding, variable-shift count masking, saturation and non-IEEE zero/division behavior. `__ltdf2` returns only `-1` or `0` and orders NaN encodings by magnitude; it is not a host three-way comparator. `__fixsfsi(-0.0f)` returns `INT_MIN`. `__floatsisf(INT_MIN)` preserves the original nonterminating normalization loop; do not use this entry to introduce a new integer-conversion policy.


`__mulsf3PSX(uint32, uint32)` accepts and returns encoded binary32 words, matching the original soft-float register carriers. Do not return this result through a native `float` function: x86 x87 quiets signaling NaNs and changes the original result bits. Preserve words across nested arithmetic calls. `psx_float_bits` and `psx_float_value` marshal native numeric values at the boundary; native conversion to a numeric float is not a guarantee of signaling-NaN bit preservation. The multiply uses the original high-part product and separately truncated cross-products, not a native floating-point multiplication or a full 48-bit mantissa product.

`__extendsfdf2` normalizes nonzero binary32 subnormals and rebases every nonzero exponent literally, including exponent `255`; this differs from native infinity/NaN promotion. `__fixdfsi` preserves the original negative-zero result and reports overflow for either sign. `__truncdfsf2` preserves half-up rounding and original modulo-32 underflow shift counts. Both integer-to-float entries retain the original nonterminating normalization for `INT_MIN`.

`__adddf3PSX`, `__muldf3PSX` and `__divdf3PSX` accept and return encoded binary64 values through `uint64` carriers. Keep nested arithmetic encoded; use `psx_double_bits` and `psx_double_value` only at native numeric boundaries, where signaling NaNs may be quieted. Addition preserves signed mantissa alignment and guard-bit-dependent rounding. Multiplication omits the low-21-bit product and truncates each cross-product separately. Division uses the original 54-bit restoring quotient and a 32-bit masked underflow rounding increment; a zero denominator produces the signed all-ones NaN encoding without an error event. Overflow reports `0x22` at points `0x0b`, `0x0d` and `0x0f` respectively. These contracts derive from complete original MIPS, not native IEEE arithmetic. Consumer caller audits remain separate requirements.

The native `LIBMATH` globals `math_errno` and `math_err_point` belong to `psx.c`. `_err_math` writes both before delivering class `0xF4000002`, specification `0x301` for error `0x21` or `0x302` for error `0x22`; other error values deliver no event. Original title-specific DRAM addresses of these SDK globals are not automatically native-symbol aliases. A consumer reading those guest addresses needs an audited mapping. These helpers do not establish equivalence for every reconstructed caller or every possible operand pair.

`VectorNormal` and `VectorNormalS` use the immutable 192-entry PsyQ reciprocal square-root table owned by `src/psx.c`. PsyQ mathematical tables must belong to the shared runtime; never read them through consuming-game DRAM addresses or project table bindings. Zero vectors use coefficient zero and return zero components and length; the GPF operation sets IR0 to zero. This safe native zero contract does not reproduce the original invalid lookup before the reciprocal table or its image-dependent IR0 value.

`psx_vblank_bind_native_counter(counter)` binds a reviewed guest SDK counter to native VBlank delivery while retaining the existing native and BIOS callback registries. Each delivered native VBlank increments the bound word before callbacks; passing zero removes the binding. `psx_vblank_bind_guest` retains its separate eight-entry guest callback-table route, which takes precedence when installed. Consuming games must derive the counter address from their original SDK callback and must not increment it from rendered frames or input polling.

`SsQueueRegisters(voice, attributes)` writes the existing deferred libsnd voice cache. After `SsInit`, bind its numeric values and dirty-byte tables with `xport_libsnd_bind_voice_volume`. `SndRegisterAttr` follows PsyQ's seven-halfword layout: left/right volume, pitch, mask, address units, ADSR1, ADSR2. `gpu_decode_tim_body(src, size, image)` is a bounded native TIM codec in `psx_gpu.c`. The input starts at the mode word after the four-byte TIM magic; full-file callers validate magic `0x10` themselves. `GpuTimImage` owns rectangle values and borrows pixel/CLUT pointers from the input for its lifetime. The final pixel block length word is ignored, as in the existing SDK-style readers; actual pixel extent is derived from rectangle dimensions. This also accepts files whose final length word excludes the block header. Pixel payloads may have two-byte padding; no pixel-format reinterpretation or allocation occurs. This codec is not an implementation of the stateful PsyQ `OpenTIM`/`ReadTIM` ABI. RR evidence: `RapidRacer-xport/status/audits/native-stage7/bounded-tim.json`.

Valid voices require a bound table and compare signed halfwords at offsets `24`, `20` and `14` in that order against the arithmetic `bank_program >> 8`, its low byte and the signed16 note. ## Windows Release runtime contract

- Release uses ordinary `fseek`/`ftell`; native disc/stream files and offsets must fit signed 32-bit positions
- Windows Release omits separate resource `ferror` checks and PC-file `fflush`; reads retain their returned byte counts, and closing a stream commits buffered writes
- `--collect` writes one normalized resource-path buffer with `fwrite`
- Debug retains resource error checks and PC-file flushing
- Release disables compiler stack probes with `/Gs2147483647`; do not provide an empty `__chkstk` implementation
- Before accepting a probe-free Release, check generated code for remaining probes and audit large or dynamic stack allocations; move page-sized buffers to heap or persistent storage when necessary

SPU rendering and XA sector decoding use private transient static workspaces under the existing audio lock. They are not serialized state. Clear render sends for each chunk; never allocate the 37632-byte XA decode workspace on an unprobed thread stack.

## Windows Release CRT

`src/platform/win/xcrt.c` is the single custom runtime for Release|Win32. The canonical Windows template and RapidRacer enable it by default. Debug keeps its standard CRT. Build the existing Release configuration with `/p:UseXcrt=false` to exclude xcrt and restore standard CRT linking; do not add configurations, headers or assembly files.

Enabled: `/NODEFAULTLIB`, `/ENTRY:WinMainCRTStartup`, `/Zl`, kernel32/user32/gdi32/winmm/shlwapi imports only. Release disables C++ exceptions, RTTI, GS, SDL, CFG, ASLR/relocation, manifest, SAFESEH and stack probing; omits frame pointers and enables COMDAT/ref elimination. DEP remains enabled. Read-only data merges into `.text`; retain `.data` separately to avoid expanding zero-initialized memory on disk. Large Release automatic allocations must move to suitable owned storage before stack probing can remain disabled.

Runtime contracts: process-heap allocation; WinAPI memory/string helpers implemented in C; x86 integer arithmetic helpers and non-unwinding setjmp/longjmp in inline assembly; minimal WinMain startup without argc/argv parsing or environment lookup; strtoul; unbuffered native files. `FILE *` carries a HANDLE and must never be dereferenced or passed to another CRT. File positions use signed32 fseek/ftell and SetFilePointer; files must be smaller than 2 GiB. Append uses FILE_APPEND_DATA, including after seeks. Text modes retain raw bytes without CRLF translation. Serialize compound operations on a shared file handle in the caller.

Only snprintf is provided for formatting resource paths and names; it directly calls wvnsprintfA with the supplied capacity and va_list. It uses WinAPI format syntax and truncation/error return semantics, without C99 extensions or float formatting. No remove/rename/vsnprintf, printf/scanf, standard streams, fprintf/vfprintf, sprintf/vsprintf, fgetc/fputc/fputs, fflush or 64-bit seek APIs. Console diagnostics and journal/trace-stream helpers are Debug-only. Resource reads retain size bounds; additional read-error diagnostics are Debug-only. `--collect` writes normalized paths using fwrite.

Windows `XPORT_AUDIO_OUTPUT` and `XPORT_AUDIO_BACKEND` are read only under `_DEBUG`. Release uses ordinary audio output; headless execution uses the null sink.

Debug and Release WinMain check `--collect` directly with strstr on the unparsed command string. Release does not build argc/argv. Both modes check --lockstep-replay and --lockstep-boundary-selftest directly with strstr; LOCKSTEP_DEBUG is a Debug-only build flag; other builds ignore these switches. Windows has no platform argument array or executable-path buffer. xport_arg_count/xport_arg_values are removed from the shared API; consuming projects own migration of any former callers.

XCRT startup initializes the process heap and calls WinMain with GetModuleHandleA(NULL), NULL, GetCommandLineA() and SW_SHOWDEFAULT, then ExitProcess. No GetStartupInfoA, environment block, command copying or executable-name parsing. XPORT_RASTERIZE/XPORT_VERIFY_VRAM environment overrides are Debug-only; Release headless rasterization is disabled.

MDEC floor rounding uses arithmetic shifts, including negative values, in IDCT and YUV conversion. Do not implement division by powers of two through general 64-bit division helpers in these hot paths. XCRT integer division is shared inline assembly: hardware DIV for 64/32, a 32-step remainder loop for a wide divisor.

Windows Release template uses /O1 and /Gw. Collect output uses ../src/platform/web/collect.log relative to the native working directory (bin). abort terminates pseudo-handle (HANDLE)-1. No GetLastError/SetLastError, GetCurrentProcess, GetModuleFileNameA, VirtualQuery or UpdateWindow calls. Presentation owns drawing; there is no custom WM_PAINT handler. Windows xport_memory_readable performs only numeric native-address/nonempty/overflow checks, not OS page validation; callers own pointer validity. Lockstep publication opens an existing named mapping first and accepts it only when reuse is requested, otherwise creates a mapping.

Canonical Windows template and RapidRacer share Debug/Release compiler, linker and xcrt settings. Debug enables XPORT_ENABLE_AUDIT and XPORT_MEMORY_DIAGNOSTICS; Release disables function markers. Keep game-specific bindings such as XPORT_NATIVE_GPU_CD in the consuming project, not the template.
