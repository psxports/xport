# Web builds

Windows web builds do not require elevation. Emscripten can move temporary runtime files into `DIST_DIR` with a protected DACL that retains temporary-directory access rules. After linking, the shared Makefile runs `tools/web_output_permissions.py --runtime OUTPUT` on runtime JS, WASM and existing source maps. The packager applies the same check to its exact published output set, including packages, manifests, asset JS, HTML, icons and music. A protected generated file must inherit its destination directory policy before publication succeeds. The helper enables inheritance only; it does not change ownership, remove explicit access rules, grant named users access, elevate, or modify source files and unrelated output files. ACL inspection or repair failure fails the build. Non-Windows hosts perform no ACL changes. Verify from tools with `python -B -m unittest tests.test_web_output_permissions tests.test_web_packager -v`; tests cover private DACL recovery, unchanged bytes, unrelated-file isolation, idempotence and a real bundled-Emscripten link.

The packager accepts normalized `DATA/` entries from `collect.log` for startup selection and ignores all other namespaces, including MUSIC, executable self-reads and diagnostic inputs. Missing `DATA/` entries still fail validation; do not reinterpret arbitrary logged paths as relative DATA paths.

All maintained consumer and shared-runtime C file opens, including diagnostic reads and writes, must call `xport_fopen` with the original path/mode. Do not redefine `fopen` with a macro or duplicate collection in a project. Only platform `xport_fopen` implementations and opening the collection log itself may use libc `fopen`. Windows Debug records successful unique read opens only while `--collect` is enabled; writes do not enter the log. Release has no collection code and ignores the switch. Web performs demand preparation for reads before the underlying open. Read resource payloads through `xport_fread(data, size, count, stream)`; the shared wrapper retains `fread` element-count semantics. Paths and demand loading belong to `xport_fopen`, not the read wrapper.

Windows Debug recognizes the exact `--collect` command-line argument, including a quoted argument. Substrings such as `--collective` or `--option=--collect` do not enable collection. `xport_main` has no argument array. Running `[SHORT]_debug.exe --collect` follows the same game entry as running without the switch. Release ignores `--collect` and never opens or resets the collection log.

The collector records only successful `DATA/` and `MUSIC/` reads and selects the first namespace component in the host path. It never records executable, diagnostic or other non-resource reads. The packager accepts a historical path emitted by the former last-`DATA/` collector only when its suffix identifies exactly one current `bin/DATA` file; zero or multiple matches fail validation.

Install the pinned SDK without changing the machine-wide Emscripten installation:

`[XPORT_ROOT]\tools\prepare.bat --web`

The SDK is stored in `[XPORT_ROOT]/tools/emsdk`. The shared Makefile invokes its Python, `emcc.py`, and `.emscripten` file by absolute path; it does not read `emcc` from `PATH`.

The build process requires write permission to `[XPORT_ROOT]/tools/emsdk/upstream/emscripten/cache` in addition to `DIST_DIR`. Emscripten creates `cache.lock` there and may generate missing system libraries during compilation or linking. In a restricted sandbox, grant the build command access to that SDK cache directory. If access is denied, Emscripten's file-lock retry loop can look like a stalled Asyncify link: `emcc.py` remains idle, `wasm-ld` never starts, no output is created, and `cache.lock` may remain absent. Run with `EMCC_DEBUG=1` to distinguish this permission failure from an occupied lock or a slow transform.

A consuming project owns `src/platform/web/Makefile` and supplies `PROJECT_ROOT`, `SHORT_NAME`, `FULL_NAME`, `APP_SOURCES`, and `APP_DEFINES` before including `[XPORT_ROOT]/src/platform/web/Makefile`. The shared HTML template sets the browser tab title to `[FULL_NAME] (xport)`, preserving spaces and HTML-escaping the supplied full name. The web runtime ignores per-frame native titles so `SHORT_NAME`, FPS counters and diagnostic captions cannot overwrite the browser tab title. Rebuild and publish the web output to update an existing deployment. Build from that directory with `make CONFIG=Debug` or `make CONFIG=Release`. Normal builds must retain the shared `DIST_DIR` default, `../../../../.github/site/$(SHORT_NAME)`, resolved from this build directory; for a project at `C:/Projects/xports/PROJECT`, this publishes to `C:/Projects/xports/.github/site/SHORT_NAME`. Do not redirect normal deployable output into `_build/web`; that directory holds intermediates. Override `DIST_DIR` only for an explicitly requested alternate destination or an isolated test. Before reporting a build complete, verify that the resolved publication directory contains `index.html`, the current runtime JS/WASM, and its referenced asset manifest and packages.

The web packager uses the consuming project's `src/platform/win/icon.ico` as its browser tab icon. Copy the bytes unchanged to `DIST_DIR/xport-icon-HASH.ico` and render a relative `<link rel="icon" type="image/x-icon">` in the shared HTML template. The content hash changes the URL when the icon changes; remove obsolete `xport-icon-*.ico` files from output. A project without the local icon emits no favicon link and no fallback icon. Publish the generated HTML and icon together; changing the source icon requires repackaging and deployment.

The shared HTML template renders Open Graph and compact Twitter Card (`twitter:card="summary"`) metadata during packaging: title `[FULL_NAME] (xport)`, page URL `https://psxports.to/[SHORT_NAME]/` and the root `cover.png` through an absolute `raw.githubusercontent.com/OWNER/REPOSITORY/BRANCH/cover.png` URL. Read `github.repository` (`OWNER/REPOSITORY`) and `github.branch` exclusively from `xport-project.json`. Startup records the repository default branch during its GitHub step. Existing projects must declare both fields; do not read Git remotes or derive repository identity from the game name or directory. Packaging performs no network lookup and does not copy the cover into web output. The cover must be committed to the selected branch of the public GitHub repository. If the config lacks repository or branch metadata, omit image tags and emit a text-only summary. Republish generated HTML after metadata changes; external services can cache previews.

Set `WEB_PACKAGER_FLAGS` to repeated `--extra-file SOURCE TARGET` arguments only for runtime bootstrap inputs outside `bin/DATA`, such as an original executable used to initialize guest DRAM. The source must exist. `TARGET` is a virtual filesystem path relative to `/` and cannot contain `..` or a drive prefix; the packager adds the leading slash. Extra files remain demand-loaded and do not enter the collected startup packages unless the collection log names their target under `DATA/`.

Set `WEB_EXCLUDE_FILES` before including the shared Makefile to a whitespace-separated list of virtual paths or glob patterns, for example `WEB_EXCLUDE_FILES := DATA/MOVIES/*.XA DATA/INTRO.BIN MUSIC/1.WAV`. The Makefile forwards each entry as a quoted `--exclude` argument to the packager. Paths are relative to the virtual filesystem root, not the project directory; a leading slash is optional. Matching is case-insensitive, backslashes normalize to slashes, and `*` matches across directory separators. Empty paths, parent traversal and drive prefixes fail validation. Makefile list entries cannot contain whitespace. Exclusions apply to DATA, extra-file virtual targets and streamed MUSIC, including collected startup files and uniquely resolved historical collection paths. They do not modify `collect.log` or source files. Missing non-excluded collected DATA still fails validation. STR files are excluded by default. A consumer can explicitly select extracted STR assets with repeated `--include-str VIRTUAL_PATH_GLOB` arguments in `WEB_PACKAGER_FLAGS`; matching uses the same normalized virtual-path rules. Explicit `--exclude` patterns still take priority. These settings exclude packaged resources, not C/C++ compilation units; projects control those through `APP_SOURCES`.

The shared Makefile compiles every source into a distinct object below `[PROJECT_ROOT]/_build/web/CONFIG`, stores dependency files and the link response file in the same intermediate directory, and writes only deployable artifacts to `DIST_DIR`. Debug and Release objects are kept separate, Asyncify and the other `-s` linker settings are passed only during the final link, command-line length remains bounded, and an ordinary rebuild recompiles only sources whose dependencies changed. Consumers add compiler options to `COMMON_FLAGS` and linker-only options to `LINK_FLAGS`.

Shared Web sources include `psx_font.c` for native PsyQ font APIs. Native-state consumers retain their existing `XPORT_NATIVE_GPU_CD` definition in `APP_DEFINES`; consumers with guest GPU/CD bindings omit it. Release consumers that disable provenance markers can add `XPORT_DISABLE_FUNCTION_MARKERS` only to their Release definitions.

All Web configurations compile with `-fno-strict-aliasing -fwrapv`. Reconstructed PS1 code aliases shared guest memory through different scalar and packet types and requires 32-bit two's-complement signed overflow; Release optimization cannot assume either behavior is absent.

PsyQ wrappers that receive a pointer returned by `psx_addr` must recover its guest DRAM offset before calling an address-based shared helper. Never cast that pointer to `uint32` and pass it back through `psx_addr`; low WebAssembly linear-memory pointers can alias valid physical PS1 addresses and redirect the access to unrelated DRAM.

The shared `psx.h` runtime contract retains C linkage when included by C++ translation units. Consumers compiling reconstructed C as C++ must use the shared timer entrypoints and remove duplicate local definitions; do not replace unresolved runtime symbols with success stubs.

Shared runtime callback implementations also support C++ compilation. Recover typed callback context pointers explicitly from `void *`; do not weaken compiler diagnostics to permit implicit C-only conversions.

The build writes `index.html`, `xport-runtime.js`, `xport-runtime.wasm`, hashed asset/manifest scripts, gzip-compressed `xport-NN-HASH.data` packages, and hashed `MUSIC/*.WAV` tracks to the relative `../../../../.github/site/SHORT_NAME` directory. Every deployed data/music file must fit 25 MiB. DATA is mounted at `/DATA`; MUSIC is streamed separately. STR files are excluded from Web packages and `collect.log` startup selection unless explicitly selected by `--include-str`; selected collected files enter the startup packages. Serve over HTTP on localhost or HTTPS in production; `file://` is unsupported. The browser needs `DecompressionStream('gzip')`, WebAssembly and Asyncify support supplied by the build.

Run the Windows Debug executable `[SHORT]_debug.exe --collect` from its normal `bin` working directory. At startup, open `../src/platform/web/collect.log` with `w` to discard the previous profile and reset the in-memory hash count. A launch without the switch leaves the log untouched. A missing/unwritable log directory fails collection startup. Successful read-only opens through `xport_fopen` record normalized `DATA/` and `MUSIC/` paths in first-open order; failed opens, writes and update modes such as `r+` are excluded. Keep a fixed array of 1024 32-bit FNV-1a hashes, compared linearly under a dedicated critical section. Hash normalized separators and ASCII case-insensitive names, preserve the first path spelling in the log and remove PSX `;version` suffixes. A hash match suppresses the line, including repeated size queries. At capacity, skip new paths without eviction or duplicate output; normal file opens still succeed. Paths longer than `MAX_PATH` are skipped rather than truncated into another name. Flush each unique line. Route consuming projects' DATA reads through `xport_fopen`; direct libc opens bypass both collection and web demand loading. Shared music and platform file helpers already use it.

Collect startup and the beginning of the first level for every selectable starting character. The packager deduplicates DATA paths in first-seen order into startup packages and ignores MUSIC and STR lines not selected by `--include-str`. It rejects unknown collected DATA paths. Collected files retain first-seen order and span as many startup packages as required, each bounded by 25 MiB minus compression overhead allowance. The manifest records `startupPackages` and `startupFiles`; all listed packages load and all listed files mount before startup completes. An absent/empty log makes package zero empty and loads everything on demand. Each Debug launch with `--collect` starts a fresh profile; collect all desired scenarios in that one process. Normal launches without `--collect` and all Release launches leave the log untouched.

Only the manifest startup packages are mandatory before Start and contain only the deduplicated collected payload. An empty collection retains an empty package zero. Older manifests without startup lists retain the package-zero behavior. Remaining files are ordered by virtual path and packed continuously up to the 25 MiB limit without directory boundaries; a file larger than the payload limit can span packages. On the first read open, Asyncify suspends game execution while the loader checks IndexedDB, fetches missing packages, verifies SHA-256, decompresses, and mounts the requested file without dimming the running game or showing download progress. A loading overlay appears only after network/checksum failure and offers click-to-retry. Unvisited packages are never downloaded automatically. File-size queries through `fopen` also trigger loading in this minimal implementation.

Content-hashed URLs prevent stale CDN data from matching new metadata. IndexedDB keys remain `data/N` and `music/track`; changed content replaces the old value, and keys absent from the current manifest are deleted. Migration removes the former `XPORT_PRELOAD_CACHE_SHORT_NAME` database. Cache failures fall back to networking. Upload the whole generated directory together and revalidate `index.html`. A query string on `index.html` is propagated to runtime JS and WASM, so a new build query invalidates both runtime resources during local or hosted testing.

MUSIC retains IMA ADPCM WAV and the SPU mixer. The selected track starts after up to 128 KiB arrives; the remaining bytes download during playback and the complete, verified track is persisted in IndexedDB. No other tracks are prefetched. Missing ADPCM blocks temporarily silence music without ending the track or stopping sound effects; playback resumes from the same position when data arrives. Stop/replacement releases the WASM association, so ongoing downloads never write into freed WASM memory. An already requested download can finish caching after the track stops. Interrupted downloads are not persisted or resumed; the next request starts again. This reduces startup latency, not the eventual size of a fully downloaded track, and allocates full-track buffers in memory.

Verification: run `python -B -m unittest tests.test_web_packager` from `tools`; run the SDK's Node executable on `tools/tests/web_assets_test.cjs`; run `tools/tests/web_input_smoke.cjs PATH_TO_SITE [RUNTIME_NAME]` against a freshly built Release site to prove that the exported touch setter reaches `xport_input_read`. Consuming projects own their game-specific runtime smoke; AA provides `tools/web_runtime_smoke.cjs PATH_TO_SITE_AA`. It executes the actual Release WASM with simulated browser I/O, starts an uncollected stage, checks demand-package requests and delayed MUSIC startup. It is not a visual browser or audio-device test. Run `python -B -m unittest tests.test_native_collect` from `tools` to verify Debug collection, unique paths, the 1024-entry limit, fresh profiles and the Release no-collection path. These compile isolated runtime checks without building a game.

The shared build adapts legacy function-pointer signatures and the runtime yields through Asyncify from `xport_poll` and frame waits. It presents the software framebuffer through the shader-only WebGL 2.0 VID renderer, converts SPU output from 44.1 kHz to the browser audio rate through an AudioWorklet, and supports keyboard without a focus outline around the game, standard gamepads in any connected browser slot, touch controls, a fullscreen overlay button, and Shift+F. OG presentation preserves the 4:3 viewport inside the full-size canvas; HD uses the full drawable. Fullscreen hides the mouse cursor. Audio initialization is optional and cannot block game startup.

Keyboard and connected gamepad port ownership follows `LIBRARY.md`: WASD/IJKL on P1; arrows/NumPad on P2; NumPad Enter/Plus are P2 Start/Select. Key handling uses `KeyboardEvent.code`; focus loss clears both keyboard masks. The first two connected browser gamepads map independently to P1/P2, skipping absent or disconnected slots. Touch and input overrides affect P1 only. Run `python -B -m unittest tests.test_pad_ports -v` from `tools` after shared input changes.

Web field waits recheck `xport_frame()` after every `emscripten_sleep(1)` until the target field is reached. `platform_poll_field` records the field observed after the last browser yield. `xport_poll` yields only when the current field differs; animation-frame and field waits update the same marker to avoid an extra clamped `sleep(0)` immediately afterward. The initial marker is `UINT64_MAX` so the first poll yields even in field zero. Whole-frame raster catch-up is enabled for every Web build. Common GPU policy, preserved transfers and readback limits are in `LIBRARY.md`.

On coarse-pointer devices, the touch overlay covers the complete browser viewport rather than the 4:3 game rectangle. It exposes D-pad, square, triangle, cross, circle, Start, Select, L1, L2, R1 and R2 simultaneously. Non-passive touch handlers suppress browser gestures before publishing the complete pressed mask directly to the exported C setter; native HTML buttons and pointer capture are forbidden for game controls. Multi-touch, sliding between buttons, touch cancellation, window blur and page hiding must update or clear the retained mask without synthesizing clicks or invoking filesystem/audio work. Non-touch pointers use the pointer-event fallback.

The Start click resumes `AudioContext` before asynchronous setup consumes browser user activation. The runtime prefers `AudioWorklet` and falls back to `ScriptProcessorNode` when worklets are unavailable. Both paths bound their pending block queues and discard stale queued blocks after a producer burst instead of allowing multi-second latency to accumulate. Initialization failures remain non-blocking but are exposed as `Module.xportAudioError` and a console error instead of being silently discarded.

Mixed-language consumers can list `.c` and `.cpp`/`.cc`/`.cxx` files in `APP_SOURCES`. Shared C sources retain `C_FLAGS=-std=c11`; C++ sources use the bundled `em++.py` with `CXX_FLAGS=-std=c++17`. Consumers may override these language flags independently. Linking selects `em++` when any C++ unit is present, otherwise `emcc`; existing C-only consumers need no migration. Game C++ files must use real C++ extensions. Run `python -B -m unittest tests.test_web_mixed_languages -v` from `tools`; it builds and executes both a C-only app and a mixed app using C linkage, virtual dispatch, vector and unique_ptr through the actual shared Makefile.

Keep JavaScript-specific operators inside `EM_JS`/`EM_ASYNC_JS` bodies intact. Protect multiline bodies containing arrow functions or strict equality with `// clang-format off` and `// clang-format on`; a C formatter can split `=>`, `===` and `!==` into invalid tokens. Parse the generated runtime and run the actual WASM after formatting changes.

Size the consuming project's WASM stack for measured native call frames. Emscripten's default 64 KiB can be smaller than a native PsyQ VAB staging record. Set a justified `-sSTACK_SIZE=BYTES` through `LINK_FLAGS +=` after the shared Makefile include and retain `-sSTACK_OVERFLOW_CHECK=2`; record the overflowing owner and actual browser diagnostic before changing the size. A successful link alone does not validate startup, resource loading or audio.

## Prepared video assets

Startup prepares supported STR movies in `bin/VIDEO` through `X convert_video`; inputs, reviewed frame rates, supported layouts and verification are defined in [STARTUP.md#str-video-preparation](STARTUP.md#str-video-preparation). This is offline asset preparation only. The current web packager/runtime does not yet publish or play these MP4 assets. Keep original sources and MDEC support; do not remove archive payloads or substitute a movie for an isolated MDEC texture/block. The future AP_WEB adapter must identify registered streams explicitly and return requested frame buffers through the compatible game API, preserving synchronization/callback contracts.
