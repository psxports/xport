# Fullscreen movies and registered Web video

## Web movie policy

- MP4/WebCodecs is required for supported standalone movies in a Web deliverable, for both fullscreen playback and video textures. This is part of Web integration during decompilation/coverage, not an optional enhancement. Native playback retains the original extracted STR/MDEC path
- Inventory movie consumers and standalone versus embedded storage; review FPS, source-sector timing and audio. Prepare verified MP4 outputs with `X convert_video`, register their exact source paths in `video.sources`, and set `video.web_enabled: true` plus the reviewed `video.sector_rate`. The flag is explicit implementation configuration, not permission to omit the required Web path
- Continue passing the original logical `DATA/*.STR` identity to `xport_fmv_*`. The Web registry resolves that identity to `VIDEO/*.mp4`; a STR name in a call or manifest key does not mean the browser downloads STR. Do not change these keys to guessed MP4 output filenames
- Never use `--include-str`, disabled registration or a raw STR fallback to satisfy playback of a supported standalone movie in Web. Leave streams embedded in level/archive data and isolated MDEC texture blocks in place; unsupported standalone formats require a recorded concrete gap rather than a silent fallback or a completed-playback claim
- Before accepting the Web deliverable, verify registered MP4 files and runtime loading, absence of substituted STR payloads in DATA packages/network requests, real decoded frames/audio and game-return or in-scene texture behavior. A conversion receipt, filename or successful build alone is insufficient

## Fullscreen player

- Add `src/xport_fmv.c` to the consumer's native project. The canonical Windows scaffold and shared Web Makefile include it
- Call `xport_fmv_play("DATA/INTRO.STR")` from a game-specific movie boundary. Return values: `1` EOF, `2` Cross/Start press, `-1` error. Handle failure explicitly
- For a game-defined source-frame limit or repeat, call `xport_fmv_play_range(path, last_frame, repeat)`. A nonzero `last_frame` includes the first delivered frame whose original source number reaches that limit; zero selects physical EOF. Physical EOF can end the pass earlier. A nonzero `repeat` restarts the same file at either boundary until interruption or failure; the shared player retains ownership of the loop and saved display/audio/callback state across repeats. Return `1` means a completed nonrepeating pass, `2` interruption, `-1` error. Use original source numbers, including Web `XportFmvFrame.number`, rather than a presentation counter
- For game-owned composition, pass `XportFmvPresentation` to `xport_fmv_play_presented(path, last_frame, repeat, presentation)`. Zero `width`/`height` retain intrinsic dimensions; nonzero values set the display canvas, bounded by640x256 with width divisible by16. `video_x`/`video_y` are nonnegative pixel offsets. The decoded aligned image must fit; `bottom_rows` appends zero rows within the canvas before composition. Pages use the aligned canvas height. Screen offsets/dimensions and `interlace` are explicit native `DISPENV` fields
- `frame(context, number)` runs once before decoding/uploading each delivered source frame. `strip(context, word_x, rgb, rows)` runs before each16-pixel upload; `word_x` is the absolute VRAM word x-coordinate, `rgb` holds `rows*48` writable bytes with48-byte row pitch. Both callbacks return positive on success and zero/negative on failure. Buffers are borrowed only during the callback. Hooks must not start another player/event loop or replace shared decoder/transport/callback ownership
- A supplied presentation defines skip policy explicitly: `controllers` bit0/1 select controller0/1, `skip_buttons` is a `PAD*` mask and `skip_held` selects held state instead of new edges. Zero masks disable that input source. Passing no presentation retains controller0 new Cross/Start presses. The synchronous call copies the presentation; `context` must remain valid until return
- `tick(context)` runs once per owned event/presentation iteration, including buffering and final-frame presentation, before the skip test. Return positive to continue and zero/negative to fail. Keep game fades here; a source-frame callback runs only when another video frame arrives
- After a completed nonrepeating pass with at least one frame, `finish(context, 0)` runs once after the last frame is presented. Return zero to finish, negative to fail or positive to begin a final-frame phase. The service then stops native source reading or pauses the Web session and calls `finish(context, step)` with successive steps starting at1 inside its existing input/event/presentation loop. Each step may update VRAM/display and returns positive to continue, zero after its final presentation or negative to fail. Input interruption exits without further finish calls. No finish hook runs between repeats, on an empty pass, on failure or on a skip
- `xport_fmv_ready()` is true only while the synchronous player is active and has decoded/uploaded at least one valid frame. It remains true during final-frame presentation and between repeats, and becomes false after cleanup. It does not report a drive status or make initial Web buffering ready
- The player owns its message, input and presentation loop. It recognizes new Cross/Start presses, including during initial Web buffering. If any selected skip button is held at entry, default edge skipping remains blocked until all selected skip buttons on all selected controllers are released; the following press skips the movie. Pressing Start while Cross is still held does not bypass the release requirement. Explicit `skip_held` opts out of this requirement
- The synchronous player has no public stop function. Its owned loop handles interruption and window-close events. The player temporarily chains the current `xport_set_cleanup` callback so host shutdown closes the movie before invoking consumer cleanup
- Native playback uses direct-file STR/MDEC/XA. Web playback requires an explicitly registered MP4 source; missing registration, unsupported codecs and transport/decode errors return failure. Do not fall back to a missing STR or suppress the error
- RGB24 output uses 16-pixel VRAM strips and two pages. Supported dimensions are positive, width divisible by16 and at most640, height at most256. Both aligned pages must fit1024x512 VRAM. P2 verification uses320x240
- Preserve current display environment/mask, raster selection, interrupt/CD/MDEC callbacks and common SPU master/CD volume/mix/reverb across playback. Do not store game globals in the player
- The caller owns game-specific HD history reset, render-cache invalidation and simulation-cursor reseeding after return. The player never advances game logic
- Present follows the existing swap interval/rAF contract. Do not add a separate FPS sleep. Original CD completion sectors establish video timing; decoded CD PCM is the Web audio/video master clock

## Native audio remainder after synchronous playback

- Include `psx_xa.h` for `XportFmvAudioRemainder`. After synchronous `xport_fmv_play`, `xport_fmv_play_range` or `xport_fmv_play_presented` returns `1`, call `xport_fmv_take_audio(&audio)` on the same main thread. It returns `1` once for an available native XA remainder; `0` means unavailable, already taken, null output or playback still active. Failure leaves the output unchanged
- The result contains linear interleaved signed 16-bit stereo PCM at44100Hz (`pcm_frames`, at most32768), the existing `XaState` after those samples were decoded, XA file/channel identity and `next_sector` relative to the mounted raw2352-byte movie file. Consume all returned PCM before decoding the next sector with that state. Do not interpret `next_sector` as the audible position or seek past the pending PCM
- The player captures and detaches XA under the existing audio lock at successful nonrepeating completion, before native Stop/unmount and before the optional final-frame hook. PCM remains held during that hook; it does not continue playing in the shared source. A skip/failure during the hook discards it. No intermediate repeat captures a remainder
- A new valid synchronous playback attempt, `xport_fmv_discard_audio()`, SPU initialization, SPU state loading or CD checkpoint restoration invalidates an unclaimed remainder. This transient host handoff is excluded from serialized state; checkpoint layouts remain unchanged. The cache resides in the existing SPU owner and does not retain a file, controller or decoder loop
- WebCodecs playback currently returns no XA remainder. A caller requiring continuation must handle `0` as an unsupported or failed handoff; do not substitute a frame/time-based restart
- The caller owns continuation source validation, decoder-state adoption and pending PCM playback. Skip/error paths must not resume. Native build, playback, skip, reset and audible continuity checks remain required at the consumer's verification gate

## Web frame service

- `src/xport.h` declares the registered Web service under `AP_WEB`. `xport_fmv_open` begins loading and returns immediately; `xport_fmv_next` returns `0` waiting, `1` RGB24 plus `XportFmvFrame` metadata (width, height and original source frame number), `2` EOF, `-1` error. `xport_fmv_close` detaches the PCM provider and invalidates the session. Use this family directly; do not add compatibility aliases
- `xport_fmv_pause(paused)` freezes frame delivery, PCM consumption and the media clock without discarding bounded decoded queues. Resume retains the current source position without elapsed-wall-time catch-up. Close/reopen resets pause state. This controls the low-level Web session; the synchronous fullscreen player has no public stop API
- In-scene callers own their event loop, texture/VRAM upload, pause boundary, original frame-number loop limits and spatial CD balance. Open only explicitly registered standalone movies; keep unregistered embedded streams and ordinary `DecDCT*` consumers on their existing MDEC path. Native callers retain STR/MDEC unless a native backend is separately provided
- JavaScript `Module.xportVideoOpen` resolves after initial video/audio priming, not whole-file download. The C bridge starts this promise without suspending the player's input/present loop
- `video.js` selects exact normalized DATA source registrations. It never intercepts `DecDCT*`, infers a movie from dimensions, or substitutes isolated MDEC texture blocks
- `Module.xportLoadVideo(source, entry)` supplies a full-capacity byte array and a verified contiguous `received` prefix. Submit a sample only when `offset+size <= received`. Subscribe to transport updates and decoder output/dequeue; unsubscribe on close
- Transport verifies each256KiB chunk before exposing it. Only complete full-hash-verified movies enter the shared IndexedDB asset cache. Closing playback permits the already requested load to finish caching; generation guards prevent late decoder or WASM access
- Keep at most4 submitted-or-decoded video frames. Audio decode requests are bounded; retain at most approximately one second of queued PCM plus bounded in-flight packets and one packet for resampling neighbors. Close every VideoFrame/AudioData, including stale callbacks
- Convert AAC output to44100Hz stereo with a continuous sample timeline, neighboring packet samples and explicit priming/trailing trimming. Feed it through `spu_set_cd_pcm_source`; the existing SPU CD routing, volume, dry mix and reverb remain authoritative. Do not use a DOM video/audio overlay
- Missing data stalls the movie media clock while ordinary event handling and SFX processing continue. Decode speed does not advance game time

## Verification

- `python -B -m unittest tests.test_web_video -v` from `tools` checks decoder bounds, incomplete-prefix startup, RGB/PCM delivery, resampling, close/reopen, silent clips and failures using Node mocks. It does not establish browser support, pixels or audible acceptance
- `node tools/tests/web_video_transport_test.cjs` checks verified prefixes, deduplication, unsubscribe, IndexedDB completion/cache and failure/retry. Existing DATA/MUSIC transport tests must continue to pass
- Exercise actual VideoDecoder/AudioDecoder in a browser with a delayed MP4 body. Require initial frames and PCM while `received < size` and `complete == false`; reopen from complete cache without a network request; close/reopen without stale output
- Run the consumer's native STR and game-return checks and build Debug/Release. Verify the Web game movie, skip, return to gameplay and presentation controls. Record user listening separately from decoded PCM or muted native captures
- P2 evidence: `Pandemonium2-xport/status/enhance/webcodecs-coordination.json`. Its browser transport fixture is `tools/serve_video_check.py`; the current report distinguishes low-level RGB/PCM testing from game/SPU and listening acceptance
