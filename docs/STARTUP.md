# Project startup, setup, analysis and planning

Normative extension of `../AGENTS.md`. Read this file only when that contract routes the current task here.

`startup FULL_NAME SHORT_NAME` initializes the current Codex project directory. Both names are user input; never infer or normalize `SHORT_NAME`. The legacy phrase `Prepare project FULL_NAME (SHORT_NAME) according to STARTUP.md` is equivalent.

## Agent protocol

1. Resolve the current project directory and shared `[XPORT_ROOT]`. If `xport-project.json` exists, stop with `STARTUP_ALREADY_INITIALIZED` before creating a goal or changing files.
2. Verify the supervisor's dependency order before dispatch: original extraction and reviewed game-icon preparation must precede its first native build. Follow [Mandatory game icon before native builds](#mandatory-game-icon-before-native-builds). If the installed supervisor still builds the default scaffold before extracting the disc, bring that ordering into compliance before starting it; a documentation requirement alone does not enforce the running Python workflow. Then create one durable goal for startup and launch exactly one supervisor:

   ```powershell
   python -B [XPORT_ROOT]/tools/startup.py start --project PROJECT_ROOT --name "FULL_NAME" --short-name SHORT_NAME
   ```

3. Treat the returned JSON as authoritative. The command returns after dispatching a detached worker; use revision-aware `status` while work continues. Windows worker liveness uses the native process exit status so `status` neither duplicates an active detached worker nor retains a stale PID. Do not reproduce deterministic steps with individual scripts or inspect full logs unless it returns `failed`.
4. On `attention`, review the bounded context and prefilled proposal, then submit the reusable response once. On `failed`, fix the stated cause and invoke `retry` with the exact failed revision; it deduplicates compact diagnostics and removes only failed generated runs.
5. Complete the goal only when the supervisor returns `complete`. Original images, accepted exports and unrelated user work remain immutable.

Compact observation and submission:

On Windows a worker with `XPORT_WINDOWS_DESKTOP` uses the validated value through the shared native `CreateProcessW` launcher and hides its startup window; Python's limited `subprocess.STARTUPINFO` does not pass `lpDesktop`. Without that variable the existing detached console launch remains the default. For a requested hidden desktop, the caller must create and retain that desktop until the worker starts, and pass its `WinSta0\NAME` value in the environment. A hidden parent window alone does not establish the detached worker's desktop. The worker records its own Windows API desktop name and PID in `status/startup-worker-desktop.json`; verify that receipt before claiming hidden-desktop execution. Never switch the user's visible desktop.

GitHub synchronization and STR video preparation always use `windows_desktop.run_hidden_desktop` on Windows, including direct `startup_github.py` and `X convert_video` invocations. Every `gh api` request and every FFmpeg version, encode, video-decode and audio-decode command runs beneath a worker on a fresh `WinSta0\XportTools_UUID` desktop. The launcher assigns native `STARTUPINFO.lpDesktop`, applies `CREATE_NO_WINDOW`, retains the desktop handle until the worker completes, and verifies the worker's actual desktop through the Windows API. Descendant console windows remain on that hidden desktop; never call `SwitchDesktop` or fall back to `Default` after a desktop creation/launch/receipt failure.

The hidden-command bridge captures both output streams and preserves stdin, working directory, environment, exit status, checked failures and command timeouts. Temporary request/result files are removed after completion; never print their contents or GitHub request bodies/credentials in failure diagnostics. Existing GitHub diagnostics and project-local video logs remain authoritative. A command timeout is propagated after the child is stopped by `subprocess.run`; no replacement conversion or GitHub synchronization is launched automatically. On non-Windows hosts the helper delegates to ordinary captured `subprocess.run`. The native Windows test must verify both the worker and a descendant created with `CREATE_NEW_CONSOLE` report the same non-Default desktop. Validate changes from `[XPORT_ROOT]` in PowerShell:

```powershell
$env:PYTHONPATH = '[XPORT_ROOT]/tools'
python -B -m unittest tools.tests.test_hidden_commands tools.tests.test_startup_github tools.tests.test_convert_video tools.tests.test_startup
```

```powershell
python -B [XPORT_ROOT]/tools/startup.py status --project PROJECT_ROOT --after-revision REVISION
python -B [XPORT_ROOT]/tools/startup.py submit --project PROJECT_ROOT
python -B [XPORT_ROOT]/tools/startup.py retry --project PROJECT_ROOT --expected-revision REVISION
```

`status/startup.json` is the durable monotonic state, `status/startup.log` holds full command output, and `status/startup-response.json` is the sole reusable response file. An unchanged `status --after-revision` returns `changed: false`; do not call a model again. A response is accepted only when both `revision` and `attention_sha256` match the current attention packet. When a frontier review establishes semantically incomplete pseudocode, record the hash-bound `analysis.pseudocode_reviews` file, then run `python -B [XPORT_ROOT]/tools/startup.py refresh-frontier --project PROJECT_ROOT --expected-revision REVISION`. This requires the exact paused frontier revision, regenerates complete evidence through the supervisor and replaces the response template; running or unrelated attention states are rejected.

The `verify_frontier` gate synchronizes source mappings into SQL and reads the complete-body queue. Completion counters and convergence scope must describe this refreshed state. Repair an already completed stale handoff with `python -B [XPORT_ROOT]/tools/startup.py refresh-completion --project PROJECT_ROOT --expected-revision REVISION`. It requires the exact completed revision, resumes at source verification, refreshes the SQL queue and revalidates the recording/convergence and isolated deployment gates. It preserves accepted exports and original inputs; it does not initialize another project or expand translation scope.

Response shape:

```json
{
  "revision": 4,
  "attention_sha256": "hash from startup.json",
  "decision": {}
}
```

A faulty accepted export discovered at the exact paused `psyq_review` or `frontier_translation` revision with an empty translation ledger can be superseded through the same supervisor with `python -B [XPORT_ROOT]/tools/startup.py reexport --project PROJECT_ROOT --expected-revision REVISION --label NEW_LABEL --exports orig/NEW_ROOT`. Both label and destination must be unused; the destination must stay under project `orig`. The command preserves previous accepted inputs, exports, runs and receipts, archives the prior config/state and resumes export, independent canonicalization, acceptance and PsyQ recognition under fresh labels. It rejects running, stale and post-translation states. Optional image-profile `function_boundaries` rows contain aligned `start`, exclusive `end`, exact original-byte `sha256` and an evidence-based `reason`. The exporter validates all ranges, hashes and non-overlap before changing IDA owners, preserves adjacent data and requires the exact new boundaries before export; accepted old evidence remains immutable. It never overwrites old evidence or initializes another project.

A named-file raw-copy overlay can use `gp_evidence.source = inherited_named_loader` through `overlay_gp_named.validate`. Bind an accepted parent profile and original input, its immutable acceptance receipt, the exact overlay bytes, and a project-owned loader review by SHA-256. The gate accepts only its reviewed complete sized-copy MIPS form: literal filename argument, size/temporary-buffer/read/copy/release ABI, pointer-loaded destination and later direct overlay entry call. Review all callee byte identities, caller route bytes, filename-to-extracted-asset mapping and code/seed partition. Scan every raw parent text word for GP writers, including discovery gaps; only the validated parent entry initializer may write GP. Reject any GP writer in the entire raw overlay, stale artifacts, a different literal/asset/destination/call, unbound functions or an incomplete semantic contract. This is static original-image evidence, with no runtime observation or native acceptance implied.

## Supervisor-owned gates

The supervisor performs and records these gates in order:

1. Refuse an initialized or conflicting root; create the C/VS2022 scaffold and unique runtime ports. The following `git_index` step creates a project-local Git repository only when absent and stages the generated `.gitignore` before GitHub synchronization
   The generated C entry implements `void xport_main(void)` and defines the required `xport_gpu_graph_type_address` binding as unresolved (`0u`). Replace that binding only with original-image evidence before calling GPU wrappers; the scaffold value is not a reviewed guest address.
2. Synchronize the standard GitHub labels/issues and run project diagnosis without compiling
   The generated Windows project compiles shared `xport_trace.c` alongside the PSX runtime. It also compiles shared `psx_xa.c` for XA decoding. The scaffold defines all four `xport_cd_*_address` bindings as unresolved (`0u`); replace them only with audited original-image evidence before using guest CD storage.
3. Extract every disc data track from `iso` into `bin/DATA` through `extract_data`, then inventory immutable inputs and hashes; propose PS-X EXE profiles and reuse a persisted licensed tool path only when the path and executable identity validate
4. Preflight IDA processor/decompiler initialization, Ghidra help output, PsyQ data and native build platform before expensive analysis; accept a legacy Ghidra launcher's nonzero `-help` exit only when the canonical headless usage marker is present. Select the highest discovered Ghidra semantic version that has a matching installed PSX extension profile; a `psyq` retry repairs a mismatched automatically discovered pair
5. Extract and verify the game's Memory Card save icon, convert it to `src/platform/win/icon.ico`, verify the local `MAINICON` resource binding and retain the provenance required below. Only after this gate passes, run the scaffold Debug native build. This gate also precedes every Release test build; it does not authorize intermediate Release builds
6. Convert Red Book audio when configured, then run the `video` gate to prepare standard STR movies as H.264 MP4 assets
7. Plan, export, independently canonicalize and fail-closed accept IDA/MIPS evidence
8. Run standalone xport PsyQ recognition from the preserved SDK catalog; pause with aggregate and per-item review details. Before submitting `psyq_review`, also complete and verify the mandatory supplemental Ghidra listing/pseudocode export below; PsyQ recognition alone does not satisfy that requirement
9. Build the SQLite analysis index and independently validate similarity evidence
10. Issue one MIPS/IDA translation packet containing only the configured executable entrypoint or entrypoints; pause for reviewed C changes, then rebuild the source index and synchronize ledger statuses into SQLite
   Do not follow calls, expand dependencies or translate an SCC during startup. Always refresh the source index before trace-contract setup, including when an entrypoint already has a reviewed classification. Leave every other game function for `function_coverage NAME` followed by `coverage NAME`.
   Startup does not require a native link after entrypoint translation because its direct callees may intentionally remain unimplemented. Coverage owns the later Debug and Release build gates.
11. As the concluding gate, create root `DuckStation.bat`, deploy and validate isolated data/settings for every reserved `audit`, `trace`, and `user` role, reuse only receipt-identical partial deployments, and publish their receipts with timing metrics in the compact handoff

The model owns the evidence-based icon preparation described below and the ambiguous attention kinds `image_review`, `tool_paths`, `psyq_review`, and `frontier_translation`. The supervisor must hold the pre-build dependency until icon preparation is verified; do not assume an undocumented icon attention command exists. The model must preserve image-qualified identities, audit the complete MIPS, use pseudocode only when its completeness metadata permits it, keep unsupported facts explicit, and never treat compilation, SDK classification or wrapper presence as runtime equivalence.

The remaining sections define startup evidence and project layout. Read `DECOMPILATION.md` only for a translation attention or decompilation failure. Runtime `record`, `stop`, and `converge` are separate workflows.

## Source region and video timing

- Prefer NTSC-U or NTSC-J originals for analysis when multiple regional versions are available; honor an explicitly selected region. Record the canonical image identity and reviewed video standard in the consuming project
- New projects default to `FIELD_RATE=60` and `lockstep.timing = {"video_standard": "NTSC", "field_rate": 60}`. The scaffold default is not evidence of the original video mode. Before the first recording or native runtime validation, verify the selected original and keep both native Debug/Release definitions and recording timing consistent
- For an explicitly selected PAL original, set `FIELD_RATE=50` in both native configurations and set `lockstep.timing` to `{"video_standard": "PAL", "field_rate": 50}`. Preserve existing recording identities; never relabel old captures when correcting a project configuration

## Disc extraction

- Place all disc images and their CUE files under project `iso` before startup. CUE filenames must reference existing track files exactly; do not guess replacements. Extraction supports ISO9660 `.iso` and standalone `.bin`/`.img`, plus CUE data tracks in MODE1/2048, MODE1/2352, MODE2/2352 and MODE2/2336. Referenced audio BIN files are excluded from data-image discovery; Red Book conversion remains a separate gate
- Extract every directory and file, remove ISO version suffixes (`;1`), preserve names and file bytes, and read ordinary files as 2048-byte logical sectors. Search file sectors in order before choosing the output format. Stop at the first Mode 2 sector that has Form 2 (`0x20`) or Realtime (`0x40`) set in its submode and retain the entire file as complete physical sectors (2352 or 2336 bytes according to the input), including all Form 1 sectors and subheaders. Only when every sector has been checked without a raw trigger, extract 2048-byte logical payloads and trim the final payload to the ISO file size. EOF/EOR differences alone do not select raw storage; the first matching sector is sufficient for raw, but a normal first sector is insufficient for logical storage. Never classify raw overlays during startup; their discovery, load addresses and analysis belong to decompilation
- Multiple discs use separate `bin/DATA/1`, `bin/DATA/2`, etc. to preserve conflicting paths; there is no fixed disc-count limit. Review boot executable, image-qualified profiles, runtime data roots and music selection explicitly for a multi-disc project; duplicate executable basenames do not produce an automatic proposal
- Extracted DATA is the runtime source: consuming games must read it through `xport_fopen` and shared file APIs, never from ISO/BIN/CUE images during gameplay. Follow [DECOMPILATION.md#runtime-file-access](DECOMPILATION.md#runtime-file-access) when replacing original CD file wrappers
- Save paths, source extents, output sizes and SHA-256 hashes in `status/startup-extraction.json`. No executable or overlay copy is written to `orig`; existing analysis/export paths remain there
- ISO directory records with a valid 14-byte XA system-use record and big-endian CDDA attribute `0x4000` may reference following CUE audio tracks outside the data track. Resolve their LBAs from ordered 2352-byte source files and CUE indexes; require one bounded AUDIO source, sector-aligned ISO size and a range inside the declared ISO volume. Preserve each audio sector as 2352 raw bytes under the original DATA filename and record `storage: raw_cdda`, track, source path and byte offset in the extraction receipt. Do not infer audio from filenames or relax bounds for ordinary files. Explicit PREGAP/POSTGAP timelines remain unsupported for this route and fail closed. Red Book WAV conversion remains a separate step
- Retry reuses byte-identical extracted files and refuses to overwrite different existing files. Originals remain untouched. Unsafe paths, missing CUE tracks, invalid/truncated volumes and unsupported ISO extensions fail `extract_data`; correct the reported source or format before retrying. With no disc images, retain the existing `image_review` attention for missing original inputs

## STR video preparation

- After music conversion, the supervisor runs `convert_video.convert` in its durable `video` step. Explicit preparation for an initialized project: `X convert_video [--ffmpeg ABSOLUTE_EXECUTABLE]`. This prepares assets only; it does not itself enable WebCodecs playback, alter MDEC or remove original DATA files. A consuming project explicitly sets `video.web_enabled: true` to publish registered prepared movies through the web packager
- Scan `bin/DATA` recursively for `.STR`, case-insensitively. When `video.sources` is present, process only that explicit list of project-relative STR paths; reject missing, unsafe or duplicate entries. Without it, inspect all STR files. Accept standard STR magic `0x80010160` in complete 2352-byte Mode 2 sectors, with or without a 44-byte RIFF/CDXA wrapper, one video channel, constant even dimensions, contiguous frame numbers and at most one constant-format XA audio channel. Verify complete ordered frame chunks and duplicate XA subheaders. Report unsupported layouts/variants in `status/startup-video.json`; preserve them for decompilation. Do not automatically search packed containers such as `ACE.SPB` or classify isolated MDEC texture blocks as movies
- Standard STR does not declare a reliable frame rate. Review playback timing during `image_review` and set `video.frame_rate` in `xport-project.json`, e.g. `15`, `30` or `"30000/1001"`. Override individual inputs with `video.frame_rates`, keyed by exact project-relative path, e.g. `"bin/DATA/1/INTRO.STR": 30`. Missing/invalid timing for a recognized movie fails `video`; correct config and retry the failed revision. Never silently accept FFmpeg's psxstr 15 FPS default
- Resolve FFmpeg from the explicit CLI argument, `video.ffmpeg`, `XPORT_FFMPEG`, then PATH. Require the psxstr demuxer, MDEC decoder, libx264 encoder and AAC encoder for audio-bearing inputs. Record executable identity/version. Missing tools or conversion/validation failure fails the gate; inspect `status/video/*.log`
- Write content-addressed MP4 files and `manifest.json` in `bin/VIDEO`. Use H.264, yuv420p, CRF 18 by default, slow preset, no B-frames, original dimensions, reviewed FPS, optional AAC audio at 128 kbit/s and faststart. Override CRF for individual inputs with `video.crfs`, keyed by exact project-relative source path and restricted to integers 0..51; record the effective CRF in the encoding/cache identity. Use this setting when a prepared movie exceeds the hosting size limit. Do not upscale, interpolate or drop/duplicate video frames. Decode the completed MP4 and require its video frame count to equal the independently scanned complete STR frame count before publication
- The manifest binds source/output SHA-256, encoder/settings, original frame numbers, sector positions/counts, channel, dimensions and XA audio metadata. The converter records `runtime_binding: pending_webcodecs_integration` because preparation alone is not runtime acceptance. Explicit `video.web_enabled` activation is owned by the consuming integration; this receipt is not proof of audio synchronization, exact MDEC pixels or runtime compatibility. Runtime integration must account for the recorded audio/video start sectors and game timing explicitly
- Publish only verified complete outputs. Retry reuses only manifest-identical inputs/settings/encoder and matching output hashes; refuse modified or unverified existing outputs. Do not delete previous assets or originals. No recognized STR requires no FFmpeg. Web integration must prepare and register supported standalone movies for MP4/WebCodecs as required by [FMV.md#web-movie-policy](FMV.md#web-movie-policy); substitution applies only to registered sources; ordinary MDEC texture/block decoding remains active on every platform

- Update this document with each shared behavior/format/command change. Agents of every project may improve it. Preserve validated constraints and provenance; replace obsolete instructions instead of appending contradictory history. Keep project-only findings in that project's `AGENTS.md` and evidence files.
- No fixed final methodology: promote a verified reusable finding into this document/toolset. State applicability, test evidence and limitations. Do not promote a game's workaround into a platform rule.

Preserve pre-existing user sessions and active recordings. Leave a test instance running only when explicitly requested by the user; report that handoff. - Full debugger output and traces go to files. Agent output: short result, first difference, evidence path. Buffer trace writes; do not rewrite a growing JSON per frame or load whole RAM dumps into context.

### Indexed TIM converter contract

`python -B [XPORT_ROOT]/tools/tim_to_ico.py INPUT.tim OUTPUT.ico [--offset 0xOFFSET] [--palette INDEX] [--report REPORT.json]` converts an indexed 4-bit or 8-bit TIM into one unscaled 8-bit Windows DIB icon with 256 palette entries and an AND transparency mask. Existing outputs require `--force`; input and output paths must differ.

## 3. Data and evidence contracts

Current implementation: `analysis.sqlite` is rebuildable static analysis/duplicate index. Statuses import from `status/translation-ledger.json`; run evidence/queue is separate `status/controls/automation/runs.sqlite`; legacy coverage may be `status/controls/coverage.json`. Preserve each existing source until an explicit lossless migration. Never store the only manual conclusion in a disposable database. One editable source of truth per datum; derive JSON/HTML when SQL becomes authoritative.

Required model (do not claim every future table already exists):

- Image: revision/hash, source path, load segments/file offsets, entry/GP. Function: image/address, name, chunks/boundaries/confidence, size/code hash, MIPS/pseudocode paths. Instruction: address/bytes/word, disassembly, owner and delay-slot flag.
- Symbols, data references, strings and structures carry origin/confidence. Retain unclassified ranges, failed decompilation, uncertain boundaries and unresolved indirect transfers.
- Control edge: source image/function/site, target image/address, direct/conditional/tail/indirect kind, resolution evidence and ambiguity. Pointer-looking data remains a candidate until usage is proven. Same overlay address does not resolve identity.
- Duplicate pair: exact bytes vs documented MIPS normalization vs similarity, input hashes/algorithm version, differing instructions/constants/addresses, flow shape and reuse risks. Normalized equality never transfers implementation or runtime proof.
- Implementation: full source binding in project.sqlite, separate from static/runtime evidence. Link original hash, C location and implementation revision. Historical export/proof statuses are not maintained by agents
- Derived C source index: `source_files`, `implementations`, `implementation_identifiers`, `source_declarations` and `implementation_declarations` map `(image,address)` to an exact C range only through an image-qualified `FUNCTION_MARKER`, an exact address-bearing symbol, or one unique address-bearing symbol in the ledger-declared source. Partial or combined regions remain `ambiguous` or `unmapped`; never select a nearby function by line proximity. Store source, body, declaration hashes and parser version. The translation ledger remains the editable mapping authority; these tables are reproducible views
- Evidence: type/scope/result, artifact path/hash, input image/source/build identities. Mark dependent evidence stale on changed inputs; retain history.
- Run: native/emulator hashes, effective configuration, paired checkpoints/provenance, character/level/context, absolute input schedule and actual decoded input, range/counts, raster/audio/shared-RAM settings. Link all channels by run/ordinal/tick.
- WIP events: unique branch identity, every occurrence, first/last event, continued/fatal status, prior skips and scenarios. Absence in one trace is not proof of unreachability.
- Large binary traces stay files; SQLite stores metadata, hashes, relationships and searchable indices.

Importer requirements: transactions, versioned schema/migrations, foreign keys/indices, reproducible import, `PRAGMA integrity_check` and `foreign_key_check`, artifact existence/hash checks. Reimport may replace derived analysis, not manual status/evidence. Export schema/importer/query CLI, provenance and unknowns when transferring a database.
